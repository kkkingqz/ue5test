# События

> **Задача:** понять, что такое событие в GV2, и научиться реагировать на то, что произошло в игре.
> **Нужно:** прочитанный [Objects](Objects.md).
> **Проверка:** `gv2-headless --check-scripts` не выводит ошибок.

**Сразу важное:** события — не файлы контента. Их нельзя описать в `definitions/`, как предмет или персонажа. Событие живёт в коде на Lua. Эта страница объясняет, как устроены события, чтобы вы могли либо написать простую реакцию сами, либо внятно поставить задачу программисту.

## Что такое событие

Событие — это **сообщение о том, что уже произошло**. Не просьба, не предложение, не вопрос: факт.

«Игрок покинул рынок» — событие. «Игрок хочет уйти с рынка» — не событие, это команда.

Из «уже произошло» следуют два свойства, на которых держится вся модель:

- **Событие нельзя отменить.** Подписчик не может сказать «нет, не уходи» — уход уже случился.
- **Событие приходит после изменения состояния**, а не до. Когда вы получили «игрок вошёл в таверну», игрок уже в таверне.

Если нужно что-то запретить или проверить *до* действия — это не событие, а валидатор. Другой механизм, к программисту.

## Цепочка

```text
игрок нажал кнопку
      ↓
КОМАНДА          «уйти с рынка в таверну»
      ↓
проверки         можно ли вообще
      ↓
изменение        текущая локация становится таверной
      ↓
СОБЫТИЯ          «покинул рынок», «вошёл в таверну»
      ↓
подписчики       кто-то реагирует
```

Событие всегда рождается внутри команды и публикуется только если команда успешно завершилась. Если команда отклонена, никаких событий не будет — игрок не увидит реакции на то, чего не произошло.

## Какие события уже есть

| Событие | Когда происходит | Что сообщает |
|---|---|---|
| `core:event.location.leave` | Игрок уходит из локации | Откуда и куда |
| `core:event.location.enter` | Игрок приходит в локацию | Откуда и куда |

Список короткий: события добавляются вместе с механиками. Нужное вам почти наверняка ещё предстоит завести.

## Как выглядит публикация

Внутри обработчика команды — вот настоящий код из движка, из перехода между локациями:

```lua
game.events.enqueue({
    event_id = "core:event.location.enter",
    payload = {
        from_location_id = from_location_id,
        to_location_id = target_location_id,
    },
})
```

`event_id` — имя события, `payload` — что именно случилось. Слово `enqueue` («поставить в очередь») выбрано не случайно: событие не доставляется мгновенно, оно ждёт успешного завершения команды.

## Как выглядит подписка

```lua
game.events.subscribers.register(
    "rh:subscriber.tavern.greeting",     -- имя подписки, любое ваше
    "core:event.location.enter",         -- на что подписываемся
    function(env)                        -- что делать
        if env.payload.to_location_id == "rh:location.city.tavern" then
            -- реакция
        end
    end
)
```

Три вещи: как называется подписка, на какое событие, и что делать. В `env.payload` лежит то, что положил публикующий.

**Одно правило, которое ломает интуицию:** подписчик не может менять состояние игры напрямую. Присвоение в `game.state` из обработчика события будет отклонено.

Если по событию нужно что-то изменить, подписчик ставит команду:

```lua
game.commands.enqueue({
    command_id = "rh:command.quest.start",
    args = { quest_id = "rh:quest.tavern.rumors" },
})
```

Причина: так любое изменение состояния проходит один и тот же путь с проверками, и порядок событий остаётся воспроизводимым. Иначе два подписчика, меняющие состояние одновременно, дали бы результат, зависящий от порядка регистрации.

## Куда это кладётся

Код игры живёт в `GameData/rh/scripts/`. Сейчас этой папки нет — она появится, когда в игру поедет первая механика. Каждый файл должен быть перечислен в `GameData/rh/scripts/manifest.lua`:

```lua
return {
    modules = {
        {
            module_id = "rh:module.gameplay.tavern",
            source = "gameplay/tavern.lua",
            dependencies = {},
            replaceable = false,
        },
    },
}
```

Файл, не указанный в манифесте, не загрузится — это защита от случайно попавшего в папку черновика.

Проверка:

```bash
gv2-headless --check-scripts
```

Она загружает и компилирует все модули, не запуская игру. Занимает доли секунды.

## Что вы можете сами, а что нет

**Сами:** написать подписку на существующее событие по образцу выше и поставить из неё команду.

**Через программиста:**

- новое событие — его должна кто-то публиковать, а публикация живёт внутри команды;
- новая команда;
- проверка «можно ли» до действия — это валидатор;
- всё, что требует изменить состояние прямо в подписчике: нужно понять, какая команда за это отвечает.

Ставя задачу, формулируйте её через цепочку выше: «когда игрок входит в таверну, должно начинаться такое-то». Из этого сразу видно, что нужно событие входа (оно есть), подписка и команда старта — и разговор получается коротким.
