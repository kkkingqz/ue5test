# Объекты контента

> **Задача:** разобраться, из каких объектов состоит контент, какие у них поля и как они связаны.
> **Нужно:** прочитанный [Setup](Setup.md).
> **Проверка:** `gv2-content describe GameData/rh <тип>` показывает актуальный список полей.

## Общее устройство

Файл с объектами всегда выглядит одинаково:

```json5
{
  schema_version: 1,
  type: "item",              // какого вида объекты в этом файле
  definitions: [
    { id: "...", data: { ... } },
    { id: "...", data: { ... } },
  ],
}
```

Каждый объект — это `id` и `data`. Всё содержательное лежит в `data`; `id` — имя, по которому на объект ссылаются остальные.

Кроме `id` и `data` у записи бывают три необязательных поля:

```json5
{
  id: "rh:item.weapon.iron_sword",
  data: { ... },
  tags: ["weapon", "melee"],   // произвольные метки для поиска и фильтрации
  deprecated: false,           // помечен ли объект устаревшим
  extensions: {},              // служебное, обычно пустое
}
```

Их можно не писать вовсе — посмотрите `locations.json5`, там их нет.

## Идентификаторы

Идентификатор устроен так:

```text
rh:item.weapon.iron_sword
│  │    └──────────────── ваше имя, любой глубины через точки
│  └───────────────────── вид объекта
└──────────────────────── пакет: rh — ваша игра, core — движок
```

Правила простые:

- только строчные латинские буквы, цифры и `_`; никаких пробелов, заглавных и кириллицы;
- ваши объекты всегда начинаются с `rh:`;
- ссылаться на объекты `core:` можно, создавать новые `core:` — нельзя.

Имя — это адрес, а не название. Название персонажа живёт в тексте и переводится; идентификатор не переводится и в игре не показывается. Поэтому `rh:npc.merchant`, а не `rh:npc.torgovec`.

**Переименовывать — только командой `rename`.** Она найдёт и поправит все ссылки. Руками почти наверняка что-нибудь останется.

## Какие бывают объекты

### `item` — предмет

| Поле | Тип | Обязательно | Что это |
|---|---|---|---|
| `label_text_id` | ссылка на текст | да | Название предмета |
| `price` | целое ≥ 0 | да | Цена |
| `icon_resource_id` | ссылка на картинку | да | Иконка |

```json5
{
  id: "rh:item.weapon.iron_sword",
  data: {
    label_text_id: "rh:text.item.iron_sword.name",
    price: 10,
    icon_resource_id: "rh:resource.item.iron_sword.icon",
  },
  tags: ["weapon", "melee"],
}
```

Цена проверяется отдельно: отрицательная не пройдёт.

### `actor` — персонаж

| Поле | Тип | Обязательно | Что это |
|---|---|---|---|
| `discriminator` | `player` или `npc` | да | Игрок это или неигровой персонаж |
| `name_text_id` | ссылка на текст | нет | Имя |
| `base_hp` | целое ≥ 1 | нет | Базовое здоровье |

Подробно — в [Characters](Characters.md).

### `location` — локация

| Поле | Тип | Обязательно | Что это |
|---|---|---|---|
| `title_text_id` | ссылка на текст | да | Название локации |
| `screen_ids` | список ссылок на экраны | да, минимум один | Какие экраны доступны в локации |

```json5
{
  id: "rh:location.city.market",
  data: {
    title_text_id: "rh:text.location.market.title",
    screen_ids: [
      "core:screen.main",
      "core:screen.inventory",
    ],
  },
}
```

Экраны берутся из `core` — их создаёт программист. Вы выбираете, какие из существующих доступны в вашей локации. Повторять один экран дважды в списке нельзя.

### `text` — текст

| Поле | Тип | Обязательно | Что это |
|---|---|---|---|
| `source_message` | непустая строка | да | Исходный текст |

```json5
{
  id: "rh:text.item.iron_sword.name",
  data: { source_message: "Iron sword" },
}
```

Подробно, включая переводы, — в [Texts](Texts.md).

### `resource` — картинка

| Поле | Тип | Обязательно | Что это |
|---|---|---|---|
| `resource_class` | `texture_2d` | да | Вид ресурса; пока только картинки |
| `required` | да/нет | да | Обязателен ли файл |

```json5
{
  id: "rh:resource.item.iron_sword.icon",
  data: {
    resource_class: "texture_2d",
    required: true,
  },
}
```

Здесь описан только сам факт «такая картинка существует». Файл кладётся в `Resources/rh/`. Если `required: true`, отсутствие файла остановит то, что его запросило; если `false` — подставится заглушка.

### `screen` — экран

Живёт в `core`, создаётся программистом. Из локаций на экраны только ссылаются.

## Как объекты связаны

```text
location ──► screen        какие экраны доступны в локации
    │
    └──────► text          название локации

item ──────► text          название предмета
   └───────► resource      иконка ──► файл в Resources/rh/

actor ─────► text          имя персонажа
```

Стрелка — это ссылка по идентификатору. Правило одно и работает всегда: **объект, на который ссылаются, должен существовать.** Ссылка на несуществующий текст или картинку — ошибка проверки, а не пустое место в игре.

Отсюда практический порядок работы: сначала текст, потом объект, который на него ссылается. Иначе первая же проверка отругает — не страшно, но лишний круг.
