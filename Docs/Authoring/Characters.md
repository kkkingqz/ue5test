# Как описать персонажа

> **Задача:** добавить в игру нового персонажа целиком — от имени до проверки.
> **Нужно:** прочитанный [Setup](Setup.md) и запущенный `validate --watch`.
> **Проверка:** `gv2-content validate GameData/rh` выводит `ok`, `inspect` показывает нового персонажа.

Персонаж — объект вида `actor`. Игрок и неигровые персонажи описываются одинаково; отличает их одно поле.

## Поля

| Поле | Обязательно | Что это |
|---|---|---|
| `discriminator` | да | `player` — персонаж игрока, `npc` — все остальные |
| `name_text_id` | нет | Ссылка на текст с именем |
| `base_hp` | нет | Базовое здоровье, целое число не меньше 1 |

Полей пока немного. Это не заглушка «на потом»: поле добавляется в движок тогда, когда становится нужным механике. Если для вашего персонажа не хватает характеристики — это нормальный запрос к программисту, а не то, что нужно обходить.

## Полный пример

Добавим стражника. Работа делается в двух файлах.

**Шаг 1. Имя — в `GameData/rh/definitions/texts.json5`.**

Добавьте запись в список `definitions`:

```json5
{
  id: "rh:text.npc.guard.name",
  data: { source_message: "Guard" },
},
```

`source_message` пишется на английском — это исходный текст, с которого делаются переводы. Русский появится на следующем шаге.

**Шаг 2. Персонаж — в `GameData/rh/definitions/actors.json5`.**

```json5
{
  id: "rh:actor.npc.guard",
  data: {
    discriminator: "npc",
    name_text_id: "rh:text.npc.guard.name",
    base_hp: 80,
  },
  tags: ["npc", "guard"],
},
```

**Шаг 3. Перевод — в `GameData/rh/localization/ru.po`.**

```po
msgctxt "rh:text.npc.guard.name"
msgid "Guard"
msgstr "Стражник"
```

`msgctxt` — идентификатор текста, `msgid` — точная копия `source_message`, `msgstr` — перевод. Подробнее в [Texts](Texts.md).

**Шаг 4. Проверка.**

Если `validate --watch` запущен, вы уже видите результат. Иначе:

```bash
gv2-content validate GameData/rh
gv2-content inspect GameData/rh rh:actor.npc.guard
```

Всё. Стражник в игре.

## Игрок

Персонаж игрока отличается только полем:

```json5
{
  id: "rh:actor.character.hero",
  data: {
    discriminator: "player",
    name_text_id: "rh:text.character.hero.name",
    base_hp: 100,
  },
  tags: ["character", "player"],
},
```

Персонажей с `discriminator: "player"` может быть описано несколько — например, разные стартовые герои на выбор. Кто именно играет в текущем прохождении, решается уже в игре, а не здесь.

## Описание против состояния

Различение, которое экономит много недоумения.

То, что вы пишете в `actors.json5`, — **описание**: «в этом мире бывает такой стражник». Оно неизменяемо и одинаково во всех прохождениях.

Когда игра запускается, из описания создаются **экземпляры** — конкретные стражники на конкретных постах, каждый со своим здоровьем, инвентарём и состоянием. Их создаёт и меняет игровая логика, а не вы.

Отсюда: `base_hp: 80` — это «сколько здоровья у стражника при создании», а не «сколько у него сейчас». Текущее здоровье живёт в сохранении и в файлах контента не появляется никогда.

По той же причине в описании персонажа нет ни позиции, ни того, что он сейчас делает: это состояние, а не описание.

## Частые ошибки

**Забыли текст.** Ссылка `name_text_id` на несуществующий текст — ошибка проверки. Сначала текст, потом персонаж.

**Идентификатор с заглавными буквами или кириллицей.** Только строчная латиница, цифры и `_`. `rh:actor.npc.guard`, не `rh:actor.npc.Страж`.

**Пакет `core:` вместо `rh:`.** Создавать объекты с `core:` нельзя — проверка это отклонит. Ваши персонажи всегда `rh:`.

**`base_hp: 0`.** Минимум — 1. Если нужен персонаж, которого нельзя убить, это механика, а не нулевое здоровье.

**Переименование руками.** Используйте `gv2-content rename` — ссылки на персонажа могут быть в местах, о которых вы не знаете.
