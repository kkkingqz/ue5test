# M5 — Theme

> **Материализует:** разделы 7 и 8 [UI Composition and Scaling](../../Proposals/UiCompositionAndScalingProposal.md).
> **Задачи:** UIC-23…27.
> **Результат:** принадлежность ассета слою наблюдаема и проверяема; перевод не обрезает текст.

## Результат этапа

Тема и шаблоны экранов перестают быть единственной подсистемой вне трёхуровневого разделения. `core` сохраняет способность отрисовать аварийные экраны без игрового пакета.

Этап не зависит от M1…M3 и выполняется после M4, чтобы переезд ассетов не пересекался с правкой раскладки в тех же шаблонах.

## Задачи

- [ ] **UIC-23 — Каталоги слоёв**
  - Зависимости: UIC-01.
  - Сегодня всё лежит в `Content/UI/`, и принадлежность ассета слою не наблюдаема.
  - Done: `Content/UI/` содержит инфраструктуру `core` — Game Shell, leaf-адаптеры, `WBP_ScreenBase`, реестр; тема, стили и шаблоны экранов текстовой игры переехали в `Content/TextSystem/UI/`; каталог `Content/RH/UI/` заведён для ассетов конкретной игры; переезд выполнен через `unreal-mcp` с исправлением ссылок, compile и save; конвенция записана в contract.
  - Evidence: `Content/TextSystem/UI/`, `Docs/UI/README.md`, `Docs/Architecture/Modding.md`.

- [ ] **UIC-24 — Гейт реестра по каталогу слоя**
  - Зависимости: UIC-23.
  - Done: валидация Screen Registry требует, чтобы класс, привязанный к `screen_id` с namespace `X`, лежал в каталоге слоя `X` или ниже по объявленной цепочке зависимостей; нарушение — ошибка валидации реестра; отрицательный случай покрыт automation; гейт по смыслу совпадает с `validate_core_boundary.py` для идентификаторов и на него ссылается.
  - Evidence: `Source/GV2/Private/UI/GV2ScreenRegistry.cpp`, `GV2.Runtime.Presentation.ScreenRegistry*`.

- [ ] **UIC-25 — Минимальная тема ядра**
  - Зависимости: UIC-23.
  - Из владения `textsystem` следует, что конфигурация без него остаётся без темы, а `core:screen.error`, `core:screen.loading` и `core:screen.recovery` обязаны отрисоваться в том числе при отказе загрузки контента.
  - Done: `core` содержит минимальную тему, достаточную только для трёх аварийных экранов; тема `textsystem` её замещает; порядок разрешения темы зафиксирован в contract; конфигурация без `textsystem` отрисовывает все три экрана, что подтверждено automation.
  - Evidence: `Content/UI/Styles/`, `Source/GV2/Private/UI/GV2UiTheme.cpp`, `GV2.Runtime.Presentation.*`.

- [ ] **UIC-26 — Минимальный размер из содержимого**
  - Зависимости: UIC-23.
  - Done: токены темы задают отступы, типографику и минимальные размеры касания, но не ширину интерактивного элемента; минимальный размер выводится из содержимого; правила переноса строк заданы шаблоном; contract запрещает фиксированную ширину кнопки в теме.
  - Evidence: `Content/TextSystem/UI/`, `Docs/UI/ScreenTemplates.md`.

- [ ] **UIC-27 — Псевдолокаль и проверка усечения**
  - Зависимости: UIC-26, UIC-22.
  - Done: генерируемая псевдолокаль удлиняет каждое сообщение на фиксированную долю и строится из существующего каталога переводов без ручного сопровождения; automation обходит зарегистрированные экраны на этой локали и требует отсутствия усечённого текста; локаль не входит в поставку и не влияет на `repository_content_hash`; полный `ctest`, `gv2-headless --self-test`, `--check-scripts` и Unreal automation зелёные.
  - Evidence: `Tools/Content/`, `Source/GV2/Private/Tests/`, отчёт CTest.

## Проверка milestone

- [ ] Класс экрана из namespace пакета вне каталога своего слоя отклоняется.
- [ ] Конфигурация без `textsystem` отрисовывает три аварийных экрана.
- [ ] Тема не задаёт ширину интерактивного элемента.
- [ ] Псевдолокаль не даёт усечённого текста ни на одном зарегистрированном экране.
