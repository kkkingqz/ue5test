# M1 — Identity

> **Материализует:** раздел 4 [UI Composition and Scaling](../../Proposals/UiCompositionAndScalingProposal.md).
> **Задачи:** UIC-01…05.
> **Результат:** повторяемый элемент имеет проверяемую идентичность; реконсиляция получает основание переиспользовать виджет.

## Результат этапа

Документ без ключа или с дубликатом ключа отклоняется до apply. Ключи выводятся из сущностей и не требуют участия автора. Наблюдаемое поведение интерфейса не меняется — меняется то, что о нём можно утверждать.

Этап обязателен для M2: реконсиляция без правила ключей пересоздаёт все элементы, и дефект при этом не наблюдаем.

## Задачи

- [ ] **UIC-01 — Создать ADR по композиции UI**
  - Done: ADR фиксирует каноничность экрана и UI-local природу прокрутки, активной вкладки и наведения; правило идентичности повторяемого элемента с областью уникальности и запретом вывода из позиции и из текста; вкладку как вложенный Screen Instance с ограничением на один уровень; растягивание по режиму фонового ресурса; разрешение авторинга и формулу масштаба; принадлежность темы и шаблонов экранов слою `textsystem`. Отдельно записывает отвергнутое: расширение дайджеста, раскладки по контрольным точкам, переопределение темы из контентного пакета, вкладку как новый вид поля. Принят до первой отметки `[x]` ниже.
  - Evidence: `Docs/ADR/0033-*.md`, `Docs/ADR/README.md`.

- [ ] **UIC-02 — Правило ключей в contract**
  - Зависимости: UIC-01.
  - Сейчас в [UI Document](../../UI/UIDocumentAndReconciliation.md) одна строка: «Repeated field items обязаны иметь deterministic `key` из durable identity». Область уникальности, источник значения, последствия смены и проверка не заданы.
  - Done: раздел contract задаёт обязательность ключа, область уникальности «непосредственный контейнер», порядок источников значения, запрет вывода из `text_id` и из изменяемого состояния, таблицу решений реконсиляции контейнера и класс ошибки для дубликата; `node_key_path` описан как полный путь `layer → instance → field → key`; [Screen Templates](../../UI/ScreenTemplates.md) ссылается на правило, а не пересказывает его.
  - Evidence: `Docs/UI/UIDocumentAndReconciliation.md`, `Docs/UI/ScreenTemplates.md`.

- [ ] **UIC-03 — Гейт документа: ключ обязателен и уникален**
  - Зависимости: UIC-02.
  - Done: общий помощник валидации ключей вызывается на фазе `PrepareBindings` всеми адаптерами повторяемых полей; отсутствующий ключ, дубликат в одном контейнере и ключ вне грамматики отклоняют документ целиком до apply с типизированной диагностикой; отказ не оставляет частично применённого экрана; отрицательные случаи покрыты automation.
  - Evidence: `Source/GV2/Private/UI/`, `FGV2ScreenFieldAdapterRegistry`, `GV2.Runtime.Presentation.*`.

- [ ] **UIC-04 — Вывод ключей в авторском слое**
  - Зависимости: UIC-02.
  - Сегодня `mod.button` принимает необязательный `key_opt`, и его отсутствие ничем не компенсируется.
  - Done: построители повторяемых полей выводят ключ из Stable ID или instance ID сущности, а при её отсутствии — из `command_id` с каноникализованными аргументами; явный ключ имеет приоритет; попытка передать локализуемый текст в качестве ключа отклоняется; геймплей `rh` не содержит ни одного ключа, заданного вручную без причины; правило покрыто спеками.
  - Evidence: `Scripts/authoring/`, `GameData/rh/scripts/`, `Tests/Lua/`.

- [ ] **UIC-05 — Диагностика переиспользования**
  - Зависимости: UIC-03.
  - Done: dev-сборка ведёт на контейнер счётчик переиспользованных и пересозданных дочерних элементов и сообщает о контейнере, который за настраиваемое число ревизий не переиспользовал ни одного; диагностика не влияет на shipping-сборку и не участвует в дайджесте; порог и сообщение зафиксированы в contract.
  - Evidence: `Source/GV2/Private/UI/`, `Docs/UI/UIDocumentAndReconciliation.md`.
