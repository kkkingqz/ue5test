# План композиции UI

> **Материализует:** [UI Composition and Scaling](../../Proposals/UiCompositionAndScalingProposal.md).
> **Задачи:** UIC-01…27.
> **Результат:** слои, оверлеи и вкладки вместо одного активного экрана; перестраивается только изменившееся; раскладка масштабируется по одному правилу.

## Цель

Довести интерфейс от одного активного экрана до многослойного документа: маршрут, оверлеи, модалки и вкладки, переиспользование виджетов при реконсиляции, единое правило масштабирования и наблюдаемая принадлежность ассетов слою.

Порядок этапов задан зависимостями, а не удобством: вкладки невозможны без реконсиляции экземпляров, а реконсиляция без правила ключей пересоздаёт всё и выглядит при этом корректно.

## Состояние на входе

Проверено по коду и contracts.

| Что | Сейчас |
|---|---|
| Активный экран | Один; следующий accepted Screen request полностью строит замену |
| Слои, оверлеи, модалки | Описаны в [UI Document](../../UI/UIDocumentAndReconciliation.md), кода нет |
| Реконсиляция по `layer + instance_key` | Описана, не реализована |
| Ключи повторяемых элементов | Одна нормативная строка; фактически `key` использует только `button_list.v2` |
| Schemas Screen Field | Пять; набора вкладок среди них нет |
| Режимы изображения | Реализованы как правила отрисовки, не как правило раскладки |
| Масштабирование и целевое разрешение | Отсутствуют во всех документах `Docs/UI/` |
| Тема | `Content/UI/Styles/DA_UITheme_Default`; принадлежность слою не зафиксирована |
| Дайджест презентации | `FinalScreenId` и `FinalScreenFields` — один экран |

## Принятые решения

Зафиксированы в [предложении](../../Proposals/UiCompositionAndScalingProposal.md), выносятся в ADR первой задачей.

- **Каноничен экран.** Прокрутка, активная вкладка, раскрытый список и наведение — UI-local, в сейв не попадают.
- **Дайджест не расширяется.** Следствие предыдущего пункта.
- **Ключ повторяемого элемента обязателен**, уникален в пределах контейнера и выведен из смысла, а не из позиции.
- **Вкладка — вложенный Screen Instance**, а не новый вид поля; вложенность ограничена одним уровнем.
- **Растягивание задаётся режимом фонового ресурса**: `tile` свободно, `fixed_aspect` с сохранением пропорций, `nine_slice` с фиксированными углами.
- **Разрешение авторинга 1920×1080**; масштаб `min(H/1080, W/1440)`; контрольных точек нет.
- **Тема и шаблоны экранов принадлежат `textsystem`** и остаются ассетами UE; `core` сохраняет минимальную тему для аварийных экранов.

## Границы

Входят: правило идентичности, многослойная реконсиляция, вкладки, масштабирование, принадлежность ассетов слою, проверка длины текста.

Не входят:

- **Фокус, навигация геймпадом и Back.** Отдельное [предложение по CommonUI](../../Proposals/CommonUIRuntimeIntegrationProposal.md); здесь закладываются только точки, которые дороже добавить позже.
- Расширение дайджеста презентации.
- Раскладки по контрольным точкам, портретная ориентация, значения безопасной области.
- Переопределение темы из контентного пакета.
- Вложенность наборов вкладок глубже одного уровня.

## Критический путь

```text
M1 ──► M2 ──► M3

M4 ──► M5
```

**M1 обязателен для M2.** Реконсиляция без правила ключей пересоздаёт все элементы, и дефект при этом не наблюдаем: интерфейс выглядит корректно.

**M2 обязателен для M3.** Вкладка — вложенный экземпляр; механизма экземпляров до M2 не существует.

M4 и M5 не зависят от M1…M3, но идут в указанном порядке между собой: переезд ассетов не должен пересекаться с правкой раскладки в тех же шаблонах.

## Общие правила выполнения

1. Ассеты редактора (`.uasset`) создаются и меняются только через `unreal-mcp`, с последующим compile, save и проверкой контракта automation-тестом ([AGENTS.md § Unreal Editor API](../../../AGENTS.md)).
2. Ни одна задача не переносит gameplay-авторитет в UE: UI остаётся восстановимой проекцией ([INV-014](../../Architecture/Invariants.md)).
3. Ни одна задача не добавляет partial patch на boundary: Lua отправляет полный документ, diff остаётся внутренним делом Presentation.
4. Правила, выразимые в Lua, проверяются спеками ([ADR-0024](../../ADR/0024-lua-spec-runner.md)).
5. Замороженный корпус `Tests/Fixtures/PortableContentCore/` не перестраивается.
6. `final_screen_id` и `final_screen_fields` в golden меняются только там, где задача сознательно меняет содержимое экрана `rh`; изменение `repository_content_hash` вне таких задач — признак ошибки.
7. Новое observable behavior синхронно отражается в contract того же change set.

## Итоговый Definition of Done

- [ ] Документ без `key` у повторяемого элемента и документ с дубликатом ключа отклоняются до apply.
- [ ] Изменение порядка элементов при неизменном наборе ключей не пересоздаёт ни одного виджета.
- [ ] Одновременно существуют маршрут, оверлей и модалка; модалка блокирует нижние слои, удаление владельца каскадно удаляет его модалки.
- [ ] Ревизия, меняющая одно поле одного экрана, не пересоздаёт остальные экземпляры.
- [ ] Переключение вкладки не порождает команду, не меняет ревизию документа и не попадает в сейв.
- [ ] Handle неактивной вкладки отклоняется Semantic Input.
- [ ] Загрузка сейва возвращает маршрут; активная вкладка, прокрутка и стек оверлеев — начальные.
- [ ] На пяти проверяемых разрешениях раскладка отличается только масштабом и шириной фона.
- [ ] Блок с `fixed_aspect` в свободно растягивающемся слоте — ошибка валидации шаблона.
- [ ] Псевдолокаль не даёт усечённого текста ни на одном зарегистрированном экране.
- [ ] Класс экрана из namespace пакета вне каталога своего слоя — ошибка валидации реестра.
- [ ] Конфигурация без `textsystem` отрисовывает `core:screen.error`, `core:screen.loading` и `core:screen.recovery`.
