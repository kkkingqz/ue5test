# M0 — решения до кода

> **Материализует:** два решения, без которых задачи Д1 вводили бы новую категорию состояния и второй путь откатa в обход contracts; оба фиксируются ADR до первой строки реализации, в рамках [Engine Gap Closure](README.md).

## EGC-01 — Зафиксировать транзакционное окно мутации с единым журналом

- [ ] EGC-01 — Зафиксировать транзакционное окно мутации с единым журналом

**Зависимость:** нет. **Файлы:** создать `Docs/ADR/0050-transactional-mutation-window.md`; обновить `Docs/ADR/README.md`. Docs: `CanonicalStateAndSave.md`, `CommandsAndEvents.md`.

**Инвариант:** [INV-004](../../Architecture/Invariants.md) даёт симметрию «событие публикуется только после успешного commit», а симметричной гарантии для состояния нет: `command_dispatcher` при ошибке отбрасывает контекст событий и перебрасывает ошибку, оставляя уже сделанные записи в `game.state`. Нарушение здесь — не частный баг, а разрешение на недоверенное состояние после пойманной ошибки.

**Решение:** принять журнал записей внутри открытого окна мутации в форме [предложения](../../Proposals/MutationWindowTransactionalityProposal.md#4-предлагаемое-решение): однократная запись прежнего значения на пару «таблица, ключ», применение в обратном порядке на ветке ошибки, отсутствующий до команды ключ восстанавливается отсутствующим. Дополнительно к предложению ADR фиксирует, что журнал **один** и покрывает обе категории изменяемого в окне состояния — каноническое и transient mode state из EGC-02. Два журнала означали бы, что ошибка откатывает одну категорию и, возможно, не откатывает другую, и что порядок их применения начинает значить. `write_revision` не откатывается; цена названа в предложении.

**Не считается закрытием:** записать решение только в предложение, оставив его `draft`; принять журнал, умолчав о transient state, и получить второй журнал в EGC-06; отложить решение о `write_revision` до реализации.

**Шаги:**
1. Написать ADR-0050: контекст (асимметрия INV-004), решение, явное правило «один журнал на окно», отвергнутые альтернативы (журнал на категорию; откат `write_revision`; транзакционность вне окна).
2. Назвать в ADR границу: загрузка сейва, построение репозитория и публикация UI-документа в окно не входят.
3. Записать, что ослабление `AuthoringFailAfterMutation` становится возможным, но выполняется отдельным решением, а не этим.
4. Перевести `MutationWindowTransactionalityProposal` в состояние, отражающее принятое решение, и сослаться на ADR.

**Done:**
- ADR-0050 принят и содержит правило единого журнала с причиной, а не только факт транзакционности.
- Граница окна названа перечислением того, что в него не входит.
- Судьба `write_revision` зафиксирована решением, а не оставлена реализации.
- `AuthoringFailAfterMutation` упомянут как следствие с отдельным решением.

**Evidence:** ADR-0050, запись в индексе ADR, обновлённое состояние предложения, `validate_docs`.

## EGC-02 — Зафиксировать временные режимы и маршрутизацию презентации

- [ ] EGC-02 — Зафиксировать временные режимы и маршрутизацию презентации

**Зависимость:** EGC-01. **Файлы:** создать `Docs/ADR/0051-temporary-modes-and-presentation-routing.md`; обновить `Docs/ADR/README.md`, `Docs/Architecture/StableIDSpecification.md`. Docs: `UIDocumentAndReconciliation.md` (раздел UI-local state), `Overview.md` (категории состояния), `ADR/0039-presentation-source-singleton.md`.

**Инвариант:** [UI-local state](../../UI/UIDocumentAndReconciliation.md#ui-local-state) требует: значение, влияющее на gameplay, становится canonical state. Состояние незавершённого боя влияет на gameplay и намеренно не сохраняется, поэтому без решения это противоречие contract, а не частный случай категории «Lua runtime state».

**Решение:** принять transient mode state как категорию рядом с canonical state в форме [предложения](../../Proposals/TemporaryGameModesProposal.md#4-модель-состояния): одно `core`-хранилище, только portable values, запись только внутри command handler, журнал из EGC-01, вне state hash и save. Принять один активный режим без вложенности, контракт `start`/`view`/`finish`/`cancel`, новый Stable ID kind `mode`, typed refusals `mode.not_active` и `mode.already_active` во владении `core`. Пересмотреть [ADR-0039](../../ADR/0039-presentation-source-singleton.md) по названному в нём же условию: регистрация остаётся единственной, но зарегистрированный source становится маршрутизатором «активный режим → его `view`, иначе построитель по умолчанию». Merge документов из нескольких sources по-прежнему отвергается — маршрутизация не является композицией.

**Не считается закрытием:** объявить transient state частным случаем «Lua runtime state» и не менять правило UI-local; разрешить несколько регистраций source; ввести kind `mode` без записи в спецификацию Stable ID; оставить причину отказа `start()` при активном режиме на усмотрение реализации.

**Шаги:**
1. Написать ADR-0051: категория состояния, модель run, один активный режим, маршрутизация, kind `mode`, отвергнутые альтернативы (несколько sources; сохранение незавершённого режима; вложенные режимы; неявное завершение текущего режима при `start()`).
2. Уточнить правило UI-local state: значение, влияющее на gameplay, хранится в canonical state **или** в transient mode state активного режима.
3. Внести kind `mode` в спецификацию Stable ID вместе с правилами freeze, как у `service`.
4. Записать в ADR-0051 отношение к ADR-0039: что именно пересмотрено, а что сохранено.
5. Перевести `TemporaryGameModesProposal` в состояние, отражающее принятое решение; снять из него требование UE-local листания отчёта (§7.3 остаётся, SR-002 правится в EGC-21).

**Done:**
- ADR-0051 принят; категория transient mode state описана вместе с правилом, которое она уточняет.
- Правило UI-local state в contract больше не противоречит незавершённому режиму.
- Kind `mode` есть в спецификации Stable ID с правилами freeze.
- Отношение к ADR-0039 названо: что пересмотрено, что сохранено, почему маршрутизация не является композицией.
- Причина отказа `start()` при активном режиме зафиксирована решением.

**Evidence:** ADR-0051, правка `StableIDSpecification.md` и раздела UI-local state, запись в индексе ADR, обновлённое состояние предложения, `validate_docs`.
