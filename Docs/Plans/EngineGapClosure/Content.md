# Э4 — контент `rh`

> **Материализует:** последний этап [Engine Gap Closure](README.md): механики и шесть пунктов стартового пакета на authoring surface. Этап начинается после закрытия Э3.

**Гранулярность намеренно крупная.** Декомпозиция геймплея принадлежит [Docs/RH](../../RH/README.md), а не этому плану: задачи ниже соответствуют механикам и пунктам стартового пакета и уточняются, когда закрывается Э3. До этого момента они не являются источником задач для команды авторского слоя — ею является [архитектура геймплея](../../RH/GameplayArchitecture.md).

**Общий инвариант этапа.** Весь геймплей пишется в `GameData/rh/` на authoring surface; обход через `game.*` или сырое `game.state` запрещён. Механики не содержат идентификаторов конкретного контента. Если возможности не хватает, она не обходится, а записывается новым гэпом — и это возврат к этапу по движку, а не обходной путь внутри Э4.

**Общая стратегия проверки** — из [раздела 9 архитектуры](../../RH/GameplayArchitecture.md#9-проверка): число тестов растёт с числом механик, а не с объёмом контента. Обходы контента перечисляют весь контент по repository и реестру Services, а не по рукописному списку.

## EGC-27 — Механики: характеристики, словарь условий, конвейер действия, сознание

- [ ] EGC-27 — Механики: характеристики, словарь условий, конвейер действия, сознание

**Зависимость:** EGC-26. **Файлы:** `GameData/rh/scripts/authoring/mechanics/`, `GameData/rh/definitions/`, `GameData/rh/schemas/`; specs в `Tests/Lua/`. Docs: `RH/GameplayArchitecture.md`.

**Инвариант:** [разделы 5.1–5.4](../../RH/GameplayArchitecture.md#5-механики). Правило получает персонажа параметром; набор характеристик у игрока и NPC одинаковый; в canonical state хранится только то, что нельзя вычислить. Нарушение — правило, работающее только с игроком, или сохранённая итоговая характеристика.

**Решение:** базовые характеристики — поля Definition через механизм EGC-12; итоговые вычисляются при чтении. Тип условия — Service `rh:service.condition_<type>` с `check` и `reason`; условия записываются данными. Конвейер действия — Service с `check` и `perform`; игрок вызывает его одной командой, приказ спутнику — та же команда с другим исполнителем. `can_act()` — первый шаг конвейера.

**Не считается закрытием:** условия, записанные в Lua для каждого действия; причина недоступности, написанная отдельно для каждого действия вместо формирования типом условия; конвейер, принимающий только игрока.

**Шаги:**
1. Объявить базовые характеристики полями Definition; проверить, что итоговые не попадают в сейв.
2. Реализовать словарь условий; обход контента проверяет, что у каждого действия существуют типы условий и Command-эффект.
3. Реализовать конвейер; проверить приказ спутнику тем же вызовом с другим исполнителем.
4. Реализовать сознание; бессознательный персонаж не исполняет приказы и не участвует в фазах.
5. Specs механик с отрицательным случаем на каждую.

**Done:**
- Каждое правило вызывается с игроком и с NPC, результат различается только данными персонажа.
- Итоговые характеристики отсутствуют в сейве; проверено содержимым сохранения.
- Обход контента перечисляет все действия по repository и находит отсутствующий тип условия.
- У каждого `condition_*` есть `check` и `reason`; перечислитель — реестр Services.
- Бессознательный персонаж отвергается конвейером на первом шаге.

**Evidence:** specs механик, обходы контента, содержимое сейва.

## EGC-28 — Ход: фазы, время мира, отчёт

- [ ] EGC-28 — Ход: фазы, время мира, отчёт

**Зависимость:** EGC-27. **Файлы:** `GameData/rh/scripts/authoring/mechanics/`, `GameData/rh/definitions/` (kind `turn_phase`); specs. Docs: `RH/GameplayArchitecture.md`.

**Инвариант:** [раздел 5.6](../../RH/GameplayArchitecture.md#56-ход). Команда конца хода доступна всегда, в том числе без выносливости и без сознания; фазы исполняются по возрастанию `order`, при равенстве — по Stable ID; одна транзакция. Нарушение — фаза, добавляемая переопределением общего списка вместо новой Definition.

**Решение:** фазы — отдельные Definitions, перебираемые механизмом EGC-11. Фаза возвращает записи отчёта. Время мира сдвигается на длительность хода из данных, публикуется факт конца хода. При непустом списке записей запускается режим отчёта, чей `view` строит шаблон EGC-23.

**Не считается закрытием:** список фаз внутри одной Definition; продвижение процессов в конце хода; отчёт, показываемый модальным окном.

**Шаги:**
1. Объявить две фазы с разным `order` и одну с равным `order` другой.
2. Проверить порядок исполнения и детерминированность при равных `order`.
3. Проверить, что новая фаза фикстуры попадает в исполнение без правки кода.
4. Проверить конец хода без выносливости и без сознания.
5. Проверить, что пустые результаты всех фаз не открывают экран отчёта.

**Done:**
- Фазы исполняются по `order`, при равенстве — по Stable ID; порядок проверен двумя прогонами.
- Новая фаза добавляется Definition и попадает в исполнение без изменения кода.
- Конец хода доступен без выносливости и без сознания.
- Пустые результаты не открывают отчёт; непустые открывают режим отчёта.
- Конец хода — одна транзакция: ошибка в фазе не оставляет частично сдвинутого времени мира.

**Evidence:** specs хода, два прогона порядка, прогон с ошибкой в фазе.

## EGC-29 — Пункт 1: десять локаций со связями и меню из источников

- [ ] EGC-29 — Пункт 1: десять локаций со связями и меню из источников

**Зависимость:** EGC-28. **Файлы:** `GameData/rh/definitions/locations.json5`, `actions.json5`, `texts.json5`, `resources.json5`; источники меню в `GameData/rh/scripts/authoring/`; specs.

**Инвариант:** [раздел 7](../../RH/GameplayArchitecture.md#7-экран). Меню собирается из четырёх источников (игрок, спутники, локация и её объекты, переходы); недоступное действие показывается неактивным с причиной. Нарушение — статичный список действий в Definition экрана.

**Решение:** `rh` объявляет свои источники меню через механизм EGC-18 и значения панелей статуса через EGC-19. Стоимость перехода — поле Definition локации. Десять локаций со связями, картинками и вариантами описания.

**Не считается закрытием:** меню, собранное одним источником; переходы, перечисленные вручную в каждой локации; скрытие недоступных действий после того, как EGC-22 закрыт.

**Шаги:**
1. Завести десять локаций со связями; обход контента проверяет, что каждый переход ведёт в существующую локацию.
2. Объявить четыре источника меню; проверить состав меню на локации каждого типа.
3. Объявить значения панелей статуса.
4. Проверить стоимость перехода и отказ при нехватке выносливости.
5. Эталонный прогон: последовательность переходов даёт эталонный хеш состояния.

**Done:**
- Обход контента перечисляет все переходы по repository и находит ссылку в несуществующую локацию.
- Меню собирается из четырёх источников; состав проверен на локации каждого типа.
- Недоступное действие приходит неактивным с причиной.
- Панели статуса показывают значения `rh`, не значения по умолчанию движка.
- Эталонный прогон воспроизводим на обоих host-ах.

**Evidence:** обходы контента, specs меню, эталонный хеш.

## EGC-30 — Пункты 2 и 3: магазин и продажа

- [ ] EGC-30 — Пункты 2 и 3: магазин и продажа

**Зависимость:** EGC-29. **Файлы:** `GameData/rh/definitions/items.json5`, Definition магазина; режим торговли в `GameData/rh/scripts/authoring/`; specs.

**Инвариант:** [раздел 5.11](../../RH/GameplayArchitecture.md#511-временные-режимы). Торговля применяет итог одной командой в конце; промежуточное состояние не сохраняется. Нарушение — цена, продублированная в подписи и в Definition: сегодня `rh` уже содержит такое расхождение, и оно закрывается здесь.

**Решение:** режим торговли на механизме EGC-05: `start` из команды локации, команды покупки, `finish` с применением итога. Цена читается из Definition предмета в единственном месте. Продажа — поиск предметов игрока механизмом EGC-08, оценка формулой, удаление проданного экземпляра, вывод оценки режимом диалога.

**Не считается закрытием:** цена, записанная в подписи кнопки; покупка, меняющая canonical state до `finish`, если политика режима этого не предусматривает; продажа, читающая `game.state`.

**Шаги:**
1. Объявить ассортимент и цены данными; удалить дублирование цены в подписях.
2. Реализовать режим торговли; проверить `cancel` на равенство хеша состояния.
3. Реализовать продажу на операциях с экземплярами; проверить удаление проданного экземпляра и отсутствие висячих ссылок.
4. Проверить, что подписи покупки помещаются в размер кнопки (инвариант Э3).
5. Эталонный прогон покупки и продажи.

**Done:**
- Цена читается из Definition в единственном месте; дублирование снято.
- `cancel` торговли оставляет хеш состояния равным хешу до старта.
- Проданный экземпляр удалён; `state_validator` не находит висячих ссылок.
- Ни одна подпись не вызывает `label_overflow`.
- Эталонный прогон воспроизводим на обоих host-ах.

**Evidence:** specs торговли и продажи, значения хешей, прогон `state_validator`, эталонный хеш.

## EGC-31 — Пункт 4: диалог

- [ ] EGC-31 — Пункт 4: диалог

**Зависимость:** EGC-30. **Файлы:** граф диалога в `GameData/rh/definitions/`; режим диалога в `GameData/rh/scripts/authoring/`; specs.

**Инвариант:** [раздел 5.11](../../RH/GameplayArchitecture.md#511-временные-режимы). Диалог применяет последствия выбора сразу обычными командами; временной остаётся только позиция в дереве. Нарушение — последствия, применяемые в конце и теряемые при выходе.

**Решение:** граф диалога данными; ветвление по флагам через словарь флагов EGC-10 и словарь условий EGC-27. Имя NPC в реплике — текстовый аргумент EGC-14. Позиция в дереве — transient mode state.

**Не считается закрытием:** флаги, объявленные по одному полю на флаг; имя NPC, собранное конкатенацией; граф диалога в Lua.

**Шаги:**
1. Завести граф диалога данными; обход контента проверяет существование каждого целевого узла.
2. Реализовать режим; проверить ветвление по флагу.
3. Проверить, что последствие выбора применено сразу, а выход из диалога его не отменяет.
4. Проверить имя NPC в реплике через текстовый аргумент.
5. Эталонный прогон прохода по графу.

**Done:**
- Обход контента перечисляет узлы графа и находит ссылку на несуществующий узел.
- Ветвление по флагу работает; неизвестный флаг отвергается по repository, а не создаётся молча.
- Последствие выбора сохраняется после выхода из диалога.
- Имя NPC приходит текстовым аргументом; конкатенации в Lua нет.
- Эталонный прогон воспроизводим.

**Evidence:** обходы контента, specs диалога, эталонный хеш.

## EGC-32 — Пункт 5: событие перехода и реакции

- [ ] EGC-32 — Пункт 5: событие перехода и реакции

**Зависимость:** EGC-31. **Файлы:** Definitions реакций в `GameData/rh/definitions/`; подписчики и команды реакций в `GameData/rh/scripts/authoring/`; specs.

**Инвариант:** [Commands and Events](../../Architecture/CommandsAndEvents.md). Подписчик работает при закрытом окне мутации, а `game.random` пишет состояние потока в canonical state, поэтому подписчик ставит в очередь команду реакции, а условия, бросок и запуск режима выполняет она. Нарушение — бросок случайности в подписчике.

**Решение:** реакции — отдельные Definitions, перебираемые механизмом EGC-11: событие, условия, шанс, приоритет, запускаемое взаимодействие. Подписчик ставит отложенную команду; команда проверяет условия, бросает поток `rh:random_stream.*` и при успехе стартует режим.

**Не считается закрытием:** реакции, перечисленные в Lua вместо Definitions; бросок в подписчике; одновременный запуск двух режимов.

**Шаги:**
1. Завести две реакции Definitions с разным приоритетом.
2. Реализовать подписчика и команду реакции; проверить порядок проверки реакций.
3. Проверить, что бросок случайности происходит только в команде.
4. Проверить отказ второй реакции при уже активном режиме (`mode.already_active`).
5. Эталонный прогон с фиксированным зерном.

**Done:**
- Реакции перебираются по repository; новая реакция добавляется Definition.
- Бросок происходит только в команде; подписчик не меняет canonical state.
- Вторая реакция при активном режиме отвергается названным отказом.
- Эталонный прогон с фиксированным зерном воспроизводим на обоих host-ах.

**Evidence:** specs реакций, прогон с фиксированным зерном, эталонный хеш.

## EGC-33 — Пункт 6: танец

- [ ] EGC-33 — Пункт 6: танец

**Зависимость:** EGC-32. **Файлы:** Definition сцены и участников в `GameData/rh/definitions/`; режим танца в `GameData/rh/scripts/authoring/`; specs.

**Инвариант:** [раздел 5.7](../../RH/GameplayArchitecture.md#57-модели-npc) и [5.11](../../RH/GameplayArchitecture.md#511-временные-режимы). Временные характеристики сцены существуют только в режиме; итог записывается участникам одной командой при завершении. Нарушение — временная характеристика, попавшая в сейв.

**Решение:** режим танца на механизме EGC-05; временные показатели считаются из базовых характеристик участников через EGC-12; экран — шаблон EGC-26. Случайность внутри режима — по решению, принятому в ADR-0051.

**Не считается закрытием:** временные характеристики в canonical state; участники, найденные перебором всех NPC мира; итог, записываемый по шагам.

**Шаги:**
1. Завести сцену с двумя участниками, найденными запросом EGC-09, а не перебором мира.
2. Реализовать режим; временные показатели — в run.
3. Проверить, что сейв во время танца не содержит показателей сцены.
4. Проверить запись итога одной командой при завершении.
5. Эталонный прогон сцены с фиксированным зерном.

**Done:**
- Участники найдены запросом по локации или роли; перебора всех NPC нет.
- Показатели сцены отсутствуют в сейве; проверено содержимым сохранения.
- Итог записан одной командой; прерывание сцены итога не записывает.
- Эталонный прогон воспроизводим.

**Evidence:** specs танца, содержимое сейва, эталонный хеш.

## EGC-34 — Закрыть план

- [ ] EGC-34 — Закрыть план

**Зависимость:** EGC-33. **Файлы:** `Docs/RH/GameplayArchitecture.md`, `Docs/Status/EngineGaps.md`, `Docs/Status/ScreenRequests.md`, `Docs/Status/ImplementationStatus.md`, `Docs/Plans/README.md`, `Docs/Plans/Archive/`.

**Инвариант:** правила ведения планов: полностью выполненный план перестаёт быть источником задач; архивация выполняется двумя commit, пути проверяются через `git cat-file -e <source_commit>:<path>`.

**Решение:** статус [архитектуры геймплея](../../RH/GameplayArchitecture.md) переводится в `normative`, поскольку её условие перехода — реализованные и проверенные механики — выполнено. Все гэпы и заявки проходятся по списку целиком. План архивируется плоским файлом с итогом каждого этапа и каждым ID задачи ровно один раз.

**Не считается закрытием:** архивация при открытых гэпах без причины; перевод архитектуры геймплея в `normative` при механике без specs; архивация одним commit.

**Шаги:**
1. Пройти GAP-001…GAP-013 и SR-001…SR-005 по списку; каждый — закрыт со ссылкой либо открыт с причиной.
2. Перевести `GameplayArchitecture.md` в `normative`; проверить, что каждая механика раздела 5 имеет specs.
3. Обновить `ImplementationStatus.md` по подсистемам.
4. Полный прогон: приёмка UE, `ctest`, все гейты, `validate_docs`.
5. Зафиксировать полный план со всеми отметками одним commit; создать плоский архив и обновить индексы вторым.

**Done:**
- Все гэпы и заявки пройдены по списку; каждый имеет исход.
- `GameplayArchitecture.md` нормативен, и у каждой механики раздела 5 есть specs; перечислитель — разделы документа.
- Полный прогон зелёный на обоих host-ах.
- Архив создан двумя commit; каждый путь проверен через `git cat-file -e`.

**Evidence:** таблица исходов гэпов и заявок, перечень механик со specs, полный прогон, проверка путей архива.
