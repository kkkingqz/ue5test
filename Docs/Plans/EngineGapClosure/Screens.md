# Э3 — экраны

> **Материализует:** этап экранов [Engine Gap Closure](README.md): пять Screen Template по [заявкам](../../Status/ScreenRequests.md), собранные из элементов, существующих после Д2. Этап начинается только после закрытия Д2 и заканчивается до начала работы над контентом.

Каждая задача этапа — одна заявка. Общая форма: schema поля, Widget Blueprint, запись в Screen Registry, фикстурный документ, проходящий Prepare/Commit, и прогон матрицы разрешений. Ресурсы редактора правятся через `unreal-mcp`, не руками.

**Общий инвариант этапа.** [ADR-0049](../../ADR/0049-control-size-owned-by-surface.md): размер кнопки задаёт поверхность, подпись в него не входит, непомещающаяся подпись — ошибка `core:diagnostic.ui_button.label_overflow`. Экран, чьи подписи не помещаются в `ButtonSize` темы, не закрывает задачу: либо подпись короче, либо поверхность объявляет свой размер. Это касается в первую очередь магазина, где подписи вида «Buy leather armor (25 gold)» уже названы в ADR как заведомо непомещающиеся.

**Общее «не считается закрытием» этапа:** Widget Blueprint без записи в реестр; запись в реестр без фикстурного документа; экран, проверенный только на 1080p; новый элемент UI, добавленный на этом этапе вместо Д2.

## EGC-22 — Неактивный пункт меню с подсказкой о причине

- [ ] EGC-22 — Неактивный пункт меню с подсказкой о причине

**Зависимость:** EGC-21. **Файлы:** `GameData/textsystem/schemas/ui_field_location_commands_v2.schema.json5`; `WBP_ButtonList` и связанные ассеты через `unreal-mcp`; `Tests/Lua/presentation/dynamic_menu.lua`. Docs: `ScreenTemplates.md`, `WidgetRegistry.md`.

**Инвариант:** [SR-001](../../Status/ScreenRequests.md#sr-001-неактивный-пункт-меню-с-подсказкой-о-причине), [Semantic Input](../../UI/SemanticInput.md). Неактивный пункт не отправляет Semantic Input, но это только presentation: команда всё равно перепроверяет условия и отказывает typed refusal. Нарушение — доступность, считающаяся authority.

**Решение:** `location_commands.v2` добавляет к элементу `enabled` (по умолчанию `true`) и `disabled_reason`. Механически disabled уже достигается отсутствием binding: пункт без binding не получает handle и приходит неактивным — объявленное `enabled` делает это намерением, а не следствием. Причина показывается подсказкой из EGC-20 только у неактивного пункта. Смена `enabled` у пункта с тем же `key` обновляет существующий виджет, а не пересоздаёт его.

**Шаги:**
1. Завести `v2` схемы; `v1` остаётся до перевода потребителей.
2. Подключить подсказку EGC-20 к элементу; у активного пункта подсказки нет.
3. Проверить обновление на месте: ревизия меняет только `enabled`, виджет тот же.
4. Проверить, что неактивный пункт не создаёт binding record и его нажатие не доходит до Lua.
5. Прогнать матрицу разрешений для меню с неактивными пунктами.

**Done:**
- `enabled` и `disabled_reason` объявлены схемой; значение по умолчанию работает.
- Неактивный пункт не создаёт binding record; попытка взаимодействия не доходит до Lua.
- Подсказка показывается только у неактивного пункта.
- Смена `enabled` при том же `key` переиспользует виджет, проверено идентичностью объекта.
- Матрица разрешений пройдена; подписи помещаются в размер кнопки.

**Evidence:** specs меню, проверка идентичности виджета, прогон матрицы разрешений, отчёт `unreal-mcp` о правках ассетов.

## EGC-23 — Screen Template отчёта о конце хода

- [ ] EGC-23 — Screen Template отчёта о конце хода

**Зависимость:** EGC-22. **Файлы:** новая schema записей отчёта в `GameData/textsystem/schemas/`; `WBP_TurnReport` и запись в Screen Registry через `unreal-mcp`; фикстурный документ в `Tests/Fixtures/SyntheticMechanicalFixture/`, spec в `Tests/Lua/presentation/`. Docs: `ScreenTemplates.md`, `WidgetRegistry.md`.

**Инвариант:** [SR-002](../../Status/ScreenRequests.md#sr-002-отчёт-о-конце-хода) в редакции EGC-21. Записи показываются по одной, номер текущей записи — transient mode state активного режима, «Далее» — обычная команда режима, то есть каждый шаг является новой ревизией того же Screen Instance. Нарушение — попытка листать записи UI-локально: механизма объявленного UI-local действия в движке нет, и этот план его не вводит.

**Решение:** шаблон показывает одну запись: заголовок, необязательную картинку, текст и кнопки. Кнопка перехода к следующей записи — элемент списка кнопок с binding на команду режима; на последней записи вместо неё кнопка завершения. Подпись кнопки перехода принадлежит шаблону `textsystem`, а не приходит из Lua. Stable identity записи — идентификатор фазы и её результата, не индекс и не текст.

**Шаги:**
1. Завести схему записей и шаблон; поле картинки отсутствует — запись без картинки, а не заглушка.
2. Собрать фикстурный документ: три записи, из них одна без картинки.
3. Пройти шаги командами режима; проверить переиспользование виджетов по `key` между шагами.
4. Проверить, что при пустом списке записей режим не стартует и экран не открывается.
5. Прогнать матрицу разрешений.

**Done:**
- Шаблон зарегистрирован; фикстурный документ проходит Prepare/Commit.
- Шаг отчёта — новая ревизия того же Screen Instance; виджеты переиспользованы по `key`.
- Запись без картинки рендерится без заглушки.
- Пустой список записей не открывает экран.
- Матрица разрешений пройдена.

**Evidence:** spec фикстуры, отчёт о переиспользовании виджетов, прогон матрицы, отчёт `unreal-mcp`.

## EGC-24 — Screen Template магазина

- [ ] EGC-24 — Screen Template магазина

**Зависимость:** EGC-23. **Файлы:** новая schema товаров в `GameData/textsystem/schemas/`; `WBP_Shop` и запись в реестре через `unreal-mcp`; фикстурный документ и spec. Docs: `ScreenTemplates.md`, `WidgetRegistry.md`.

**Инвариант:** [SR-003](../../Status/ScreenRequests.md#sr-003-экран-магазина) в редакции EGC-21: отдельной области описания нет, описание товара показывается в его строке, выбора товара как UI-local состояния нет. Плюс общий инвариант этапа про размер кнопки: подписи покупки — первый кандидат на `label_overflow`.

**Решение:** строка товара несёт иконку, название, описание, цену и кнопку покупки с `enabled`/`disabled_reason` по модели EGC-22. Баланс игрока — отдельное текстовое поле. После покупки Lua публикует новую ревизию того же экрана: меняются баланс и доступность, `key` товаров не меняются, прокрутка сохраняется как UI-local состояние. Неактивность товара — только presentation; команда покупки перепроверяет деньги.

**Шаги:**
1. Завести схему и шаблон; описание — поле строки товара.
2. Собрать фикстурный документ: товар доступный, недоступный с причиной, товар без иконки.
3. Проверить, что подписи кнопок покупки помещаются в размер кнопки темы; при переполнении сократить подпись или объявить размер поверхности — не расширять кнопку под текст.
4. Опубликовать вторую ревизию с изменённым балансом; проверить сохранение прокрутки и переиспользование виджетов по `key`.
5. Прогнать матрицу разрешений.

**Done:**
- Шаблон зарегистрирован; фикстурный документ проходит Prepare/Commit.
- Ни одна подпись кнопки не вызывает `label_overflow` на всех разрешениях матрицы.
- Вторая ревизия сохраняет прокрутку и переиспользует виджеты по `key`.
- Недоступный товар приходит без binding и с причиной.
- Матрица разрешений пройдена.

**Evidence:** spec фикстуры, отчёт об отсутствии `label_overflow` по матрице, отчёт о переиспользовании, отчёт `unreal-mcp`.

## EGC-25 — Screen Template диалога

- [ ] EGC-25 — Screen Template диалога

**Зависимость:** EGC-24. **Файлы:** новая schema вариантов в `GameData/textsystem/schemas/`; `WBP_Dialogue` и запись в реестре через `unreal-mcp`; фикстурный документ и spec. Docs: `ScreenTemplates.md`, `WidgetRegistry.md`.

**Инвариант:** [SR-004](../../Status/ScreenRequests.md#sr-004-экран-диалога). Каждый шаг — новая ревизия того же Screen Instance, поэтому экран не пересоздаётся между шагами; `key` варианта — стабильный идентификатор из данных диалога, не индекс и не текст. Нарушение — пересоздание экрана на каждом шаге, теряющее UI-local состояние.

**Решение:** шаблон показывает имя говорящего, портрет, картинку шага, текст и список вариантов. «Далее» — обычный вариант с binding, а не отдельная кнопка шаблона. Длинный текст прокручивается; прокрутка сбрасывается при смене шага. Неактивный вариант — по модели EGC-22.

**Шаги:**
1. Завести схему и шаблон; реплика рассказчика — шаг без имени говорящего и без портрета.
2. Собрать фикстурный документ: шаг с одним вариантом «Далее», шаг с тремя вариантами, шаг с неактивным вариантом, шаг от рассказчика.
3. Пройти три шага подряд; проверить, что Screen Instance тот же, а виджеты вариантов переиспользованы по `key` там, где ключи совпали.
4. Проверить сброс прокрутки при смене шага и её сохранение внутри шага.
5. Прогнать матрицу разрешений, включая длинный текст.

**Done:**
- Шаблон зарегистрирован; фикстурный документ проходит Prepare/Commit.
- Три шага подряд не пересоздают Screen Instance.
- Шаг без говорящего рендерится без заглушек.
- Прокрутка сбрасывается при смене шага.
- Матрица разрешений пройдена для длинного текста.

**Evidence:** spec фикстуры, отчёт об идентичности Screen Instance, прогон матрицы, отчёт `unreal-mcp`.

## EGC-26 — Screen Template сцены участников

- [ ] EGC-26 — Screen Template сцены участников

**Зависимость:** EGC-25. **Файлы:** новая schema участников в `GameData/textsystem/schemas/`; `WBP_ParticipantScene` и запись в реестре через `unreal-mcp`; фикстурный документ и spec. Docs: `ScreenTemplates.md`, `WidgetRegistry.md`.

**Инвариант:** [SR-005](../../Status/ScreenRequests.md#sr-005-экран-танца). Участники и полосы сохраняют виджеты по `key` между действиями; временные характеристики существуют только в режиме. Структура «участники с показателями, описание, действия» не зависит от танца. Нарушение — шаблон, знающий про танец.

**Решение:** вложенная коллекция: участники, у каждого — имя, портрет и полосы показателей. Полоса — существующий элемент `progress_bar`; вложенность коллекций выражается уже существующими declared composites, новый элемент UI не вводится. Действия — список по модели EGC-22.

**Шаги:**
1. Завести схему и шаблон на существующих элементах; доказать, что новый элемент UI не потребовался.
2. Собрать фикстурный документ: два участника с разным числом полос, участник без портрета.
3. Опубликовать вторую ревизию с изменёнными значениями полос; проверить переиспользование виджетов участников и полос по `key`.
4. Проверить отказ при одном участнике, если заявка требует минимум двух.
5. Прогнать матрицу разрешений.

**Done:**
- Шаблон зарегистрирован; фикстурный документ проходит Prepare/Commit.
- Вложенная коллекция собрана из существующих элементов; перечень использованных элементов приведён.
- Вторая ревизия переиспользует виджеты участников и полос по `key`.
- Нарушение минимального числа участников отвергается названной диагностикой.
- Матрица разрешений пройдена.

**Evidence:** spec фикстуры, перечень использованных элементов, отчёт о переиспользовании, прогон матрицы, отчёт `unreal-mcp`.
