# M1 — Service Authoring

> **Материализует:** разделы 6—14 [предложения](../../Proposals/GameplayServiceAuthoringProposal.md).
> **Задачи:** GSA-01…05.
> **Результат:** пакет объявляет сервис одной таблицей и не видит устройства реестра.

## Результат этапа

`services` доступен в авторском окружении. Сервис объявляется атомарно, содержит только функции, неизменяем после регистрации и наследует execution scope вызывающего.

Этап сам по себе не добавляет игре ни одной способности — потребитель появляется в M2.

## Задачи

- [ ] **GSA-01 — Создать ADR по авторским сервисам**
  - Done: ADR фиксирует критерий выбора между методом сущности и сервисом через владение операцией; атомарное объявление и вызов через точку; контракт «только функции» с явным разделением проверяемого гейтом и конвенции без гейта; kind `service` и проверку формы ID в реестре; неизменяемость после регистрации; наследование execution scope вызывающего; атрибуцию `fail()` и `emit()` пакету объявления; разрешение межпакетной ссылки на заморозке. Отдельно записывает отвергнутое: распределённое объявление, вызываемый сервис, форма `service("name", …)`, расширение чужого сервиса модом, сервисы без потребителя. Записывает, что механизм принимается только вместе с потребителем из M2. Принят до первой отметки `[x]` ниже.
  - Evidence: `Docs/ADR/0035-*.md`, `Docs/ADR/README.md`. Номера 0033 и 0034 закреплены за UIC-01 и CVA-01; при другом порядке выполнения номера меняются местами с обновлением ссылок в том же change set.

- [ ] **GSA-02 — Kind `service` и проверка формы ID**
  - Зависимости: GSA-01.
  - `service_registry.register` проверяет только «непустая строка», тогда как `validator_registry` требует `stable_id.is_kind(id, "validator")`.
  - Done: kind `service` внесён в реестр kinds [Stable ID Specification](../../Architecture/StableIDSpecification.md); `service_registry.register` отклоняет ID, не являющийся каноническим Stable ID kind `service`; существующие спеки жизненного цикла, использующие `core:service.test.*`, продолжают проходить; отрицательный случай покрыт спекой.
  - Evidence: `Docs/Architecture/StableIDSpecification.md`, `Scripts/runtime/service_registry.lua`, `Tests/Lua/lifecycle/lifecycle_phases.lua`.

- [ ] **GSA-03 — Прокси `services` и контракт таблицы**
  - Зависимости: GSA-02.
  - Done: `services` доступен в авторском `_ENV`; присваивание таблицы объявляет сервис и канонизирует ID как `<package_id>:service.<name>`; принимаются только таблицы, содержащие исключительно функции; отклоняются `InvalidServiceName`, `InvalidServiceImplementation`, `ServiceFieldNotFunction`; распределённое объявление `services.trade.buy = …` отклоняется; регистрация выполняется через существующий `game.services.register`, второй реестр не создаётся.
  - Evidence: `Scripts/authoring/context.lua`, `Tests/Lua/authoring/gameplay_services.lua`.

- [ ] **GSA-04 — Неизменяемость, дубликаты и разрешение ссылок**
  - Зависимости: GSA-03.
  - Done: зарегистрированная реализация неизменяема — подмена операции через локальное имя и через канонический ID отклоняется `ServiceImmutableAfterRegistration`; повторное объявление того же ID даёт `ServiceDuplicateDeclaration`; объявление после заморозки — `ServiceDeclarationAfterFreeze`; обращение к необъявленному локальному имени даёт `UnknownServiceKey`, а не `nil`, по образцу проксы команд; межпакетная ссылка на уровне модуля разрешается на заморозке, отсутствующий сервис даёт `ServiceTargetMissing` с указанием обращающегося пакета и запрошенного ID; каждый случай покрыт отрицательной спекой.
  - Evidence: `Scripts/authoring/context.lua`, `Tests/Lua/authoring/gameplay_services.lua`.

- [ ] **GSA-05 — Наследование execution scope**
  - Зависимости: GSA-04, CVA-09 плана [CommandValidators](../CommandValidators/README.md).
  - Формулировка «мутирующий сервис из валидатора завершится ошибкой мутации» недостаточна: она срабатывает, только если сервис действительно пишет в состояние, и пропускает сервис, вызывающий `emit(...)` или `commands.*:later(...)`.
  - Done: сервис исполняется в scope вызывающего и собственного не создаёт; охранники побочных эффектов применяются к телу сервиса так же, как к телу валидатора; `fail()` и `emit()` из сервиса атрибутируются пакету объявления, что проверено межпакетным вызовом; вложенный вызов сервиса не создаёт команды, окна мутации и отдельного commit; мутация из сервиса вне команды отклоняется.
  - Evidence: `Scripts/authoring/context.lua`, `Tests/Lua/authoring/gameplay_services.lua`.

## Проверка milestone

- [ ] `services.foo = { … }` регистрирует сервис; ID генерируется автоматически.
- [ ] Таблица с полем-значением и распределённое объявление отклоняются.
- [ ] Подмена операции, дубликат, позднее объявление и неизвестное имя отклоняются типизированными ошибками.
- [ ] Ссылка на несуществующий сервис обнаруживается на заморозке.
- [ ] Сервис, вызванный из валидатора, подчиняется ограничениям валидатора.
- [ ] Второй реестр сервисов не создан.
