# План редактора контента

> **Материализует:** [Content Editor Plugin](../../Proposals/ContentEditorPluginProposal.md).
> **Задачи:** CED-01…20.
> **Результат:** геймдизайнер редактирует определения `item`, `location`, `actor` и `world` формой в Unreal Editor; на диске остаётся тот же JSON5, изменённый атомарно и проверенный той же валидацией, что в CI.

## Цель

Дать встроенную в Unreal Editor среду работы с определениями GV2 — без ручной правки JSON5 в типовых случаях и без второй контентной архитектуры внутри редактора.

Ключевое решение плана лежит не в интерфейсе, а под ним: **общая реализация авторинга становится библиотекой**, и CLI с редактором становятся двумя её frontend-ами. Подпроцесс `gv2-content` в роли backend-а отвергнут — он добавляет границу процесса поверх кода, который и так должен быть общим.

## Состояние на входе

Проверено по коду.

| Что | Сейчас |
|---|---|
| Чтение контента | `GV2ContentCore` и `GV2ContentHostSupport` — библиотеки; UE-модуль их уже линкует |
| Запись контента | `Json5AstRewriter` и реализации операций лежат внутри исполняемого таргета `gv2-content`, вызвать их извне нельзя |
| Операции CLI | `validate`, `inspect`, `describe`, `new`, `set`, `delete`, `rename`, `refs`, `index`, `hash`, `coverage`; поддерживается `--format=json` |
| Атомарность записи | Отсутствует: каждая операция перезаписывает файл независимо |
| Пробное применение изменения схемы | Отсутствует; `refs` даёт ссылки, но не список того, что станет невалидным |
| Метаданные представления | `schemas/<name>.ui.json5` с гейтом `validate_authoring_metadata.py`; единственный пример — `item_v1.ui.json5` |
| Kind-ы определений | `actor`, `item`, `location`, `action`, `resource`, `screen`, `text` |
| Схема `actor` | Базовая в `core` плюс два extension site: `textsystem` и `rh` |
| `world` | Существует только как рантайм-состояние; определением не является |

## Принятые решения

- **Backend — библиотека, а не подпроцесс.** `gv2_content_authoring` владеет операциями записи; CLI и редактор её вызывают.
- **Запись атомарна.** Набор изменённых полей применяется одной операцией по схеме «подготовить → провалидировать → заменить»; дублирование — тоже одна операция.
- **Внешнее изменение файла обнаруживается.** Запись по устаревшему представлению отклоняется, а не выполняется молча.
- **Анализ влияния изменения схемы требует новой операции** пробного применения без записи; это предусловие Schema Editor, а не следствие имеющегося tooling.
- **Понятия, которых нет, не отображаются.** Редактор работает с существующими kind-ами; для будущих специальный workflow проектируется отдельно.
- **Первый срез охватывает четыре kind-а сразу:** `item`, `location`, `actor`, `world`.

## Границы

Входят: библиотека авторинга, адаптер редактора, браузер определений, форма по схеме, панель ссылок, атомарное сохранение, диагностика, четыре kind-а.

Не входят:

- **Schema Editor и анализ влияния** — отдельный этап после подтверждения основного цикла; в этом плане закрывается только предусловие в виде операции пробного применения.
- Raw JSON5 view, bulk editor, localization workspace, live preview.
- Специальные workflow для понятий, которых в проекте нет.
- Интеграция с системой контроля версий сверх того, что даёт текстовый формат.
- Зависимость runtime или headless от редакторского модуля.

## Критический путь

```text
M1 ──► M2 ──► M3 ──► M4 ──► M5
```

**M1 обязателен для всего остального.** Пока операции записи заперты внутри исполняемого файла, у редактора нет способа вызвать их иначе как подпроцессом — то есть ровно тем способом, который отвергнут.

M5 отделён от M4 намеренно: сначала цикл подтверждается на простейшем kind-е, затем расширяется на сложные.

## Общие правила выполнения

1. Канонический источник — `GameData/**/*.json5`. Ни одна задача не превращает определения в `.uasset` и не заводит второй репозиторий.
2. Редактор не воспроизводит правила пакетов, наложения, разрешения Stable ID и валидации: он их вызывает.
3. Runtime и headless не получают зависимости от редакторского модуля; проверяется сборкой.
4. Каждая операция записи заканчивается authoritative-валидацией и перечитыванием канонического представления.
5. Правила проверяются на **отрицательный** случай: неатомарная запись, устаревшее представление, невалидное значение.
6. Точечная правка сохраняет комментарии и форматирование файла.
7. Новое observable behavior синхронно отражается в contract того же change set.

## Итоговый Definition of Done

- [ ] Операции записи вызываются из библиотеки; ни один путь редактора не запускает подпроцесс.
- [ ] CLI и редактор используют одну реализацию: поведение операций совпадает, проверено общими тестами.
- [ ] Сохранение нескольких изменённых полей применяется атомарно; отказ оставляет файл в исходном состоянии.
- [ ] Дублирование определения — одна операция; сбой не оставляет наполовину скопированного определения.
- [ ] Запись по изменившемуся под редактором файлу отклоняется типизированной ошибкой.
- [ ] Форма строится из схемы; добавление поля в схему не требует правки C++ редактора.
- [ ] Ссылки отображаются в обе стороны и переводят к определению.
- [ ] Диагностика показывается структурно и переводит к полю.
- [ ] `item`, `location` и `actor` редактируются полностью, включая extension site из двух пакетов.
- [ ] Правка через редактор даёт тот же результат на диске, что та же правка через CLI, включая сохранение комментариев.
- [ ] Shipping-сборка не содержит редакторского модуля.
