# План укрепления границ generic-абстракций

> **Материализует:** находки `REM-01`…`REM-07` внешнего ревью от [2026-09-01](../../Status/GV2_remaining_review_2026-09-01.md).
> **Задачи:** GBH-01…11.
> **Результат:** три границы generic-модели перестают быть местами, где утверждение сильнее проверки.

## Цель

Ревью фиксирует смену характера рисков, и это главный его вывод: **критические проблемы больше не в schema-specific адаптерах — они переехали в границы generic-абстракций.**

Три границы названы точно:

```text
объявленная capability   →  реальная capability ребёнка
подготовленная мутация   →  транзакционный commit живого виджета
схемы на файловой системе →  авторитет репозитория
```

Первая и третья — незавершённые абстракции: объявление не несёт того, что должно нести. Вторая — единственная настоящая архитектурная недоработка списка: её нельзя закрыть аккуратной проверкой, потому что класс отказа возникает **после** начала необратимого применения.

## Состояние на входе

| Что | Сейчас |
|---|---|
| Сверка объявления композита с ребёнком | `DoesCapabilityTreeSupportKind` сравнивает только вид; диапазон, `TargetKind`, требования идентичности коллекции не участвуют |
| Объявление композита | Хранит `PropertyName`, `ChildWidgetName`, `Kind` — и не хранит, **какую именно** capability ребёнка делегирует |
| `FGV2NumberPropertyConsumer::Prepare` | Проверяет тип и сохраняет значение; объявленный диапазон capability не применяется |
| `CommitUiHostProperties` | Выходит по первому отказу; отката уже применённых мутаций нет, предыдущее физическое состояние не хранится |
| `CommitReconcile` | Присоединяет экраны последовательно; отказ на втором оставляет первый в дереве Shell — остаток записан комментарием в коде, но не строкой статуса |
| `HasHostForLayer` | Существует и реконсилятором не используется |
| `CollectionHost` в Designer | Выбирается в списке видов, объявляется через `AddCustom` без `EntryWidgetClass` и ключевого свойства — создать первый элемент невозможно |
| UI-схемы | Сканируются с файловой системы, не принадлежат closure активного репозитория (`UPP-R5`) |
| `ScreenTemplates.md` | Описывает `schema_id` и политику необязательного host на уровне элемента, чего в `IGV2ScreenFieldHost` нет |
| `ApplyOptionalImageResource`, `ApplyOptionalPortrait` | Остались в публичном API вопреки `ADR-0040` |

## Принятые решения

- **Объявление обязано нести параметры своего вида.** Плоскость схемы для автора контента сохраняется — он по-прежнему пишет `day: TextSpec`, а не `day.text`. Обогащается **объявление**, а не схема: для числа это диапазон, для коллекции — класс элемента и ключевое свойство. Тройка `(имя, ребёнок, вид)` оказалась недостаточной для видов со структурой, и `REM-01` с `REM-05` — два следствия одного упрощения.
- **Каждый выбираемый в Designer вид обязан быть работоспособен от объявления до отрисовки.** `CollectionHost` — тот же класс дефектов, что `AddObject` до `PCC-05`, только на поверхности, которую видит автор контента, а не программист. Поэтому вводится гейт по перечислению видов Designer, симметричный гейту по `EGV2PreparedUiValueKind`.
- **`REM-02` решается ADR, а не задачей.** Из трёх возможных механизмов — откат каждой мутации, commit в теневое состояние со свопом, иной транзакционный commit — выбор меняет модель, а не реализацию, и обязан быть обоснован до написания кода.
- **Инъекция отказа ставится в опасную точку, а не в удобную.** `PCC-07` закрывался инъекцией и не обнаружил `REM-02`, потому что инъекция стояла на уровне экрана, а не в середине commit переиспользуемого живого экземпляра. Это повторяется в `GBH-11` как явное требование.

## Границы

Не входят: `STATUS-001`, `STATUS-002`, `STATUS-003`. Форма схемы, видимая автору контента, не меняется — обогащается только объявление в Designer.

## Milestones

- [ ] M1 — [Declared Surface](DeclaredSurface.md): объявляемая поверхность работоспособна целиком, структурный отказ предсказывается до мутации. GBH-01…05.
- [ ] M2 — [Declaration Constraints](DeclarationConstraints.md): объявление несёт свои ограничения и сверяется с ребёнком полностью. GBH-06…08.
- [ ] M3 — [Transactional Commit](TransactionalCommit.md): commit живого виджета транзакционен либо контракт сужен до фактического. GBH-09…11.

## Критический путь

```text
M1 задачи независимы друг от друга

GBH-06 ──► GBH-07 ──► GBH-08        (строгий порядок внутри M2)

GBH-09 ──► GBH-10 ──► GBH-11        (ADR до реализации, реализация до сверки)

M2 и M3 независимы друг от друга; M3 завершает план
```

## Общие правила выполнения

1. Задача не отмечается `[x]`, пока не назван тест, который **покраснеет** при откате изменения, и это не продемонстрировано.
2. Закрытие дефекта, тронувшего N мест одной формы, обязано либо покрыть все N, либо объяснить, почему часть не нуждается в отдельном доказательстве.
3. Остаток, сознательно не закрываемый задачей, записывается строкой `STATUS-NNN` с наблюдаемым условием повторного открытия, а не комментарием в коде.
4. Ассеты меняются только через `unreal-mcp`, с compile, save и прогоном automation.
5. Правки нормативных контрактов выполняются в той же задаче, что и код.

## Итоговый Definition of Done

- [ ] Структурная непригодность Shell предсказывается в Prepare; частично присоединённого дерева не возникает. (GBH-01)
- [ ] Каждый выбираемый в Designer вид работоспособен от объявления до отрисовки; неработоспособный вид краснит сборку. (GBH-02)
- [ ] Судьба принадлежности UI-схем репозиторию решена: либо реализована, либо записана строкой статуса с условием повторного открытия. (GBH-03)
- [ ] Контракты описывают фактический `IGV2ScreenFieldHost`. (GBH-04)
- [ ] Параллельные optional-пути применения удалены из публичного API. (GBH-05)
- [ ] Объявление несёт параметры своего вида и указывает, какую capability ребёнка делегирует. (GBH-06, GBH-08)
- [ ] Значение, выходящее за объявленное ограничение capability, отклоняется до виджета, а не обрезается им. (GBH-07)
- [ ] Сверка объявления с ребёнком сравнивает capability целиком, а не только вид. (GBH-08)
- [ ] Отказ commit переиспользуемого живого экрана не оставляет физически применённой части новой ревизии — либо контракт сужен до фактического поведения. (GBH-09, GBH-10)
- [ ] Инъекция отказа стоит в середине commit переиспользуемого живого экземпляра. (GBH-11)
- [ ] Каждая находка ревью закрыта продемонстрированным красным тестом. (GBH-11)
