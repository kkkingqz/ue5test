# M3 — Lifecycle and Closure

> **Материализует:** `GBH-R5`, перечислитель границ отката и закрытие раунда.
> **Задачи:** GBF-06…08.
> **Результат:** побочные эффекты вынесены за пределы отменяемой транзакции, а множество границ перестаёт быть рукописным.

## Результат этапа

`GBF-07` — самая важная задача плана, и её легко принять за формальный аудит. `GBH-10` нашёл шесть границ отката систематическим просмотром каждой последовательности фазы Commit. Список был верен в момент написания; седьмую границу, добавленную позже, он не покроет, и обнаружит её следующее внешнее ревью — ровно так, как обнаружило `GBH-R1`, где рукописный перечень ветвей отказа attach не содержал `AddChild`.

Поэтому задача считается закрытой не тогда, когда границы перечислены, а когда **перечисление выполняет механизм**.

## Задачи

- [x] **GBF-06 — Callback вне отменяемой транзакции**
  - Зависимости: GBF-05.
  - `OnScreenFieldsApplied` вызывается до окончательной публикации транзакции документа. Blueprint, подписанный на это событие, наблюдает и может изменить состояние ревизии, которая ещё может быть отменена, — и его собственные действия откатом не покрываются.
  - Инвариант: наружу выходит только зафиксированное состояние ([UI Document § Атомарность публикации](../../UI/UIDocumentAndReconciliation.md)). Нарушение особое тем, что последствия производит не наш код: побочный эффект принадлежит Blueprint, поэтому в откат он не попадает даже теоретически.
  - Не считается закрытием: включение callback в транзакцию с попыткой откатить его последствия; перенос вызова на строку ниже без доказательства, что точка теперь после публикации; проверка подписчиков только в известных трёх ассетах.
  - Done:
    - ни один Blueprint/UI-callback не исполняется внутри отменяемой транзакции, если сам не является её частью;
    - `OnScreenFieldsApplied` перенесён за точку окончательной публикации либо удалён при отсутствии подписчиков;
    - выбор обоснован проверкой фактических подписчиков в C++ и во **всех** `.uasset`, а не в известных трёх;
    - тест подтверждает, что при отказе после прежней точки вызова callback не вызывается вовсе;
    - контракт описывает фактический момент вызова.
  - Evidence: `Source/GV2/Private/UI/GV2ScreenWidgetBase.cpp`, `Content/`, `Docs/UI/UIDocumentAndReconciliation.md`.

- [x] **GBF-07 — Границы отката перечисляет механизм**
  - Зависимости: GBF-06.
  - Шесть границ (свойство, хост/экран, документ, Shell-attach, элемент keyed-коллекции, вложенный экран во вкладке) найдены аудитом. Рукописный список — напоминание, а не гейт: он верен на момент написания и молча устаревает.
  - Инвариант: универсальное утверждение требует перечислителя (`AGENTS.md`). Это главная задача плана. Нарушение уже наблюдалось дважды: рукописный перечень ветвей отказа attach не содержал `AddChild` (`GBH-R1`), рукописный перечень constraint-полей не содержал `KeyPropertyName`. Седьмая граница отката, добавленная после этого плана, повторит ту же историю, если её появление ничем не отслеживается.
  - Не считается закрытием: расширенный до семи пунктов рукописный список; комментарий в коде, перечисляющий границы; тест, проверяющий шесть известных границ поимённо.
  - Done:
    - введён механизм, перечисляющий места, где может произойти отказ после начала применения;
    - для каждого такого места требуется либо покрытие контрактом восстановления, либо явная классификация с причиной;
    - появление новой границы без покрытия роняет гейт; форма гейта — runtime-тест по образцу `GBH-05` либо портативная проверка через CTest по образцу `GBF-03`, но не отказ компиляции: границы существуют как места в коде, а не как типы;
    - шесть известных границ проходят через этот механизм, а не перечисляются рядом с ним;
    - есть отрицательный самотест: синтетическая новая граница без покрытия обязана его уронить;
    - в отчёте зафиксировано, что именно механизм перечисляет и какие места он по построению не видит.
  - Evidence: `Source/GV2/Private/UI/`, `Source/GV2/Private/Tests/`, отчёт change set.

- [x] **GBF-08 — Сверка закрытий и архивация раунда**
  - Зависимости: GBF-07.
  - Инвариант: закрытие проверяется независимо от задачи, которая его заявила. Две предыдущие такие сверки нашли непокрытую часть собственной работы плана — `PCC-12` (тест чистоты покрывал один класс из трёх) и приёмка `GBH` (отсрочка, пережившая обоснование). Считать эту сверку формальной нет оснований.
  - Не считается закрытием: ссылка на задачу вместо продемонстрированного красного теста; закрытие экземпляра при неразобранном классе; исход «закрыто, но не проверено».
  - Done:
    - для каждой находки `GBH-R1`…`GBH-R7` назван гейт и продемонстрировано, что он краснеет при откате соответствующего изменения;
    - подтверждено, что закрыт класс, а не экземпляр: закрытие, тронувшее несколько мест одной формы, покрывает все либо объясняет исключения;
    - проверено, что ни одна починка не свелась к сужению `ADR-0041` и не ввела schema-specific путь;
    - `STATUS-008` не изменён, условие его повторного открытия не наступило;
    - полный прогон — UE automation, портативный CTest, `gv2-headless --check-scripts`, `validate_docs.py` — зелёный;
    - ревью перенесено в `Docs/Status/Archive/` двухкоммитной процедурой `AGENTS.md`.
  - Evidence: отчёт change set, `Source/GV2/Private/Tests/`, `Docs/Status/Archive/`.
  - **Проверка 2026-09-03:** сначала не закрыта — полный прогон подтверждался набором из 16 тестов фильтра `GV2.UI` при 108 в наборе, а падающий тест лежал в группе `GV2.Runtime.UI.*`, под фильтр не попадающей. Доведено: прогон по всему набору, 108/108, счёт взят из `index.json` (`-ReportExportPath`), а не подсчётом строк лога — лог обрывается на последнем тесте при завершении сессии. См. `GBF-AF-02`.
