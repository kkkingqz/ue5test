# План доведения транзакционной модели UI

> **Материализует:** находки `GBH-R1`…`GBH-R7` внешнего ревью от [2026-09-02](../../Status/GV2_GenericBoundaryHardening_Followup_Review_2026-09-02.md).
> **Задачи:** GBF-01…08.
> **Результат:** обещанная `ADR-0041` атомарность выполняется механизмом, а не совпадением, и каждое универсальное утверждение модели имеет перечислитель.

## Цель

Раунд нашёл дефекты не на новой территории, а **внутри ремонтной машинерии, построенной предыдущим планом**. Три из семи находок — прямое следствие того, что механизм проверялся против собственной модели: план отката строится по текущей схеме и потому неверно восстанавливает смену схемы; откат чинит физическое состояние и не чинит учётное; гейт полноты выводился из раскладки памяти вместо списка полей.

Отдельно `GBH-R1` показывает, во что обходится рукописный перечень: ветви отказа `AttachScreenToLayer` аудировались руками, `AddChild() == nullptr` в список не попал, и recovery-ветка из `GBH-10`, написанная специально под непредсказуемый отказ attach, оказалась недостижимой — функция скрывает собственный отказ.

Поэтому у плана две задачи, а не одна: закрыть семь находок и **привести механизмы к правилу перечислителя** (`AGENTS.md`, «Универсальное утверждение требует перечислителя»). Без второй половины следующий раунд найдёт восьмую границу отката, которую сегодняшний рукописный список из шести не покрывает.

## Состояние на входе

| Что | Сейчас |
|---|---|
| `AttachScreenToLayer` | Возвращает `true` при `AddChild() == nullptr`; результат используется только для `Cast<UOverlaySlot>` |
| План отката | Строится по **текущей** схеме; при смене схемы восстанавливает значения в форму новой, а не прежней |
| Восстановление | Возвращает физическое состояние и не возвращает `LastCommittedProperties` и метаданные схемы |
| Невозможность подготовить откат | Логируется, транзакцию не блокирует |
| `OnScreenFieldsApplied` | Вызывается до окончательной публикации транзакции документа |
| `keyed_by` схемы | Не проецируется в `KeyPropertyName` capability, поэтому сравнение из `GBH-08` не с чем выполнять |
| Гейт полноты полей | `sizeof` — суррогат: новое поле садится в padding, размер не меняется, гейт остаётся зелёным |
| Границы отката | Шесть, найдены аудитом; перечислителя, который найдёт седьмую, нет |

## Принятые решения

- **Ни одна находка не закрывается сужением `ADR-0041`.** Частично применённое состояние не становится допустимым нормальным контрактом — это правило унаследовано от `GBH-09` и здесь действует так же.
- **Каждое универсальное утверждение получает перечислитель.** «Все ветви отказа attach», «все границы отката», «все поля capability» — для каждого называется механизм, порождающий множество. Рукописный список допустим только как напоминание и подписывается как напоминание.
- **Обратная мутация обязательна, а не опциональна.** Невозможность подготовить откат для свойства — отказ фазы Prepare, а не запись в лог: транзакция, чей откат не построен, не является транзакцией.
- **Порядок починок — от детерминированных к структурным.** `GBF-01`…`03` закрывают дефекты, у которых есть однозначный правильный ответ; `GBF-04`…`05` меняют форму механизма; `GBF-06` выносит побочный эффект за пределы отката. Обратный порядок заставил бы переделывать структуру дважды.

## Границы

Не входят: `STATUS-008` (владение UI-схемами репозиторием) — если по ходу появятся схемы, поставляемые модом, работа останавливается и выделяется отдельно; переработка Screen Registry; возврат к schema-specific DTO; рефлексивная привязка имён свойств к `UPROPERTY`; изменение конвейеров текста и изображений.

## Отношение к параллельному плану

[DeclaredCompositeAdoption](../DeclaredCompositeAdoption/README.md) выполняется независимо. Пересечение одно — `GV2UiMutationPlan.cpp`: `DCA-08` удаляет из него хардкод `Cast` по классам локации, `GBF-04` меняет форму плана мутаций. Владение по участкам: разрешение цели — за `DeclaredCompositeAdoption`, построение и откат плана — за этим планом. При одновременном ведении `DCA-08` выполняется до `GBF-04`, иначе удаление мостика придётся повторять поверх новой формы.

## Milestones

- [ ] M1 — [Deterministic Bugs](DeterministicBugs.md): дефекты с однозначным правильным ответом закрыты. GBF-01…03.
- [ ] M2 — [Structural Rollback](StructuralRollback.md): откат восстанавливает то же состояние, что было, а не то, что описывает текущая схема. GBF-04…05.
- [ ] M3 — [Lifecycle and Closure](LifecycleAndClosure.md): побочные эффекты вне транзакции, границы перечислимы, раунд закрыт. GBF-06…08.

## Критический путь

```text
GBF-01, GBF-02, GBF-03      — независимы друг от друга

GBF-04 ──► GBF-05 ──► GBF-06 ──► GBF-07 ──► GBF-08

GBF-02 предшествует GBF-07: пока keyed_by не спроецирован,
аудит границ коллекций опирается на несравнимые стороны
```

## Общие правила выполнения

1. Задача не отмечается `[x]`, пока не назван гейт, который **покраснеет** при откате изменения, и это не продемонстрировано.
2. Для каждого универсального утверждения задачи назван перечислитель множества. Ответ «просмотрели код» перечислителем не является: такое утверждение либо сужается, либо переносится в `STATUS-NNN`.
3. Регрессия пишется до починки и проходит через production-путь, а не через прямой вызов helper-а.
4. Ассеты меняются только через `unreal-mcp`; этот план изменений ассетов не предполагает.
5. Правки нормативных контрактов выполняются в той же задаче, что и код.

## Итоговый Definition of Done

- [ ] `AttachScreenToLayer` не может вернуть успех после неудачного `AddChild`; отказ доходит до `CommitReconcile` и запускает восстановление по `ADR-0041`. (GBF-01)
- [ ] `keyed_by` схемы проецируется в `KeyPropertyName` capability, и сравнение из `GBH-08` получает две сопоставимые стороны. (GBF-02)
- [ ] Полнота полей capability проверяется инвентаризацией членов по исходнику с отрицательным самотестом; `sizeof` в роли доказательства отсутствует. (GBF-03)
- [ ] Каждая прямая мутация плана имеет обратную; невозможность её подготовить — отказ Prepare, а не запись в лог. (GBF-04)
- [ ] Откат при смене схемы восстанавливает значения в форму **прежней** зафиксированной схемы. (GBF-04)
- [ ] Восстановление возвращает вместе с физическим состоянием `LastCommittedProperties` и метаданные схемы. (GBF-05)
- [ ] Ни один Blueprint/UI-callback не исполняется внутри отменяемой транзакции, если сам не является её частью. (GBF-06)
- [ ] Множество границ отката перечисляется механизмом, а не рукописным списком; появление новой границы без покрытия краснит сборку. (GBF-07)
- [ ] Каждая находка `GBH-R1`…`GBH-R7` закрыта продемонстрированным red-on-revert гейтом. (GBF-08)
- [ ] `STATUS-008` не изменён; условие его повторного открытия не наступило. (GBF-08)
