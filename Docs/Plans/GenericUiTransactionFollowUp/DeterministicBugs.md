# M1 — Deterministic Bugs

> **Материализует:** `GBH-R1`, `GBH-R6`, `GBH-R7`.
> **Задачи:** GBF-01…03.
> **Результат:** три дефекта, у которых есть однозначный правильный ответ, закрыты, и ни один из трёх гейтов больше не опирается на суррогат.

## Результат этапа

Эти три находки объединяет то, что спорить о решении не о чем: отказ обязан распространяться, `keyed_by` обязан проецироваться, полнота обязана выводиться из списка полей. Этап идёт первым, потому что `GBF-02` даёт `GBF-07` сопоставимые стороны, а `GBF-03` задаёт образец перечислителя, по которому строится `GBF-07`.

Задачи независимы друг от друга и переставляются.

## Задачи

- [x] **GBF-01 — Shell-attach сообщает о фактическом отказе**
  - `UGV2GameShellWidgetBase::AttachScreenToLayer` использует результат `Host->AddChild(ScreenWidget)` только для приведения к `UOverlaySlot` и возвращает `true` независимо от него. `GBH-10` при этом построил в `CommitReconcile` ветку восстановления, срабатывающую по `false` от этой функции, и прямо называл отказ `AddChild` примером непредсказуемого engine-level отказа. Ветка недостижима для случая, ради которого написана.
  - Инвариант: результат отказоспособной операции обязан быть потреблён ([UI Document § Границы транзакционности](../../UI/UIDocumentAndReconciliation.md)). Нарушение здесь выглядит как «логический успех при физическом отсутствии»: экран опубликован в `ActiveScreens` и не присутствует в дереве Shell.
  - Не считается закрытием: проверка одного лишь `AddChild` при сохранении остальных отбрасываемых результатов в файле; регрессия, вызывающая helper напрямую вместо прохода через production-путь; заново составленный вручную перечень ветвей отказа.
  - Done:
    - `AddChild() == nullptr` даёт `false` из `AttachScreenToLayer`;
    - отказ доходит до `CommitReconcile` и запускает восстановление по `ADR-0041`;
    - `ActiveScreens`, прежние виджеты и метаданные остаются предыдущей ревизией;
    - регрессия проходит через production `CommitReconcile` и проверяет состояние дерева Shell, а не возвращённое значение;
    - назван перечислитель множества «отказоспособные вызовы движка в этом файле» — гейт, краснящий при отбрасывании результата такого вызова.
  - Evidence: `Source/GV2/Private/UI/GV2GameShellWidgetBase.cpp`, `Source/GV2/Private/UI/GV2LayeredUiReconciler.cpp`, `Source/GV2/Private/Tests/`.

- [ ] **GBF-02 — `keyed_by` схемы проецируется в capability**
  - `GBH-08` добавил сравнение `KeyPropertyName`, но схема проецирует `keyed_by` только в флаг `bRequiresKeyedIdentity`; само имя ключевого поля в capability со стороны схемы не попадает. Сравнение получает две стороны, одна из которых всегда несёт значение по умолчанию, — то есть проверка есть, а сравнивать нечего.
  - Инвариант: `SchemaContract ⊆ WidgetCapabilities` ([ADR-0040](../../ADR/0040-universal-ui-property-pipeline.md)). Нарушение здесь тихое: сверка формально исполняется и не может провалиться, потому что одна её сторона не заполняется.
  - Не считается закрытием: приведение объявления к умолчанию схемы вместо проекции самой схемы; тест, сравнивающий два значения по умолчанию.
  - Done:
    - `keyed_by` компилированной схемы проецируется в `KeyPropertyName` capability на стороне схемы;
    - несовпадение имени ключа схемы и объявления отклоняется до `Ready` с кодом `KeyPropertyMismatch`;
    - совпадение принимается;
    - зафиксировано, что до этой задачи сравнение из `GBH-08` было неисполнимым, и тест краснеет при возврате проекции только во флаг.
  - Evidence: `Source/GV2/Private/UI/GV2UiCapability.cpp`, `Source/GV2/Private/Tests/`.

- [ ] **GBF-03 — Инвентаризация членов вместо `sizeof`**
  - `static_assert(sizeof(FGV2UiPropertyCapability) == 192)` описан как гейт полноты, но раскладка памяти полноту не доказывает: новое поле садится в существующий padding и размер не меняется. Проверено экспериментально на структуре той же формы — добавление `bool` рядом с `bRequiresKeyedIdentity` оставило `sizeof` неизменным.
  - Инвариант: универсальное утверждение требует перечислителя (`AGENTS.md`). Нарушение здесь — не отсутствие гейта, а ложная уверенность: отсутствие гейта видно, ложная уверенность не видна, поэтому этот случай хуже, чем если бы гейта не было вовсе.
  - Не считается закрытием: замена числа на актуальное; добавление второго суррогата (`alignof`, контрольная сумма имён); превращение структуры в отдельный runtime-framework ради одного гейта.
  - Done:
    - утверждение, что раскладка памяти является доказательством полноты, удалено вместе с `static_assert`;
    - введён механический инвентарь членов по исходнику, сравнивающий фактический список полей с явной таблицей классификации;
    - гейт падает на любом неклассифицированном члене;
    - есть отрицательный самотест, добавляющий синтетический неизвестный член и требующий падения гейта;
    - гейт исполняется через CTest и не зависит от наличия редактора.
  - Evidence: `Source/GV2/Private/UI/GV2UiCapability.cpp`, `Tools/`, `Source/GV2/Private/Tests/`.
