# M1 — Foundation

> **Материализует:** [Lua Runtime Contract](../../../Architecture/LuaRuntimeContract.md) в части окна мутации и изоляции состояния.
> **Задачи:** DLA-01…04.
> **Результат:** рантайм знает, была ли запись, сырое состояние недостижимо из геймплея, проверка переносимости одна на всех.

## Результат этапа

Наблюдаемое поведение не меняется: этап готовит опоры, на которых стоят правило `fail()` и канонизация аргументов. Поэтому идёт первым и отдельно.

## Задачи

- [x] **DLA-01 — Создать ADR по designer-facing слою**
  - Реализация меняет четыре контракта: окно мутации и загрузчик (`LuaRuntimeContract`), семантику отказа и исполнения команд (`CommandsAndEvents`), форму состояния (`CanonicalStateAndSave`), объявление полей в схеме (`DefinitionEnvelopeAndSchemaRules`).
  - Done: ADR фиксирует границу слоя, идентичность команды по ключу дескриптора, отложенную регистрацию, правило `fail()` с `write_revision`, три вида property, помеченную ссылку как механизм обратного превращения, sparse-материализацию runtime-полей и изоляцию сырого состояния; перечисляет отвергнутые альтернативы с причинами; принят до первой отметки `[x]` ниже.
  - Evidence: Создан `Docs/ADR/0027-designer-lua-authoring-layer.md`, зарегистрирован в `Docs/ADR/README.md`.

- [x] **DLA-02 — Ввести `write_revision` в окно мутации**
  - Зависимости: DLA-01.
  - Счётчик принадлежит `mutation_window`, а не слою: тогда он считает записи любого происхождения — прямое присваивание, доменный метод, сервис.
  - Done: монотонный счётчик увеличивается в `__newindex` guarded-прокси; `M.write_revision()` доступен модулям ядра; спеки покрывают рост при записи через доменный метод и через сервис, идемпотентную запись (`x = x` считается мутацией), запись во вложенную таблицу и **`table.insert`/`table.remove` на guarded-таблице**; обоснование эксклюзивности внутри команды (запрет вложенной диспетчеризации, закрытое окно у подписчиков, своё окно у отложенных команд) записано рядом со счётчиком.
  - Evidence: Добавлен счётчик `write_revision` и `M.write_revision()` в `Scripts/runtime/mutation_window.lua`. Спека `Tests/Lua/lifecycle/mutation_window.lua` проверяет все сценарии инкремента.

- [x] **DLA-03 — Изолировать сырое состояние**
  - Зависимости: DLA-01.
  - `unwrap_state` сегодня в экспорте; продакшн-Lua его не вызывает, два спека вызывают ради `validate_state_tree`.
  - Done: `unwrap` возвращается отдельным `admin`-handle по образцу реестра подписчиков; `guard_state` остаётся в экспорте — его вызывает C++; два спека переведены; попытка достать сырое состояние из геймплейного пакета невозможна и покрыта negative case; в contract записано, что ни один геймплейный модуль, доменный метод или сервис не получает сырое каноническое состояние.
  - Evidence: `unwrap_state` удалён из экспорта `Scripts/runtime/mutation_window.lua`, добавлен `create_controller()` с admin handle; спеки `Tests/Lua/actions/location_actions.lua` и `Tests/Lua/economy/economy_service.lua` переведены на проверку без unwrap; негативный тест в `Tests/Lua/lifecycle/mutation_window.lua` подтверждает отсутствие `unwrap_state`.

- [x] **DLA-04 — Выделить общий примитив переносимого значения**
  - Зависимости: DLA-01.
  - Проверка живёт локально внутри `event_envelope`; аргументы команд не проверяются вовсе, поэтому обёртка дошла бы до очереди и до run manifest.
  - Done: проверка вынесена в отдельный модуль ядра и переиспользуется конвертом события; `validate_request` проверяет `args` тем же примитивом; очередь отложенных команд — тоже; второй копии правила в дереве не остаётся; спеки покрывают отказ на функцию, userdata, таблицу состояния, обёртку, цикл, разреженный массив и смешанные ключи в каждом из трёх мест.
  - Evidence: Создан `Scripts/runtime/portable_value.lua`, подключён в `event_envelope.lua` и `command_dispatcher.lua`. Спека `Tests/Lua/commands/portable_args.lua` проверяет отказ во всех трёх точках.

## Проверка milestone
