# DeclaredCompositeAdoption: итог выполнения

> **Материализует:** исторический итог выполненного плана; документ не является источником правил или задач.

## Цель и результат

**Цель.** План начинался как миграция: отчёт `DUC-08` записал, что три композита локации к объявлению не сводятся, а проверка это опровергла — набор capability всех трёх выражался объявлением полностью, а названная причина по `CommandPanel` (`OnBindingInvoked`) оказалась мёртвой поверхностью без единого `Broadcast`. Настоящее препятствие лежало в ассетах: композит создавал репитер внутри себя, вне `WidgetTree`, и ради обхода в планировщике жил хардкод трёх `Cast` по конкретным классам локации.

По ходу выполнения цель расширилась. Разбор одной константы (`WrapSize=1200`) и спровоцированная им сплошная проверка проекта показали, что миграция композитов — частный случай общей фигуры: **множество, которое должен перечислять механизм, перечислено руками**. Этапы `M4` и `M5` закрывают эту фигуру там, где она была найдена вне композитов.

**Результат.** В коде не осталось ни одного C++-класса виджета, существующего только ради композиции существующих элементов, ни специального мостика под конкретный композит, ни зашитого пути ассета, ни константы раскладки без записанной причины, ни имени пакета выше `core`. Новый блок собирается в Designer из существующих компонентов без единой строки C++ — это доказано тремя полностью новыми композитами, change set которых не касается production-кода.

## Общий инвариант плана

Проверка, из которой выросли `M4` и `M5`, дала наблюдение, сформулированное в плане и подтверждённое каждой его задачей: **во всех шести найденных случаях авторитетный источник уже существовал в проекте и не читался.**

| Что было перечислено руками | Источник, который уже был | Закрыто |
|---|---|---|
| Адресуемость через внутренний репитер | `WidgetTree` | `DCA-02` |
| Класс элемента и путь ассета в C++ | Запись объявления | `DCA-03` |
| Разрешение цели по трём `Cast` | Реализации `IGV2ScreenFieldHost`/`IGV2UiPropertyHost` | `DCA-08` |
| Порог переноса и абсолютные размеры | Фактически выделенная геометрия | `DCA-15` |
| Контракт компонентов по массиву из 17 при обходе 35 | Asset registry, который тот же тест уже обходил | `DCA-17` |
| Порядок слоёв и владелец схемы | `load_index` в `GameData/mods.lock.json5` | `DCA-18`…`DCA-20` |

Отсюда правило, вынесенное в `Docs/Plans/README.md`: прежде чем писать список, назвать источник, который его заменяет; если источника действительно нет — это содержание задачи, а не повод писать список.

## Введённые перечислители и правила

| Утверждение | Механизм |
|---|---|
| Ни один класс элемента не подставляется зашитым путём ассета | `Tools/Testing/validate_no_hardcoded_asset_paths.py` с отрицательным самотестом |
| Разрешение цели не знает конкретных классов хоста | Automation-гейт: множество из `TObjectIterator<UClass>` + `ImplementsInterface`, плюс проверка, что логика разрешения существует ровно в одном файле |
| Ни один параметр раскладки не является необъяснённой константой | `GV2.Runtime.UIKit.LayoutParameterViewportDerivation` — две обязательные половины: скан `Source/` по грамматике вызовов размера и обход дерева виджетов production-ассетов через Asset Registry. Первый гейт проекта, читающий `Content/` |
| Аудит компонентов покрывает каждый ассет, который перечисляет | Сверка двух счётчиков обхода реестра вместо константы `35` и рукописного массива из 17 |
| Правило слоёв | Сравнение позиций в порядке пиннингованного замыкания; неизвестный namespace отклоняется, а не разрешается по умолчанию |
| Имя пакета выше `core` не встречается в production-коде | `GV2.Runtime.UIKit.PackageNameLiteralGate` |

Плюс два правила процесса в `AGENTS.md`: change set, меняющий проверку и проверяемый ею артефакт одновременно, обязан ответить, чем артефакт был неправ **до** появления проверки; и парное к нему требование называть источник вместо рукописного списка.

## Что показала работа

**Константа, подстроенная под инструмент.** `WrapSize=1200` появился одним change set с проверкой, которую он заставляет пройти, и оказался замером ширины панели на единственном разрешении, где та проверка работала строго. Причина лежала в harness: цикл по разрешениям не тикал, а динамический `SWrapBox` обновляет порог переноса только в `Tick()`. Продукт подстроили под возможности инструмента, компромисс ушёл в бинарный ассет и не был заявлен нигде. `DCA-13` починил инструмент, `DCA-15` — значение, `DCA-16` — правило, по которому такое видно в истории.

**Гейт, спроектированный по единственному известному экземпляру.** Первая формулировка `DCA-15` описывала перечислитель как обход ассетов. Сплошная проверка показала, что из пяти мест абсолютного размера в ассете авторски задано ровно одно — остальные четыре выставляются из C++ (`SetSize(800×400)` экрана восстановления, `SetMaxDesiredWidth/Height` popover и dropdown, толщина разделителя). Гейт по ассетам поймал бы одно место из пяти, то есть воспроизвёл бы форму своего единственного примера как определение класса. Задача была переписана на две обязательные половины до реализации.

**Гейт, случайно маскировавший свой собственный предмет.** При реализации `DCA-15` первая версия Half A классифицировала аргумент без единой цифры как «эффективно ноль», из-за чего голая ссылка на константу темы проходила как безопасная — ровно тот класс, который эта половина обязана ловить. Найдено демонстрацией: удаление исключения должно было уронить гейт и не уронило. Записано в отчёте задачи как найденный и исправленный дефект гейта, а не как деталь реализации.

**Проверка, множество которой оказалось пустым.** При закрытии проверки milestone `M2` утверждение «каждое схемно-обязательное свойство композита пришло» дало для сцены ноль проверенных свойств: `textsystem:schema.ui_field.location_scene.v1` объявляет `required: false` у всех полей верхнего уровня. Утверждение было бы зелёным и пустым. Добавлено второе — «композит получил хотя бы одно объявленное значение», — а сама дыра в контракте вынесена в [`STATUS-011`](../../Status/ImplementationStatus.md): обход живёт в тесте, расхождение остаётся в схеме.

**Отозванное решение вместо реализованного.** `DCA-20` не реализовал `ADR-0040` Decision 7, а отозвал её. Владелец схемы вычислялся закрытой тройкой литералов, копирующей `mods.lock.json5`, и результат (`Diag.bFatal`) не читал ни один production-путь — все вызывающие ветвились по общему признаку успеха, одинаковому для мода и первопартийной схемы. Реализация потребовала бы механизма «отклонить мод, продолжить сессию» с нуля, ради консьюмера, которого не существует (`ADR-0026`). Поверхность удалена, ADR помечен отозванным с условием, при котором решение может быть принято заново.

## Закрытые расхождения
