# M1 — Registry Integrity

> **Материализует:** [ADR-0031 § 2.2](../../../ADR/0031-entity-authoring-extensions.md) в части заморозки, композиции и разрешения конфликтов.
> **Задачи:** EEH-01…05.
> **Результат:** заморозку невозможно обойти, скомпонованная таблица участвует в разрешении метода, повторное объявление отклоняется всегда.

## Результат этапа

Три заявленные гарантии реестра начинают выполняться. Наблюдаемое поведение игры не меняется — меняется то, что о реестре можно утверждать.

## Задачи

- [x] **EEH-01 — Уточнить ADR-0031**
  - Done: ADR фиксирует, что скомпонованная `effective method table` является единственным путём разрешения метода; что фасад реестра не отдаёт наружу изменяемое внутреннее состояние; что повторное объявление метода внутри одного модуля отклоняется наравне с объявлением из разных модулей. Отдельно записывает отвергнутое: явный `override` для методов сущностей до появления потребителя и сохранение «последний побеждает» внутри модуля. Принят до первой отметки `[x]` ниже.
  - Evidence: `Docs/ADR/0031-entity-authoring-extensions.md`, `Docs/Architecture/LuaRuntimeContract.md`.

- [x] **EEH-02 — Закрыть утечку изменяемых записей через фасад**
  - Зависимости: EEH-01.
  - `__index` публичного фасада при промахе по имени функции возвращает `methods_by_kind[k]` — живую таблицу записей. `game.entity_extensions.Actor = {}` отклоняется, но `game.entity_extensions.Actor.<method>.fn = <другая функция>` проходит **после** заморозки и подменяет метод, потому что `get_method` читает `record.fn` при каждом вызове.
  - Done: через фасад невозможно получить ни изменяемую таблицу записей, ни саму запись; интроспекция остаётся доступной через `describe`, `kinds` и `get_effective_methods`, возвращающие копии либо замороженные представления; спека проверяет, что подмена `fn` после заморозки отклоняется, а не молча применяется.
  - Evidence: `Scripts/runtime/entity_extension_registry.lua`, `Tests/Lua/actors/entity_extension_registry.lua`.

- [x] **EEH-03 — Разрешение метода через скомпонованную таблицу**
  - Зависимости: EEH-02.
  - Композиция строится при заморозке, но `get_effective_methods` не вызывается нигде, кроме собственных спек: и `actor_registry.lua`, и `properties.lua` ищут метод через `get_method`, читающий записи напрямую. Гарантия неизменяемости к фактическому разрешению метода не применяется.
  - Done: разрешение метода экземпляра и определения идёт через скомпонованную таблицу; `get_method` либо снимается, либо реализуется поверх неё; до заморозки поведение прежнее, после — читается только замороженное представление; спека подтверждает, что после заморозки разрешение не обращается к внутренним записям.
  - Evidence: `Scripts/runtime/entity_extension_registry.lua`, `Scripts/runtime/actor_registry.lua`, `Scripts/authoring/properties.lua`.

- [x] **EEH-04 — Повторное объявление внутри модуля — ошибка**
  - Зависимости: EEH-01.
  - Сейчас совпадение `source_module` и `package_id` приводит к молчаливой замене `fn`. Две `function Actor:add_gold()` в одном файле проходят без сигнала. Соседняя авторская поверхность ведёт себя противоположно: в `commands` дубликат внутри модуля отклоняется `CommandAlreadyDefined`, и эта проверка появилась именно потому, что молчаливый дубликат прятал настоящий дефект.
  - Done: повторное объявление метода с тем же именем на том же `entity_kind` отклоняется независимо от источника; сообщение об ошибке различает случаи «тот же модуль» и «разные модули»; спека `idempotent_registration_same_module` заменена спекой на отказ; ни один существующий пакет не полагался на прежнее поведение.
  - Evidence: `Scripts/runtime/entity_extension_registry.lua`, `Tests/Lua/actors/entity_extension_registry.lua`.

- [x] **EEH-05 — Изоляция спек не протекает**
  - Зависимости: EEH-04.
  - `with_isolated_extensions` копирует записи по ссылке. Ветка повторной регистрации мутирует общую запись, и после восстановления внешний реестр остаётся с подменённой функцией.
  - Done: изоляция копирует записи по значению либо иным способом исключает мутацию внешнего состояния; после выхода из изоляции реестр совпадает с исходным, включая `fn` каждого метода; спека проверяет именно этот случай, а не только добавление нового метода.
  - Evidence: `Scripts/runtime/entity_extension_registry.lua`, `Tests/Lua/actors/entity_extension_registry.lua`.

## Проверка milestone

- [x] Подмена метода через фасад после заморозки отклоняется.
- [x] Разрешение метода после заморозки идёт через скомпонованную таблицу.
- [x] Повторное объявление внутри одного модуля отклоняется.
- [x] Повторная регистрация внутри изоляции не переживает выход из неё.
- [x] Набор методов, их семантика и коды отказов не изменились.
