# План реализации Content Authoring Tools

> **Архив.** План выполнен полностью (M1–M4) и больше не является источником задач. Нормативное поведение перенесено в [Build and Tooling](../../../Architecture/BuildAndTooling.md); инструкция по подключению редактора — в `Tools/Editor/README.md`. Документ сохраняется как implementation record.

## Цель

Сделать ручное создание контента ненужным там, где оно механическое, и дать автору обратную связь за секунды. План развивает CLI-часть [Content Diagnostics and Tooling Proposal](../../../Proposals/ContentDiagnosticsAndToolingProposal.md).

## Состояние на входе

`gv2-content` умеет `validate`, `inspect`, `hash` со стабильными кодами диагностик, спанами и JSON-выводом. Схемы самоописывающиеся и машинно-читаемые. Этого достаточно, чтобы проверить готовый файл, и недостаточно, чтобы его написать: автор не знает, какие поля бывают, вручную пишет конверт и узнаёт об опечатке в ID только после запуска.

Скрипты проверить нечем: чтобы узнать, загрузился ли модуль, нужно запустить весь прогон.

## Границы

Входят: генерация справочника и заготовок из схем, быстрая проверка module graph, обратные ссылки и переименование, живой цикл проверки, индекс ID для автодополнения в редакторе.

Не входят: GUI-редактор, импорт из таблиц, LSP-сервер, авторская документация для дизайнера — её структура обсуждается отдельно.

## Принятые ограничения

- **Автор работает в репозитории** текстовым редактором. Инструменты рассчитаны на этот сценарий и не предполагают отдельного приложения.
- **`gv2-content` не получает Lua VM.** Это записано в [Build and Tooling](../../../Architecture/BuildAndTooling.md) и остаётся так: проверка скриптов принадлежит `gv2-headless`, у которого VM уже есть.
- **Генераторы не создают второй источник истины.** `new` создаёт файл один раз и забывает о нём; `rename` переписывает существующие файлы на месте. Пайплайн генерируемых определений в план не входит.

## Milestones

- [x] M1 — [Schema Driven Authoring](SchemaDrivenAuthoring.md): справочник и заготовки из схем.
- [x] M2 — [Script Feedback](ScriptFeedback.md): проверка module graph без запуска геймплея.
- [x] M3 — [Rename Support](RenameSupport.md): обратные ссылки и переименование до заморозки ID.
- [x] M4 — [Live Loop](LiveLoop.md): непрерывная проверка и индекс для автодополнения.

## Критический путь

```text
Schema Driven Authoring
→ Script Feedback
→ Rename Support
→ Live Loop
```

Этапы слабо связаны и могут переупорядочиваться. Порядок отражает отношение пользы к стоимости: M1 и M2 опираются на уже готовые механизмы, M3 и M4 требуют новой машинерии.

## Общие правила выполнения

1. Инструмент читает те же схемы и тот же build path, что рантайм; вторая интерпретация схемы запрещена.
2. Вывод инструмента machine-readable и не содержит абсолютных путей.
3. Инструмент не публикует repository и не меняет содержимое `GameData` без явного запроса пользователя.
4. Новая команда описывается в `BuildAndTooling` в том же change set.

## Итоговый Definition of Done

- [x] Автор узнаёт доступные поля вида сущности, не открывая схему.
- [x] Валидная заготовка создаётся командой, а не копированием.
- [x] Ошибка в Lua-модуле обнаруживается за секунды и без запуска геймплея.
- [x] Переименование ID выполняется инструментом, а не поиском по репозиторию.
- [x] Редактор подсказывает существующие ID.
