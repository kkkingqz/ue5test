# План выделения слоя TextSystem

> **Материализует:** [TextSystem Layer](../../../Proposals/Archive/TextSystemLayerProposal.md).
> **Задачи:** TSL-01…20.
> **Результат:** три слоя вместо двух; локация и переход принадлежат `textsystem`, стоимость перехода — игре.

## Цель

Выделить между движком и игрой переиспользуемую основу текстовой игры: локации, переходы, презентацию экрана локации.

И, что важнее для всего дальнейшего, — **сделать пакет подключаемым из данных**. Сегодня набор пакетов зашит по именам в обоих хостах, поэтому добавление слоя является изменением движка.

## Состояние на входе

Проверено по коду.

| Что | Сейчас |
|---|---|
| Набор пакетов | Зашит по именам: `core`, затем `rh`, в `Headless/Source/main.cpp` и `GV2RuntimeSubsystem.cpp` |
| Контейнерный режим `gv2-content` | Отсутствует: `validate GameData` даёт `package.json5 package root has no package.json5` |
| Трёхзвенная цепочка пакетов | Работает при явном перечислении корней — проверено на временном дереве |
| Автообнаружение модулей | Реализовано; новый пакет подхватывается генератором без правок |
| Источник презентации | Реализован; `location_screen.lua` уже зарегистрирован источником |
| Владение локацией | `rh/scripts/gameplay/actors.lua`: `current_location`, `require_location`, `travel`, `is_connected` |
| Переход в ядре | `core:command.location.travel`, `core:service.location`, `Scripts/gameplay/location_service.lua`, `Scripts/gameplay/root.lua` |
| Разбиение спеков | Бинарное: фикстурная сессия только для `Tests/Lua/commands` |
| Kind `action` | В реестре kind отсутствует |
| Квесты | Секция `state.quests` объявлена, потребителей нет |

## Принятые решения

Зафиксированы в [предложении](../../../Proposals/Archive/TextSystemLayerProposal.md), выносятся в ADR первой задачей.

- **Три уровня и критерий выбора.** Нужна любой игре — `core`; любой текстовой, но не любой — `textsystem`; выражает правила конкретной игры — `rh`.
- **Это осознанное исключение из [ADR-0026](../../../ADR/0026-core-and-gameplay-ownership.md).** Второй текстовой игры нет, а правило требует доказанной применимости. Основание — цена момента: разделять систему из двухсот строк дешевле, чем из двух тысяч. ADR обязан сформулировать это именно так, а не как доказанную применимость.
- **Набор пакетов собирается из данных.** Хосты и CLI перестают знать имена пакетов.
- **Стоимость перехода принадлежит игре.** `textsystem` знает, что переход возможен; `rh` — чего он стоит.
- **Расширение существующими механизмами.** Схемные расширения, декораторы экземпляров и определений, managed-операции; отдельной иерархии классов Lua не вводится.

## Границы

Входят: набор пакетов из данных, пакет `textsystem`, перенос владения локацией и переходом, презентер и декларативные экраны, трёхуровневое разбиение спеков, чистка `rh/actors.lua`.

Не входят:

- **Quest foundation.** Подсистемы не существует, потребителей нет; создание её сейчас было бы ровно той speculative generality, против которой написан ADR-0026. Появится вместе с первым квестом.
- **Inventory как подсистема `textsystem`.** `add_item` остаётся в `rh`.
- Наследование классов Lua, изменение грамматики Stable ID, перенос авторитета геймплея в UE.
- Пересборка замороженного корпуса: он изображает пакет по имени `core`, а не движок, и под правило не подпадает.

## Критический путь

```text
M1 ─┬─► M2 ─┬─► M3
    │       └─► M5
    └─► M4
```

**M1 обязателен для всего остального.** Пока набор пакетов зашит в C++, третий слой существовать не может.

M1 завершается зелёным при **пустом** `textsystem`: если трёхзвенный набор работает до переноса, любая поломка в M2 однозначно относится к переносу, а не к загрузке.

## Общие правила выполнения

1. Ни одна задача не добавляет знания об именах пакетов в C++. Появление такого знания — дефект, а не удобство.
2. `textsystem` не содержит данных `rh`: ни рынка, ни таверны, ни меча, ни стоимости перехода.
3. Правила, выразимые в Lua, проверяются спеками ([ADR-0024](../../../ADR/0024-lua-spec-runner.md)).
4. Замороженный корпус `Tests/Fixtures/PortableContentCore/` не перестраивается.
5. Изменение `script_set_hash` в golden ожидаемо и обновляется воспроизведением манифеста; изменение `repository_content_hash` — признак ошибки, кроме задач, сознательно меняющих контент.
6. Новое observable behavior синхронно отражается в contract.

- [x] Локация, переход и презентер работают в пакете-образце без `rh`.
- [x] `textsystem` не содержит данных `rh`.
- [x] `rh/actors.lua` не содержит кода локации; золото и выносливость не являются двумя копиями одного кода.
- [x] `rh/scripts/presentation/location_screen.lua` удалён.
- [x] Спеки уровня Core проходят без `textsystem` и `rh`; спеки TextSystem — без `rh`.
- [x] В геймплейном коде граница слоёв не видна.

Три уточнения по итогам приёмки.

**Данные игры внутри `textsystem`.** Презентер локации содержал запасной идентификатор `"rh:screen.location.market"` — локация без экрана молча получала бы экран `rh`. Заменено отказом: отсутствие экрана у локации является ошибкой контента, а не поводом подставить чужой.

**Дубликат команды не ловился.** Проверка повторного объявления ключевалась по сырому ключу, а `commands.travel` и `commands["rh:command.travel"]` дают один и тот же `command_id`. Обе формы проходили, и вторая молча перекрывала первую. Проверка переведена на канонический ID и сразу нашла второй экземпляр той же избыточности — в пакете `sample`.

**Скрипты ядра лежат вне его пакета.** `GameData/core/` не содержит `scripts/`: модули ядра живут в `Scripts/` в корне репозитория. Поэтому `core` остаётся не вполне обычным пакетом, и каждый обходчик скриптов содержит для него отдельную ветку. На результат этого плана не влияет, но границу «пакет подключается из данных» замыкает не полностью.
