# GenericBoundaryHardening: итог выполнения

> **Материализует:** исторический итог выполненного плана; документ не является источником правил или задач.

## Цель и результат

**Цель:** закрыть семь находок [внешнего ревью от 2026-09-01](../../Status/Archive/GV2RemainingReview2026-09-01.md) (`REM-01`…`REM-07`), сместившихся после `PipelineClosureCorrection`/`DataDrivenUiComposition` из schema-specific адаптеров в границы generic-абстракций: объявленная capability → реальная capability ребёнка, подготовленная мутация → транзакционный commit живого виджета, схемы на файловой системе → авторитет репозитория.

**Результат:** объявление композита несёт параметры своего вида (диапазон числа/целого, `target_kind`, для коллекции — класс элемента и ключевое свойство) и явно указывает, какую именно capability ребёнка делегирует; сверка объявления с ребёнком и schema→Widget используют одну общую subset-функцию, сравнивающую capability целиком, а не только вид; каждый выбираемый в Designer вид работоспособен от объявления до отрисовки, а `CollectionHost` возвращается в public surface только после E2E-доказательства; структурная непригодность Shell предсказывается в Prepare; mid-Commit failure на переиспользуемом живом host/screen/collection восстанавливает предыдущую физическую presentation через единый rollback-механизм ([ADR-0041](../../ADR/0041-ui-commit-rollback-model.md)), а не оставляет частично применённую ревизию; принадлежность UI-схем репозиторию честно зафиксирована как отложенная (`STATUS-008`); контракты описывают фактический `IGV2ScreenFieldHost`; legacy optional-apply API удалены.

## Этапы и задачи

### M1 — Declared Surface

Объявляемая поверхность не рекламирует неработоспособные kinds; Shell structural failure предсказывается до мутации; authority/docs debt имеет явного владельца.

- `GBH-01` — Структурная непригодность Shell предсказывается в Prepare
- `GBH-02` — Каждый selectable вид Designer работоспособен целиком (часть A — до M2, скрывает `CollectionHost`; часть B — после M2, возвращает его с полным contract)
- `GBH-03` — Судьба принадлежности UI-схем репозиторию решена (defer, `STATUS-008`)
- `GBH-04` — Контракты описывают фактический host API
- `GBH-05` — Параллельные optional-пути применения удалены

### M2 — Declaration Constraints

Объявление несёт свои ограничения, указывает конкретную child capability и сверяется с ней общей subset-функцией.

- `GBH-06` — Объявление несёт параметры своего вида
- `GBH-07` — Consumer применяет объявленное ограничение
- `GBH-08` — Сверка сравнивает capability целиком

### M3 — Transactional Commit

Mid-Commit failure на переиспользуемом live UI восстанавливает предыдущую committed presentation; partial physical revision не допускается как нормальное состояние.

- `GBH-09` — Решение о механизме восстановления ([ADR-0041](../../ADR/0041-ui-commit-rollback-model.md))
- `GBH-10` — Реализация выбранного механизма на всех шести обнаруженных границах
- `GBH-11` — Инъекция в опасную точку и сверка закрытий

## Что дала сверка закрытий REM-02

`GBH-11` (сверка закрытий, симметричная `PCC-12` предыдущего плана) нашла тот же класс разрыва, что и предыдущий раунд: единственный существовавший regression test для атомарности Commit (`PCC-07`) проверял более узкое свойство, чем заявлял. `PCC-07` инъектирует отказ на экране, который **заменяется** новым widget instance (V1→V2) — target ещё off-tree до успешного коммита всего документа, поэтому mid-Commit failure там всегда была безопасна. Реально опасная точка — mid-Commit failure на уже **живом переиспользуемом** экземпляре — не была протестирована ни разу, хотя именно её описывает `REM-02` буквально. Новый danger-point test (`GBH-11`, Step K) подтверждён red-on-revert независимо от `PCC-07`, который остаётся зелёным на том же откате — разница между двумя классами failure стала наблюдаемой, а не предполагаемой.

Закрытие `GBH-10` попутно нашло собственный реальный дефект той же формы: ни один код никогда не вызывал `SetLastCommittedProperties` для элемента keyed collection — `LastCommittedProperties` отслеживался только на уровне Screen Field host. Без этого `RollbackPlan` элемента строился бы против пустого объекта (all-Reset, а не настоящее восстановление). Найдено и исправлено в том же change set, что и основной механизм — не оставлено как отдельный будущий task.

`GBH-08` тоже нашла независимый реальный баг при подключении своей subset-функции: `ResolveDelegatedChildCapability(ChildBuilder.Build(), ...)` передавал временный `FGV2UiCapabilityTree` напрямую, и резолвленный указатель указывал внутрь уже разрушенной temporary — latent use-after-free, не обнаруженный раньше, потому что ничто не разыменовывало указатель после возврата до собственного subset-check `GBH-08`.

## Принятые по ходу решения

- **`REM-02` решается ADR, а не документационной капитуляцией.** [`ADR-0041`](../../ADR/0041-ui-commit-rollback-model.md) выбрал единый принцип «захват предыдущего состояния перед live-мутацией, откат в обратном порядке той же обычной Prepare/Commit-машиной» — не bespoke undo-код, а replay уже существующего `LastCommittedProperties` — применяемый рекурсивно на всех шести обнаруженных границах (property, host/screen, документ, Shell attach, keyed collection item, nested screen в табе). Отклонены: shadow/staged дерево со свопом (несовместимо с сохранением UI-local widget state при переиспользовании), «Commit не может отказать после первой мутации» как самостоятельная замена (конъюнкция условий плана не делает его дешевле), сужение контракта до допустимого partial state (запрещено явно).
- **Объявление обязано нести параметры своего вида, а не schema.** Форма schema для автора контента не меняется; обогащается объявление в Designer — диапазон для числа, класс элемента и ключевое свойство для коллекции. Тройка `(имя, ребёнок, вид)` оказалась недостаточной для видов со структурой, и `REM-01`/`REM-05` — два следствия одного упрощения.
- **Одна функция subset-совместимости общая для обеих границ.** Схема→Widget и DeclaredComposite→child не реализуют «те же правила» двумя копиями (`IsUiCapabilitySubset`, `GBH-08`) — mutation test подтвердил единственность реализации, уронив обе стороны одновременно при временном отключении.
- **`REM-04` осталась осознанно отложенной.** Условие триггера (мод поставляет `ui_field`/`ui_value` схему) не наступило; `STATUS-008` зафиксирован во всей нормативной цепочке (`ImplementationStatus.md`, оба UI-контракта, ADR-0040), а не только в одной строке статуса.
- **Инъекция отказа ставится в опасную точку, а не в удобную.** Явное требование `GBH-11`, выведенное из того, что `PCC-07` не нашло `REM-02` именно потому, что стояло на уровне замены экрана, а не middle of commit переиспользуемого экземпляра.

## Проверка

Полный регрессионный прогон на итоговом коммите: **105/105** UE Automation (`GV2.*`, headless `-nullrhi`, подтверждено через `Saved/Logs/GV2.log`, не только stdout), **68/68** портативных CTest, `validate_docs.py` (168 файлов) и его `--self-test` — без ошибок.

Каждая задача с кодовым изменением продемонстрировала red-on-revert отдельно (временное отключение проверки/механизма красит именно и только относящийся к ней тест); `GBH-03` и часть `GBH-08`/`GBH-11` использовали docs/status consistency gate там, где искусственный runtime test не доказывал бы ничего сверх самого факта отсутствия кода.
