# CommandValidators: итог выполнения

> **Состояние:** план выполнен; документ является историческим summary, а не источником правил или задач.

## Цель и результат

**Цель:** Дать авторскому слою `validate(command_ref, name, fn)` — независимую read-only policy поверх существующей команды. Механизм нужен там, где проверку добавляет не владелец команды: другой пакет, слой или мод

**Результат:** пакет может независимо ограничить чужую команду, не владея её реализацией; ядро перестаёт знать имена игровых параметров; замена обработчика становится явной

## Этапы и задачи

### M1 — Argument Decoding

ядро не знает имён игровых параметров; декодирование существует в одном экземпляре и готово к переиспользованию валидатором

- `CVA-01` — Создать ADR по авторским валидаторам
- `CVA-02` — Убрать имена игровых параметров из ядра
- `CVA-03` — Единственное декодирование аргументов

### M2 — Validator Authoring

пакет объявляет policy для чужой команды одной строкой; отказ атрибутируется объявившему пакету

- `CVA-04` — Общий execution scope
- `CVA-05` — `fail()` в scope валидатора
- `CVA-06` — API `validate` и идентичность
- `CVA-07` — Разрешение target на заморозке
- `CVA-08` — Адаптер к существующему реестру

### M3 — Side Effect Guards

валидатор не может произвести наблюдаемый эффект, и это проверено на отказ в каждой точке

- `CVA-09` — Охранники в четырёх точках
- `CVA-10` — Спека на отказ в каждой точке
- `CVA-11` — Область действия и порядок относительно поиска обработчика

### M4 — Handler Replacement

замена обработчика перестаёт быть молчаливой; политики чужих пакетов переживают её осознанно

- `CVA-12` — Явная заменяемость команды
- `CVA-13` — Сквозная верификация
