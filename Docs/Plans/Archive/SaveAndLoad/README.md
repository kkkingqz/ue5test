# План реализации Save and Load

> **Материализует:** [Canonical State and Save](../../../Architecture/CanonicalStateAndSave.md) в рамках [ADR-0021](../../../ADR/0021-opaque-save-container.md).
> **Задачи:** SAV-01…21.
> **Результат:** состояние сохраняется в непрозрачный контейнер и восстанавливается из него без потерь.

## Цель

Закрыть последний недостающий элемент vertical slice: состояние сохраняется в непрозрачный контейнер и восстанавливается из него так, что канонический хэш состояния совпадает до и после.

План материализует [Canonical State and Save](../../../Architecture/CanonicalStateAndSave.md) в рамках [ADR-0021](../../../ADR/0021-opaque-save-container.md): сериализация, integrity check и миграции принадлежат Lua, host предоставляет только slot-scoped byte storage.

## Состояние на входе

Canonical state, instance identity, mutation window, command path с валидаторами, EventBus и фазы `Idle`/`ExecutingCommand`/`PumpingEvents` реализованы.

Сохранения нет ни в каком виде: slot-storage примитива у host-а не существует, фаза `Saving` не выставляется, хуки `migrate_state` и `restore_instances` объявлены контрактом и никогда не вызывались.

Существенная часть работы уже сделана в другом месте: `state_hasher.M.serialize` даёт полностью обратимую каноническую кодировку — каждый тип имеет тег, строки и ключи снабжены длиной, контейнеры счётчиком. Формат контейнера проектировать не нужно, а integrity check совпадает с уже вычисляемым `state_hash`.

## Принятые решения

- **Кодек — существующий канонический энкодер.** Он выносится из `state_hasher` в отдельный модуль и дополняется обратной операцией; хэшер становится его потребителем. Следствие, которое обязано быть записано в контракт: изменение кодировки ломает совместимость сейвов, поэтому кодек версионируется, а любое его изменение требует поднятия `save_version`.
- **Изменение данных не влияет на загрузку.** `repository_content_hash` записывается в контейнер как provenance и не является условием загрузки. Ошибкой является отсутствие Stable ID, на который ссылается сейв, а не изменение данных за этим ID.
- **Отсутствие ID — всегда ошибка.** Per-field recovery policy в v1 не вводится; формулировка контракта приводится в соответствие. Политика восстановления появится позже, под конкретный случай и отдельным решением.
- **Редиректы разрешаются и переписываются.** Переименованный через redirect ID грузится, а состояние переписывается на final canonical target, как требует `StableIDSpecification`. Иначе redirect-таблицу невозможно ретировать никогда.
- **Загрузка только на холодном старте.** Приложение стартует в режиме `LoadSave` вместо `NewGame`; replacement session не вводится.

## Границы

Входят: канонический кодек с обратной операцией, slot-storage примитив в обоих host-ах, конверт контейнера, фаза `Saving` и safe point, загрузка на холодном старте, резолв редиректов, реестр reference-полей, миграции.

Не входят: replacement session и загрузка во время игры; orphan-секции отсутствующих модов; `game.random` и `game.time`; внешний инспектор сейвов; сжатие и бинарная упаковка контейнера.

Честная оговорка: без replacement session пункт меню «загрузить другое сохранение» работать не будет. Это отдельная работа вместе с переходами Menu↔Game.

## Критический путь

```text
Canonical Codec
→ Save Path
→ Cold Start Load
→ Migrations

Slot Storage
→ Save Path
```

M1 и M2 независимы и могут идти параллельно; оба нужны M3.

## Общие правила выполнения

1. Canonical state не пересекает C++/Lua boundary: host получает и отдаёт только байты и скаляры.
2. Единственный C++ в плане — slot-storage примитив; он проходит критерий ADR-0020 по условию «требует файловой системы». Всё остальное принадлежит Lua.
3. Проверки пишутся Lua-спеками в `Tests/Lua/save/`; C++ conformance допустим только для самого примитива.
4. Изменение канонической кодировки требует поднятия `save_version` и осознанного обновления golden-прогонов.
5. Каждая задача добавляет negative case, если меняет failure semantics.
6. Новое observable behavior синхронно отражается в contract.

## Итоговый Definition of Done

- [x] `state_hash` до сохранения и после загрузки совпадает в обоих host-ах.
- [x] Изменение данных за существующим Stable ID не мешает загрузке.
- [x] Отсутствие Stable ID даёт типизированную ошибку, различающую retired и unknown.
- [x] Переименованный через redirect ID грузится, а состояние переписывается на канонический target.
- [x] Отказ записи оставляет предыдущий слот валидным.
- [x] Миграция выполняется детерминированно и не меняет исходный слот при провале.
