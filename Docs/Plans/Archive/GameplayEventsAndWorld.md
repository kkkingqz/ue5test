# GameplayEventsAndWorld: итог выполнения

> **Состояние:** план выполнен; документ является историческим summary, а не источником правил или задач.

## Цель и результат

**Цель:** Замкнуть command path: validators до мутации, факты после commit, подписка на факты и первый доменный объект мира. План материализует Commands and Events; новых архитектурных решений он не вводит и ADR не требует

**Результат:** Замкнуть command path: validators до мутации, факты после commit, подписка на факты и первый доменный объект мира. План материализует Commands and Events; новых архитектурных решений он не вводит и ADR не требует

## Этапы и задачи

### M1 — Command Validators

Между приёмом команды и вызовом handler появляется ordered read-only проверка. Отказ валидатора является нормальным результатом, а не сбоем, и гарантированно не оставляет следов в state

- `GEW-01` — Реестр валидаторов и порядок
- `GEW-02` — Ограничить права валидатора
- `GEW-03` — Зафиксировать семантику отказа

### M2 — World Domain Object

Над секцией `state.world` появляется доменный объект по той же модели, что Actor: disposable wrapper без второй копии данных. Мир получает первое реальное содержимое — текущую локацию

- `GEW-04` — Реализовать World wrapper
- `GEW-05` — Ввести текущую локацию

### M3 — Event Bus Core

Gameplay публикует неотменяемые факты после успешного commit. Доставка детерминирована, ограничена и не может изменить state

- `GEW-06` — Определить конверт события
- `GEW-07` — Публиковать только после commit
- `GEW-08` — Обеспечить детерминированную доставку
- `GEW-09` — Ввести фазы и лимит pump

### M4 — Subscription and Reaction

Модуль подписывается на факт по `event_id` и реагирует на него. Условие срабатывания проверяется в самом обработчике: декларативных фильтров и предикатного языка не вводится

- `GEW-10` — Реализовать подписку по `event_id`
- `GEW-11` — Ограничить права обработчика
- `GEW-12` — Зафиксировать поведение отложенной команды

### M5 — Travel Slice

Сценарий проходит целиком в обоих host-ах: игрок отправляет команду перемещения, валидатор проверяет допустимость, handler меняет текущую локацию через сервис, мир публикует факты выхода и входа, подписчик на них реагирует

- `GEW-13` — Реализовать команду перемещения
- `GEW-14` — Опубликовать факты перехода
- `GEW-15` — Подтвердить сценарий в обоих host-ах
- `GEW-16` — Синхронизировать документацию
