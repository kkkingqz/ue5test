# M3 — Presenter and Data

> **Материализует:** разделы 13 и 14 [предложения](../../Proposals/GameplayLocationScreenProposal.md).
> **Задачи:** GLS-10…13.
> **Результат:** значения экрана собираются из определения локации и текущего состояния; игра участвует только данными.

## Результат этапа

Презентер `textsystem` объединяет два источника в поля документа. Игра не пишет полей напрямую и не знает о композитах.

## Задачи

- [ ] **GLS-10 — Расширение схемы определения экрана**
  - Зависимости: GLS-03.
  - Существующая схема определения экрана не содержит ни фона, ни персонажа. Добавлять их в схему `core` неверно: фон сцены и персонаж — понятия текстовой RPG, а не механизм движка ([INV-016](../../Architecture/Invariants.md)).
  - Done: `textsystem` объявляет расширение схемы определения экрана через существующий механизм extension site — тем же способом, которым `textsystem` и `rh` уже расширяют определение актора; расширение добавляет ресурс фона и персонажа сцены; схема `core` не меняется; гейт границы проходит.
  - Evidence: `GameData/textsystem/schemas/`, `Docs/Architecture/DefinitionEnvelopeAndSchemaRules.md`.

- [ ] **GLS-11 — Презентер: два источника значений**
  - Зависимости: GLS-10, GLS-01.
  - Done: презентер собирает поля экрана из определения экрана, выбранного через `screen_ids` локации, и из текущего канонического состояния; из определения берутся заголовок, описание, фон, персонаж и набор действий, из состояния — день, ресурсы, имя локации, портрет, показатели, предметы, эффекты и доступность команд; переходы к соседним локациям продолжают строиться из связей локации; презентер не обращается к идентификаторам `rh`.
  - Evidence: `GameData/textsystem/scripts/presentation/`, `Tests/Lua/presentation/`.

- [ ] **GLS-12 — Данные `rh`**
  - Зависимости: GLS-11.
  - Done: три определения экрана `rh` дополнены ресурсом фона и персонажем сцены; заведены изображения фона для трёх локаций и персонажа для таверны; портрет игрока и иконки предметов подключены; ни одно из этих значений не появляется в `textsystem` или `core`; `repository_content_hash` меняется осознанно и однократно.
  - Evidence: `GameData/rh/definitions/`, `Resources/rh/`.

- [ ] **GLS-13 — Ресурсы-заглушки**
  - Зависимости: GLS-04, GLS-12.
  - Done: заведены заглушки для фоновой иллюстрации, изображения персонажа, портрета и иконки; заглушка соответствует режиму отрисовки замещаемого ресурса; при отсутствии правильного ресурса показывается заглушка, слой не исчезает и экран остаётся пригодным; подстановка попадает в диагностику; заглушки принадлежат тому слою, который отвечает за соответствующий элемент.
  - Evidence: `Resources/`, `Source/GV2/Private/UI/`.

## Проверка milestone

- [ ] Схема `core` не изменена; фон и персонаж добавлены расширением `textsystem`.
- [ ] Презентер не содержит идентификаторов `rh`.
- [ ] Значения из определения и из состояния объединяются в одном документе.
- [ ] Отсутствие любого изображения даёт заглушку, а не пустое место.
