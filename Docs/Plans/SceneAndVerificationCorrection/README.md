# План исправления сцены и верификации

> **Материализует:** findings проверки планов — [Plan Audit Findings](../../Status/AuditFindings.md), части, требующие изменений через границы слоёв.
> **Задачи:** SVC-01…12.
> **Результат:** персонаж сцены доходит от контента до экрана, проверки измеряют заявленные величины, а не удобные, и вакуумных тестов в наборе не остаётся.

## Цель

Устранить findings, затрагивающие **несколько слоёв сразу** или требующие построения средства измерения там, где его нет.

Это отделено от [второго плана](../Archive/ToolingAndWidgetHygiene.md) не по важности, а по характеру работы: здесь почти каждая задача пересекает границу Lua → C++ → ассет либо требует понимания раскладки Slate.

## Состояние на входе

| Что | Сейчас |
|---|---|
| Персонаж сцены | Презентер шлёт `character_resource_ids` (массив строк), адаптер читает `characters` (массив объектов); данные теряются молча |
| Хост репитера персонажей | `CharacterRepeater` и `CharacterContainer` в `WBP_SceneView` не привязаны |
| Слот персонажа | `HAlign_Fill`, `VAlign_Fill` — привязки к нижнему краю нет |
| Контракт поля сцены | Персонажей не упоминает вовсе |
| Матрица разрешений | Читает `GetDesiredSize()` после `SlatePrepass`; `ArrangeChildren` не вызывается |
| Тест перехода `LocationTransitionFlow` | Перехода не выполняет; два чтения одного аксессора |
| Handle неактивной вкладки | Создаётся для всех вкладок; путь `Submit` о вкладках не знает |
| Аварийные экраны | `core:screen.error`, `.loading`, `.recovery` не существуют |
| Откат композита | Реализован в `ApplyScreenFields`, тестом не покрыт |
| Дерево браузера | Разбирает Stable ID вручную вместо `FStableId` |

## Принятые решения

- **Персонаж чинится в строгом порядке.** Сначала контракт, затем ассет, затем граница. Обратный порядок ломает экран целиком: как только имена совпадут, `CanApplyScreenField` начнёт отклонять модель сцены, потому что хост репитера не привязан.
- **Вакуумные тесты снимаются, а не дополняются.** Тест, который выглядит покрытием и им не является, вреднее отсутствия теста.
- **Утверждение без средства измерения либо получает средство, либо снимается.** Третьего варианта — оставить неподтверждаемым — нет.

## Границы

Не входят: рефакторинг `FGV2ScreenFieldValue` в размеченное объединение и композиция источников презентации. По обоим принимается решение (SVC-11), реализация планируется отдельно по его итогам.

```text
SVC-01 ──► SVC-02 ──► SVC-03 ──► SVC-04        (строгий порядок)

```

## Общие правила выполнения

1. Порядок задач M1 не меняется: контракт, ассет, граница, тест.
2. Ассеты меняются только через `unreal-mcp`, с последующими compile, save и прогоном automation.
3. Ни одна задача не редактирует файлы, закреплённые за [ToolingAndWidgetHygiene](../Archive/ToolingAndWidgetHygiene.md): `Tools/`, корневой `CMakeLists.txt`, `GV2DropdownSelectWidgetBase.*`, `GameData/sample/`, новые файлы тестов типографики.
4. Правки в `GV2RuntimeSubsystemTests.cpp` принадлежат только этому плану.
5. Каждое исправленное утверждение получает проверку на **отрицательный** случай.
6. Закрытый finding снимается из [AuditFindings](../../Status/AuditFindings.md) тем же change set.
