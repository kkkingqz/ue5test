# M2 — Authority

> **Материализует:** `PKG-R1` и вторую половину `PKG-R2`.
> **Задачи:** PAH-04…05.
> **Результат:** контентный факт выводится один раз и живёт ровно столько, сколько сессия.

## Результат этапа

Это главный этап плана. Сегодня один и тот же факт выводится независимо в четырёх местах, и **пока их четыре, перечислитель невозможен**: у любой проверки есть сторона, которую она не видит, потому что та выводится из другого источника.

| Потребитель | Как выводит сегодня | После этапа |
|---|---|---|
| Порядок пакетов | второй вызов обнаружения по `mods.lock.json5` | снимок |
| Корни схем | `DiscoverDefaultSchemaPackageRoots()` в `static` | снимок |
| Владение ассетами | четыре зашитые пары | метаданные пакета через снимок |
| Разрешение экрана | DataAsset плюс проекция | снимок (`PAH-02` уже убрал прямой доступ) |

Порядок внутри этапа существенный: `PAH-04` создаёт снимок и переводит на него схемы — самый острый случай, потому что кэш переживает сессию; `PAH-05` добавляет к снимку владение ассетами и удаляет таблицу, которую `PAH-03` до этого сделал безопасной, но не убрал.

## Задачи

- [ ] **PAH-04 — Снимок контента сессии, и схемы внутри него**
  - Зависимости: PAH-02.
  - `GetSchemaCache()` (`GV2ScreenFieldMaterializer.cpp:27`) содержит функционально-локальный `static FGV2UiSchemaCache Cache(DiscoverDefaultSchemaPackageRoots())` — синглтон времени жизни процесса, построенный один раз при первом обращении. Он не привязан ни к какой сессии, переживает её перезапуск, и корни в нём захвачены на момент первого вызова, а не на момент пиннинга.
  - Инвариант: активная сессия использует пиннингованный неизменяемый снимок репозитория, а перезагрузка применяется через контролируемый рестарт ([ADR-0006](../../ADR/0006-repository-reload-and-session-pinning.md)); каждое решение презентации выводится из одного снимка ([ADR-0042](../../ADR/0042-presentation-authority-and-publication.md), `INV-P1`, `INV-P2`). Нарушение здесь не «два набора могут разойтись»: расхождение при рестарте с другим набором пакетов **гарантировано**, потому что кэш не перестраивается вовсе. Случай `EditorPackageRoots` — не гипотетический сценарий, а штатный режим редактора.
  - Не считается закрытием: сброс кэша при старте сессии — это чинит момент построения и оставляет второй авторитет; **session-scoped кэш, сохранивший ленивое чтение файлов** — окно расхождения сужается, но `PKG-R1` остаётся открытым; сверка двух наборов корней на равенство — совпадение значений не делает авторитет одним; перенос того же `static` в другой файл.
  - Done:
    - снимком владеет координатор сессии, а репозиторий является одним из его пиннингованных компонентов (`0A` предложения); UE-типы в `GV2ContentCore` не попадают;
    - снимок **агрегирует** авторитеты и не дублирует определения и провенанс репозитория (`0B`): копия того же факта внутри снимка — такая же множественность, как копия снаружи;
    - обнаружение, чтение, разбор, компиляция и заморозка схем происходят **до** `Ready`; после `Ready` разрешение идёт только из захваченной памяти (`0C`);
    - ленивая компиляция допустима только из уже захваченных in-memory документов; повторного чтения файлов после `Ready` нет ни одного;
    - снимок строится из точного разрешённого набора пакетов этой сессии, а не повторным вызовом канонического обнаружения по `mods.lock.json5`;
    - время жизни снимка равно времени жизни сессии; объектов схем, переживающих сессию, не существует;
    - замена сессии строит новый кандидат-снимок, полностью валидирует его и заменяет прежний атомарно; частично построенный снимок не наблюдаем;
    - разрешение схемы по `schema_id` обращается только к снимку;
    - `DiscoverDefaultSchemaPackageRoots` и функционально-локальный `static` удалены;
    - сессия, поднятая со вторым набором корней, видит схемы этого набора, а не первого — проверено двумя последовательными сессиями в одном процессе;
    - существует гейт `INV-P1`: презентационный код после `Ready` не вызывает обнаружения контента; множество вызовов берётся сканированием по грамматике вызовов обнаружения и чтения файловой системы, у гейта есть отрицательный самотест;
    - порядок пакетов и разрешение экрана переведены на снимок в этой же задаче либо явно оставлены `PAH-05` с записанной причиной.
  - Evidence: `Source/GV2/Private/Application/GV2ScreenFieldMaterializer.cpp`, `Source/GV2/Private/UI/GV2UiSchemaCache.*`, `Source/GV2/Private/Application/GV2SessionCoordinator.*`, `Docs/Architecture/BootstrapAndSessionLifecycle.md`, новый гейт.

- [ ] **PAH-05 — Пакет владеет своими UE-корнями**
  - Зависимости: PAH-03, PAH-04.
  - После `PAH-03` неизвестный корень отклоняется, но таблица из четырёх пар остаётся, и добавление пакета по-прежнему требует правки C++. Будущий пакет с ассетами под собственным корнем не будет понят.
  - Инвариант: состав и порядок пакетов принадлежат данным замыкания, а не коду ([ADR-0042](../../ADR/0042-presentation-authority-and-publication.md), `INV-P2`). Нарушение здесь расширяемостное, а не корректностное: правило сегодня верно для трёх пакетов, которые есть, и не имеет способа стать верным для четвёртого.
  - Не считается закрытием: генерация той же таблицы из данных в C++-константу на этапе сборки; вывод корня из имени пакета по соглашению — соглашение об именовании и есть та же зашитая таблица, только неявная.
  - Done:
    - метаданные пакета объявляют его UE-корни контента данными, отдельной секцией `package.json5`, которую портативный хост игнорирует (`0F`);
    - корни нормализуются перед сравнением;
    - два активных пакета не могут владеть одним корнем; пересечение корней **запрещено**, а не разрешается правилом longest-prefix;
    - «путь ассета → ровно один пакет» является инвариантом построения снимка, и его нарушение отклоняет построение, а не разрешается в пользу первого совпадения;
    - доверенный внешний домен объявлен один раз и назван; корень проекта, не попавший ни в пакет, ни в домен, отклоняется;
    - отображение «путь ассета → пакет-владелец» строится снимком из этих данных;
    - таблица `ContentRootOwners` в C++ удалена;
    - синтетический четвёртый пакет со своим корнем понимается без единой правки `Source/` — показано в тесте;
    - `GameData` существующих трёх пакетов приведён, и `mods.lock.json5` перегенерирован по правилам проекта.
  - Evidence: `GameData/*/package.json5`, `GameData/mods.lock.json5`, `Source/GV2/Private/UI/GV2ScreenRegistry.cpp`, `Docs/Architecture/`, `Source/GV2/Private/Tests/`.

## Проверка milestone

- [ ] Ни один контентный факт не выводится в двух местах независимо.
- [ ] Объектов, переживающих сессию и хранящих контент, не существует.
- [ ] Презентация не выполняет обнаружения после `Ready`, и это утверждает перечислитель с отрицательным самотестом.
- [ ] Добавление пакета не требует правки `Source/`, и это показано синтетическим пакетом.
