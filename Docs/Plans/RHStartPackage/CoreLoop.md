# Основной цикл

> **Материализует:** этап M1 [плана](README.md): меню локации с доступностью, панели статуса, конец хода с фазами, уникальные и сгенерированные NPC.

## RSP-06 — Меню локации с доступностью

- [ ] RSP-06 — Меню локации с доступностью

**Файлы:** `scripts/authoring/rules/menu.lua`; удаление статичных списков взаимодействий из Definitions экранов; `Docs/RH/GameplayArchitecture.md` § 7.

**Зависит от:** RSP-04, RSP-05; GAP-006, SR-001.

**Решение:** источники меню `rh` — взаимодействия локации и переходы. Каждый пункт получает доступность и причину из `check` того же взаимодействия или перехода.

**Инвариант:** [§ 7](../../RH/GameplayArchitecture.md#7-экран): недоступное показывается неактивным с причиной; доступность не сохраняется. Нарушение — отдельное вычисление доступности для меню, которое расходится с командой.

**Не считается закрытием:**
- скрытие недоступных пунктов вместо неактивных;
- причина, написанная в данных меню;
- статичный список взаимодействий, оставленный в экране рядом с источником.

**Done:**
- Меню собирается источниками `rh`; в Definitions экранов нет статичных списков взаимодействий.
- Недоступный пункт виден неактивным, его причина — результат `check`.
- Для каждого пункта меню в фикстурных состояниях доступность совпадает с исходом команды; перечислитель — пункты, которые вернули источники.

**Evidence:** specs меню: доступный, неактивный с причиной, совпадение с командой.

## RSP-07 — Панели статуса

- [ ] RSP-07 — Панели статуса

**Файлы:** `scripts/authoring/rules/status.lua`; `Docs/RH/GameplayArchitecture.md` § 7.

**Зависит от:** RSP-02, RSP-08 (время мира); GAP-007; список предметов — GAP-004.

**Решение:** `rh` задаёт значения верхней панели (день и время суток из номера хода и длительности хода) и панели игрока (выносливость из текущего значения и максимума по формуле, деньги, предметы).

**Инвариант:** [§ 3](../../RH/GameplayArchitecture.md#3-инварианты): максимум выносливости и время суток вычисляются, а не хранятся. Нарушение — поле максимума или времени суток в state.

**Не считается закрытием:**
- имена характеристик `rh` в `textsystem`;
- делитель полоски, заданный числом в коде.

**Done:**
- Верхняя панель показывает день и время суток, вычисленные из номера хода.
- Полоска выносливости — текущее значение относительно максимума по формуле.
- Деньги и предметы игрока берутся из модели.

**Evidence:** specs значений панелей в начале игры, после перехода, после конца хода.

## RSP-08 — Конец хода

- [ ] RSP-08 — Конец хода

**Файлы:** `scripts/authoring/rules/turn.lua`; schema kind `turn_phase`; Definitions фаз; номер хода и время мира в `world`; `Docs/RH/ContentData.md`.

**Зависит от:** RSP-02; GAP-010; GAP-009 — желательно.

**Вход:** фазы конца хода и их записи отчёта; формула восстановления выносливости.

**Решение:** по [§ 5.6](../../RH/GameplayArchitecture.md#56-ход). Первая фаза — восстановление выносливости. Записи отчёта собираются в список для RSP-10.

**Инвариант:** [§ 3](../../RH/GameplayArchitecture.md#3-инварианты): у NPC нет своих ходов; фазы не перебирают всех NPC. Нарушение — фаза, обходящая всех персонажей мира.

**Не считается закрытием:**
- список фаз в Lua;
- восстановление выносливости в самой команде без фазы;
- пустые записи в списке отчёта.

**Done:**
- `rh:command.turn.end` доступна при нулевой выносливости.
- Фазы — Definitions `turn_phase`, исполняются по возрастанию `order`, при равенстве — по Stable ID; перечислитель — перебор Definitions kind `turn_phase`.
- Фаза восстановления выносливости работает по формуле с параметрами `config`.
- Номер хода растёт на один, время мира сдвигается на длительность хода из `config`, публикуется `rh:event.turn_ended`.
- Записи отчёта собраны в порядке фаз, без пустых.
- Обход: каждая `turn_phase` ссылается на существующий Service с `run`; перечислитель — repository kind `turn_phase`.

**Evidence:** specs конца хода: восстановление, порядок фаз, равный `order`, событие, список записей.

## RSP-09 — Уникальные NPC и генерация типовых

- [ ] RSP-09 — Уникальные NPC и генерация типовых

**Файлы:** `scripts/authoring/rules/npc_generation.lua`; параметры генерации в расширении `actor` (`rh`); NPC в `rh:scenario.default`; `Docs/RH/ContentData.md`.

**Зависит от:** RSP-01, RSP-02; GAP-012; имя экземпляра — GAP-018.

**Вход:** уникальные NPC и их размещение; шаблоны типовых NPC, их количество и места.

**Решение:** по [§ 5.9](../../RH/GameplayArchitecture.md#59-персонажи-уникальные-и-типовые). Сценарий создаёт уникальных NPC и генерирует типовых через `rh:service.npc_generation`. Эффект `spawn_npc` и имя экземпляра добавляются, только если их использует контент плана (RSP-15, RSP-16).

**Инвариант:** [§ 3](../../RH/GameplayArchitecture.md#3-инварианты): в state только то, что нельзя вычислить. Нарушение — копия значений Definition у уникального NPC.

**Не считается закрытием:**
- генерация через `math.random`;
- отдельная Definition на каждого типового NPC;
- обращение к сгенерированному NPC по instance ID, записанному в код.

**Done:**
- Сценарий создаёт ровно один экземпляр на каждую Definition уникального NPC в заданной локации.
- Типовой NPC получает значения характеристик из диапазонов шаблона, имя и портрет — из наборов шаблона.
- Броски идут из потока `rh:random_stream.generation`; одинаковый seed даёт одинаковый state hash.
- Код обращается к уникальному NPC через `actor(...)`, к сгенерированному — через имя экземпляра, если его использует контент плана.
- Обход: у каждого шаблона для каждой характеристики набора `min ≤ max`, наборы имён и портретов не пустые; перечислитель — repository и таблица набора.

**Evidence:** specs генерации: диапазоны, повторяемость по seed, отсутствие копий у уникальных NPC; обход.
