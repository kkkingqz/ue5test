# Приёмка

> **Материализует:** этап M3 [плана](README.md): эталонные прогоны стартового пакета и сверку документов с реализацией.

## RSP-17 — Эталонные прогоны

- [ ] RSP-17 — Эталонные прогоны стартового пакета

**Файлы:** эталонные прогоны пакета в месте, которое даст GAP-016; `Docs/RH/GameplayArchitecture.md` § 9.

**Зависит от:** RSP-01…RSP-16; GAP-016.

**Решение:** каждый прогон — последовательность команд и seed на реальных пакетах `core + textsystem + rh` с зафиксированным state hash. Изменение hash объясняется так же, как в [Regenerate Golden](../../Guides/RegenerateGolden.md).

**Инвариант:** [Headless Simulation](../../Architecture/HeadlessSimulationContract.md): одинаковый input даёт одинаковый canonical hash в headless и UE. Нарушение — прогон, который зависит от host.

**Не считается закрытием:**
- hash, скопированный из прогона без объяснения;
- прогон, не проходящий через команды игрока;
- проверка только в headless.

**Done:**
- Прогон «цикл»: новая игра, переходы, взаимодействие, конец хода с отчётом.
- Прогон «магазин»: покупка и отказ из-за нехватки денег.
- Прогон «диалог»: ветвление по флагам игрока и NPC.
- Прогон «продажа»: оценка, согласие и отказ.
- Прогон «реакция и танец»: реакция на переход и танец до итога.
- Каждый прогон даёт один и тот же hash в headless и UE.
- Профиль Editor `core + textsystem + rh` проходит прогон «цикл».

**Evidence:** digest каждого прогона, сверка headless и UE, отчёт UE automation.

## RSP-18 — Сверка документов с реализацией

- [ ] RSP-18 — Сверка документов с реализацией

**Файлы:** `Docs/RH/GameplayArchitecture.md`, `Docs/RH/ContentData.md`, `Docs/Status/ResourceRequests.md`, `Docs/RH/README.md`.

**Зависит от:** RSP-17.

**Решение:** правила реализованных механик сверяются с кодом и specs. Документ остаётся `draft`, пока в нём есть механики вне плана (процессы, квесты, бой, модели NPC, роли, сознание); перевод в `normative` — когда реализованы и они.

**Инвариант:** `AGENTS.md`, раздел «Documentation is part of every code change»: код и документация не расходятся. Нарушение — правило в документе без реализации или реализация без правила.

**Не считается закрытием:**
- перевод в `normative` при нереализованных механиках;
- формат данных kind, описанный только примером.

**Done:**
- У каждого правила реализованных механик есть spec или обход, который покраснеет при его нарушении; соответствие — таблица разделов документа и specs в Evidence.
- `Docs/RH/ContentData.md` описывает каждый собственный kind `rh`; перечислитель — schemas пакета.
- В `Docs/Status/ResourceRequests.md` есть заявка на каждый ID ресурса и текста-заглушки контента; перечислитель — Definitions ресурсов `rh` с `required: false` и тексты с `source_message` вида `[<id>]`.

**Evidence:** таблица «раздел — spec или обход», результат обоих перечислений, `validate_docs.py`.
