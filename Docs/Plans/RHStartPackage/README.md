# Стартовый пакет RH: план реализации

> **Материализует:** [архитектуру геймплея RH](../../RH/GameplayArchitecture.md) в новом пакете `rh` на authoring surface: каркас пакета, основной игровой цикл и стартовый пакет — десять локаций, магазины, продажа с оценкой, диалоги, реакции на переход, танец.
> **Задачи:** RSP-01…RSP-18 в файлах этапов ниже. Checkbox задачи — единственный источник её завершения.
> **Результат:** играбельный цикл «новая игра → переходы и взаимодействия → магазин, продажа, диалог, танец → конец хода» в `GameData/rh/`, проверенный specs пакета и эталонными прогонами.

## Граница плана

План содержит только геймплей `rh`: Lua в `GameData/rh/scripts/authoring/`, Definitions и schemas `rh`, документы `Docs/RH/` и заявки в `Docs/Status/`. Доработка движка — `core`, `textsystem`, C++, Widget Blueprint, Screen Templates — ведётся отдельным планом; здесь она только перечислена как зависимость.

Если в ходе задачи выясняется, что движку не хватает возможности, задача останавливается, а пробел записывается в [Engine Gaps](../../Status/EngineGaps.md). Обход через `game.*`, сырое `game.state` или собственный presentation module запрещён. Недостающий экран записывается в [Screen Requests](../../Status/ScreenRequests.md).

Пакет пишется с нуля: заглушка `rh` не переносится и не переименовывается.

## Проверка

Состав проверок задан [RH Gameplay Architecture § 9](../../RH/GameplayArchitecture.md#9-проверка): schemas данных, обходы контента, 3–5 specs на механику с отрицательным случаем, specs чистых ядер, 3–5 эталонных прогонов. Обход вводится той же задачей, что и его kind или точка расширения; перечислитель — repository и registry Services, а не рукописный список.

Перед коммитом задачи: `python3 Tools/Documentation/validate_docs.py`, `ctest --test-dir cmake-build-ci`, `gv2-headless --check-scripts`.

## Не входит в план

- Вся доработка движка, включая Screen Templates и Widget Blueprint экранов SR-001…SR-005.
- Процессы, квесты и сюжет, бой, модели NPC в конце хода, роли, спутники и приказы, сознание, дом, расписания NPC: архитектура описана, но в стартовом пакете у них нет ни производителя, ни потребителя.
- Аргумент `performer` у `rh:command.perform` — добавляется вместе со спутниками.
- Переопределение сборки меню для конкретной локации — добавляется с первой локацией, которой оно нужно.
- Типы условий и эффектов, которые не использует контент плана.
- Механизм расширения `union` для модов.
