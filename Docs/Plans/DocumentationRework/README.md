# План переработки документации

> **Материализует:** разбор состояния документации по итогам ревизии корпуса.
> **Задачи:** DOC-01…16.
> **Результат:** правила проекта записаны и заметны, инструкции перестают учить удалённому API, у авторского слоя появляется собственный контракт и собственная документация для дизайнера.

## Цель

Корпус документации — 223 файла и 162 тысячи слов — в целом дисциплинирован: тир документа привязан к каталогу и проверяется машиной, у каждого контракта один владелец, инварианты имеют ID, документов-сирот нет.

Проблемы точечные, но каждая работает против пользователя документации:

- инструкции в `Guides/` учат API, которого больше нет;
- у авторского слоя нет ни контракта, ни документации для дизайнера, хотя это главная поверхность проекта;
- `LuaRuntimeContract.md` собрал семнадцать разделов и стал общим складом;
- ключевые правила проекта — «до 1.0 совместимости нет» и «минимум C++» — либо не записаны вовсе, либо спрятаны;
- архив планов занимает треть корпуса.

## Предусловие выполнения

План выполняется **после закрытия активных планов**: [EntityExtensionsHardening](../EntityExtensionsHardening/README.md), [CommandValidators](../CommandValidators/README.md), [GameplayServices](../GameplayServices/README.md), [UiComposition](../UiComposition/README.md). Первый из списка, [RHActorsSimplification](../Archive/RHActorsSimplification/README.md), уже закрыт.

Причина конкретна: три из них меняют авторский слой — добавляют `validate` и `services`, переделывают `field.*` и методы актора. Справочник инструментов авторского слоя, написанный раньше, пришлось бы переписывать сразу после написания.

## Состояние на входе

Измерено по корпусу.

| Что | Сейчас |
|---|---|
| Правило «до 1.0 обратной совместимости нет» | **Не записано нигде.** Существуют только частные следствия — например, что смена namespace ломает старые сейвы |
| Правило «минимум C++» | Записано как [INV-013](../../Architecture/Invariants.md) и [ADR-0020](../../ADR/0020-cpp-scope-criterion.md), но не заметно: строка в середине списка |
| `Guides/` | 7 файлов; четыре учат удалённому API: `register_type`, ручной `setmetatable`-декоратор, `game.commands.handlers.register` с ручным конвертом результата |
| Проверка инструкций | Отсутствует: `Concepts/` и `Guides/` не проверяет ничего, кроме front matter и ссылок |
| Legacy-формы вне архива | `register_type` — 6 файлов, `/Game/` — 6, `validate_amount` — 5, `RESOURCES` — 4, `actor_decorator` — 2 |
| Авторский слой | Контракта нет; поверхность размазана по `LuaRuntimeContract`, `ScreenTemplates` и пяти ADR |
| `Docs/Authoring/` | Удалён ранее «до стабилизации набора команд» |
| `LuaRuntimeContract.md` | 4872 слова, 17 разделов, 76 файлов ссылаются |
| `Status/ImplementationStatus.md` | Перечисляет реализованное; требует ручного обновления при каждом расширении объёма |
| Архив планов | 102 файла, 54 тысячи слов — треть корпуса; активных планов 23 файла |
| Номера ADR | Выделяются при написании плана; за одну сессию столкнулись трижды |

## Принятые решения

- **Правила получают владельца и заметность.** Совместимость — новый контракт `CompatibilityPolicy.md` и новый инвариант; «минимум C++» остаётся у существующего владельца, меняется только видимость.
- **Гейт на удалённые идентификаторы работает по инструктирующим тирам.** В планах и предложениях упоминание удалённого API законно — они его удаляют; в `Guides/` и `Concepts/` то же упоминание означает «так делай».
- **`LuaRuntimeContract` делится на три документа** по владению: VM и загрузка, фасад и реестры, авторский слой.
- **Авторский слой получает два документа:** нормативный контракт в `Architecture/` и инструкции для дизайнера в `Docs/Authoring/` с полным списком инструментов и примерами.
- **`Guides/` — только для программиста.** Задачи дизайнера уезжают в `Authoring/`.
- **`ImplementationStatus` инвертируется:** перечисляет незакрытые расхождения с контрактами, а не реализованное.
- **Архив планов сжимается до README.** Zip не создаётся: git уже является архивом, а двоичный объект хуже ищется. README архивного плана называет коммит, из которого восстанавливается финальная версия.
- **Номер ADR занимается созданием файла.** До этого план ссылается на решение по названию — правило применяется в этом плане с первой задачи.

## Границы

Входят: правила и их видимость, гейт и чистка legacy, разделение контракта, документация авторского слоя, переработка `Guides/`, инверсия `Status/`, сжатие архива.

Не входят:

- Переписывание архивных планов и предложений: это исторические записи.
- Перевод документации на английский или второй язык.
- Генерация справочника авторского слоя из кода: справочник пишется руками, потому что примеры важнее полноты.
- Изменение схемы front matter и правил валидатора сверх перечисленного.

## Критический путь

```text
M1 ──► M2

M3 ──► M4 ──► M5
```

M1 предшествует M2: гейт материализует правило, а не наоборот. M3 предшествует M4: документация дизайнера ссылается на новый контракт авторского слоя. M4 предшествует M5: `Guides/` делится по аудитории только после того, как вторая аудитория получила свой каталог.

Ветви независимы и могут выполняться в любом порядке относительно друг друга.

## Общие правила выполнения

1. Ни одна задача не вводит второго источника истины: у правила ровно один владелец, остальные места на него ссылаются.
2. Каждое изменение правил валидатора сопровождается проверкой на **отрицательный** случай.
3. Перенос или переименование документа обновляет все относительные ссылки в том же change set.
4. Задачи ссылаются на ADR по названию решения; номер занимается созданием файла (DOC-03).
5. `python3 Tools/Documentation/validate_docs.py` зелёный после каждой задачи.
6. Архивные планы и предложения не переписываются по существу; допускается только добавление ссылки на коммит (DOC-15).

## Итоговый Definition of Done

- [ ] Правило «до 1.0 обратной совместимости не поддерживаем» записано, имеет владельца, номер инварианта и видно в корневом router-е.
- [ ] Правило «минимум C++» видно там же и по-прежнему имеет единственного владельца.
- [ ] Гейт отклоняет упоминание удалённого API в `Guides/` и `Concepts/` и не срабатывает на планах и предложениях.
- [ ] В `Guides/` и `Concepts/` не осталось инструкций по удалённым механизмам.
- [ ] `LuaRuntimeContract.md` не содержит разделов про фасад, реестры и авторский слой; на все три документа ссылаются актуальные пути.
- [ ] Авторский слой имеет нормативный контракт и справочник для дизайнера с примером на каждый инструмент.
- [ ] `Guides/` содержит только задачи программиста; каждая соответствует реальному повторяющемуся действию в этом репозитории.
- [ ] `ImplementationStatus` перечисляет расхождения, а не реализованное, и не требует правки при добавлении возможности.
- [ ] Архив планов состоит из README со слитым Evidence и ссылкой на коммит; файлы этапов удалены.
- [ ] Правила «изменил код с гайдом — переработал гайд» и «изменил авторский слой — переработал его документацию» записаны в `AGENTS.md`.
