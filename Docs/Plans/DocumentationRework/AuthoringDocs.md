# M4 — Authoring Docs

> **Материализует:** решение о документации авторского слоя для геймдизайнера.
> **Задачи:** DOC-10…11.
> **Результат:** у человека, который пишет игру, есть одна страница со всеми доступными инструментами и примером на каждый.

## Результат этапа

`Docs/Authoring/` возвращается — на этот раз при выполненном условии, ради которого его удаляли: набор команд зафиксирован закрытыми планами.

Каталог инструктирует и правил не вводит: при расхождении прав контракт из M3.

## Задачи

- [ ] **DOC-10 — Каталог `Docs/Authoring/` и его тир**
  - Зависимости: DOC-07.
  - Каталог инструктирует, а не нормирует, поэтому его документы обязаны иметь `status: informative`. Сегодня валидатор допускает этот статус только в `Concepts/` и `Guides/`.
  - Done: `Authoring` добавлен в список инструктирующих каталогов валидатора, и статус требуется внутри него в обе стороны; заведена схема шапки для каталога (обязательное первое поле) наравне с остальными тирами; создан `Docs/Authoring/README.md` как router с порядком чтения; каталог добавлен в `Docs/README.md` с явной пометкой «не нормативен»; проверка на отрицательный случай пройдена.
  - Evidence: `Tools/Documentation/validate_docs.py`, `Docs/Authoring/README.md`, `Docs/README.md`, `Docs/Architecture/README.md`.

- [ ] **DOC-11 — Справочник инструментов авторского слоя**
  - Зависимости: DOC-10.
  - Done: `Docs/Authoring/` содержит полный перечень доступных в авторском скрипте инструментов — объявление команд и действий, методы сущностей, дескрипторы полей, валидаторы, сервисы, отказы, события, тексты, кнопки и экраны, создание экземпляров; **на каждый инструмент — назначение, сигнатура и рабочий пример**; примеры взяты из фактического кода `rh` и `sample`, а не придуманы; отдельно описано, чего делать нельзя и какая ошибка при этом возникает; для каждого инструмента дана ссылка на нормативный источник; порядок изложения — от задачи дизайнера, а не от устройства рантайма.
  - Evidence: `Docs/Authoring/`, `GameData/rh/scripts/`, `GameData/sample/scripts/`.

## Проверка milestone

- [ ] Валидатор требует `informative` внутри `Authoring/` и запрещает снаружи.
- [ ] Каждый инструмент авторского слоя описан и снабжён примером.
- [ ] Каждый пример соответствует фактическому коду.
- [ ] Каталог виден из корневого router-а с пометкой о ненормативности.
