# M4 — Authoring Docs

> **Материализует:** решение о документации авторского слоя для геймдизайнера.
> **Задачи:** DOC-10…11.
> **Результат:** у человека, который пишет игру, есть один маршрут чтения, полный reference доступных инструментов и проверенный пример на каждый.

## Результат этапа

`Docs/Authoring/` возвращается — на этот раз при выполненном условии, ради которого его удаляли: набор команд зафиксирован закрытыми планами.

Каталог инструктирует и правил не вводит: при расхождении прав контракт из M3.

## Задачи

- [ ] **DOC-10 — Каталог `Docs/Authoring/` и его тир**
  - Зависимости: DOC-07.
  - Каталог инструктирует, а не нормирует, поэтому его документы обязаны иметь `status: informative`. Сегодня валидатор допускает этот статус только в `Concepts/` и `Guides/`.
  - Done: `Authoring` добавлен в единую классификацию инструктирующих каталогов validator-а, включая гейт DOC-05, и `status: informative` требуется внутри него в обе стороны; заведена схема шапки для каталога (обязательное первое поле) наравне с остальными тирами; `Docs/README.md` и `Docs/Architecture/README.md` описывают будущий каталог как ненормативный; `AGENTS.md` синхронно обновляет Documentation authority, How to read documentation, Placement, правила `informative` и обязанность менять authoring docs вместе с authoring API; положительный и отрицательный validator cases пройдены. Сам каталог создаётся только в DOC-11 сразу с достаточным числом содержательных документов, а не как пустой router.
  - Evidence: `Tools/Documentation/validate_docs.py`, `Docs/README.md`, `Docs/Architecture/README.md`, `AGENTS.md`.

- [ ] **DOC-11 — Справочник инструментов авторского слоя**
  - Зависимости: DOC-10.
  - Done: `Docs/Authoring/` создаётся атомарно и содержит `README.md` как router и минимум два самостоятельных reference-документа: `LuaGameplayReference.md` для Commands, entity methods, `field.*`, Validators, Services, отказов, Events и создания instances; `PresentationAuthoringReference.md` для actions, text, buttons, Screens и desired presentation. Вместе они покрывают полный перечень доступных в authoring script инструментов; **на каждый инструмент — назначение, сигнатура и рабочий пример**; inventory в router-е показывает, какой документ владеет объяснением каждого инструмента; примеры взяты из фактического кода `rh` и `sample`, а не придуманы; отдельно описано, чего делать нельзя и какая ошибка при этом возникает; для каждого инструмента дана ссылка на нормативный источник; порядок изложения — от задачи дизайнера, а не от устройства runtime.
  - Evidence: `Docs/Authoring/`, `GameData/rh/scripts/`, `GameData/sample/scripts/`.
