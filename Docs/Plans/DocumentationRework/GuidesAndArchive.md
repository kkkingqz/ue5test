# M5 — Guides and Archive

> **Материализует:** решения о разделении инструкций по аудитории, инверсии статуса и сжатии архива.
> **Задачи:** DOC-12…16.
> **Результат:** `Guides/` описывает работу с движком, статус перечисляет пробелы, архив перестаёт занимать треть корпуса.

## Результат этапа

- [x] **DOC-15 — Перевести архив планов в плоские summary-файлы**
  - Зависимости: DOC-14.
  - Архив — 102 файла и 54 тысячи слов при 23 файлах активных планов. После выполнения для оперативного чтения нужны итог каждого этапа, task IDs и маршрут к полной истории; сами task-файлы остаются доступными в git.
  - Формат: выполненный `<PlanName>` представлен одним `Docs/Plans/Archive/<PlanName>.md` со `status: archived`. Summary содержит цель и общий результат; раздел по каждому milestone/этапу с кратким итогом; **все** шаги этого этапа в форме `<task ID> — <исходное название>` (`SAV-03 — ...`, `SAV-04 — ...`) и в исходном порядке; ссылки на актуальные normative contracts; полный hash `source_commit` и кликабельную ссылку на этот commit в repository web UI, где доступны полные файлы плана. Task ID обязан встретиться ровно один раз и не меняется при архивации.
  - Процедура для нового выполненного плана: все checkboxes и milestones сначала фиксируются отдельным commit при ещё существующем полном каталоге плана; этот commit становится `source_commit`; затем создаётся flat summary, обновляется `Archive/README.md`, план удаляется из списка активных, исходный `Docs/Plans/<PlanName>/` удаляется, и выполняется archive commit. Summary не может ссылаться на archive commit как на источник полного плана — это была бы circular-ссылка.
  - Миграция существующего архива: до первой правки фиксируется HEAD с полными `Docs/Plans/Archive/<PlanName>/`; для каждого каталога создаётся соседний `<PlanName>.md`, после чего каталог удаляется. Все входящие ссылки из-за пределов удаляемых каталогов инвентаризируются и перенаправляются на flat summary либо на нормативный owner contract.
  - `Docs/Plans/README.md`: раздел с таблицей выполненных планов удалён полностью; вместо него остаётся только ссылка `[Архив выполненных планов](../Archive/README.md)`. Перечень, дата завершения и краткий результат принадлежат только `Docs/Plans/Archive/README.md`, который ссылается на flat summary-файлы.
  - Verification: для каждого удаляемого файла выполняется `git cat-file -e <source_commit>:<original_path>`; ссылка на commit проверяется; для каждого summary автоматически либо эквивалентной проверкой сопоставляются milestone names и полный набор task IDs исходного плана; минимум один representative файл восстанавливается через `git show`; после удаления не остаётся подкаталогов планов внутри `Docs/Plans/Archive/`; **zip не создаётся**.
  - Правило архивации в `Docs/Plans/README.md` и `AGENTS.md` описывает эту же двухкоммитную процедуру, обязательную полноту task IDs и плоскую структуру без альтернативного варианта.
  - Evidence: `Docs/Plans/Archive/`, `Docs/Plans/README.md`, `AGENTS.md`.
