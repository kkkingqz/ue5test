# M5 — Guides and Archive

> **Материализует:** решения о разделении инструкций по аудитории, инверсии статуса и сжатии архива.
> **Задачи:** DOC-12…16.
> **Результат:** `Guides/` описывает работу с движком, статус перечисляет пробелы, архив перестаёт занимать треть корпуса.

## Результат этапа

Инструкции разделены по аудитории: дизайнер читает `Authoring/`, программист — `Guides/`. Оба каталога описывают то, что действительно делают.

## Задачи

- [ ] **DOC-12 — Разделить `Guides/` по аудитории**
  - Зависимости: DOC-11.
  - Done: `AddActorWrapper.md` **удалён** — его предмет не существует: механизм `register_type` с ручным `setmetatable`-декоратором убран решением по авторским расширениям сущностей; `AddCommand`, `AddEvent`, `AddDefinition` и `AddUIScreen` переработаны как задачи дизайнера и перенесены в `Docs/Authoring/`; `AddLuaModule` и `AddLuaSpec` остаются в `Guides/` и переработаны — второй обязан знать о трёх тирах спек, появившихся после его последней правки; все ссылки обновлены.
  - Evidence: `Docs/Guides/`, `Docs/Authoring/`.

- [ ] **DOC-13 — Недостающие гайды программиста**
  - Зависимости: DOC-12.
  - Каждый гайд отвечает реальной повторяющейся задаче этого репозитория, а не гипотетической.
  - Done: добавлены только четыре гайда с подтверждёнными повторяющимися потребителями:
    - **AddAuthoringSurface** — новый глобал в `_ENV`, прокси с `__newindex`, отложенная регистрация, заморозка, атрибуция ошибок пакету; самая частая задача последних планов;
    - **AddScreenField** — схема поля, адаптер и `WBP_*` через `unreal-mcp`;
    - **RegenerateGolden** — какой хэш от чего меняется, воспроизведение манифестом, кэширование хэша на конфигурации CMake;
    - **WhenToWriteCpp** — критерий [ADR-0020](../../ADR/0020-cpp-scope-criterion.md) как процедура, а не как принцип.
  - `AddRegistry` не создаётся: новый registry является архитектурным решением, а общий protocol принадлежит `RuntimeFacadeAndRegistries.md`, не инструкции по копированию. `AddGate` не создаётся до появления минимум двух независимых повторяющихся consumers; обязательные требования к gate остаются в `BuildAndTooling.md` и рядом с существующими test helpers.
  - Для каждого нового гайда в change set указаны минимум два фактических пути/изменения, подтверждающих повторяемость задачи; без такого evidence документ не создаётся.
  - Каждый гайд явно называет свой предмет в шапке, чтобы правило DOC-04 было проверяемым.
  - Evidence: `Docs/Guides/`.

- [ ] **DOC-14 — Инвертировать `ImplementationStatus`**
  - Зависимости: DOC-12.
  - Документ перечисляет реализованное и обязан обновляться при каждом расширении объёма — то есть структурно обречён расходиться с кодом.
  - Done: документ перечисляет только **подтверждённые незакрытые расхождения** нормативных contracts с реализацией: `missing`, `partial` или `known_nonconformance`; каждая строка содержит ссылку на конкретное нормативное правило, точное расхождение и evidence из кода/test либо отсутствие требуемого evidence; roadmap, приоритеты, предложения и «ближайшие возможности» запрещены, потому что принадлежат Plans/Proposals; строки «реализовано» удалены — на этот вопрос отвечают код и tests; одновременное добавление contract и полностью соответствующей реализации не требует новой строки, закрытие существующего gap удаляет её в том же change set; правило обновления в `AGENTS.md` приведено в соответствие.
  - Evidence: `Docs/Status/ImplementationStatus.md`, `AGENTS.md`.

- [ ] **DOC-15 — Сжать архив планов**
  - Зависимости: DOC-14.
  - Архив — 102 файла и 54 тысячи слов при 23 файлах активных планов. Ценность сосредоточена в `README.md` каждого плана: принятые решения, границы, обоснование «не входит» и уточнения по итогам приёмки. Файлы этапов после архивации несут только Evidence.
  - Done: до первой правки фиксируется полный `source_commit` — HEAD, содержащий финальные несжатые архивы; для каждого архивного плана в `README.md` сохраняются решения, границы, причины и краткий Evidence summary без переноса полного task log; README называет этот заранее известный `source_commit`, поэтому circular-ссылка на создаваемый commit отсутствует; все входящие ссылки из-за пределов сжимаемого архива инвентаризированы и перенаправлены до удаления; файлы этапов удалены; для каждого удалённого path выполняется `git cat-file -e <source_commit>:<path>`, а минимум один representative файл восстанавливается и сравнивается через `git show`; **zip не создаётся** — git уже является архивом, а двоичный объект в истории хуже ищется; правило переноса в `Docs/Plans/README.md` и `AGENTS.md` описывает именно эту процедуру для будущих архивов.
  - Evidence: `Docs/Plans/Archive/`, `Docs/Plans/README.md`, `AGENTS.md`.
