# План универсального UI property pipeline

> **Материализует:** [Universal Data-Driven UI Property Pipeline](../../Proposals/UniversalDataDrivenUIPropertyPipelineProposal.md).
> **Задачи:** UPP-01…32.
> **Результат:** свойство, объявленное схемой, либо наблюдаемо доходит до экрана, либо даёт типизированный отказ; состояния «принято и молча не применено» не существует структурно.

## Цель

Заменить schema-specific цепочку `PrepareXxx` → `BuildXxx` → `FGV2XxxViewModel` → `ApplyXxx` одним универсальным pipeline с data-driven схемами и раздельными фазами Prepare/Commit.

Цель не в устранении списка дефектов — они уже устранены точечно. Цель в том, чтобы список перестал пополняться. За четыре раунда проверки одно семейство («значение пересекло границу и молча исчезло») дало четыре экземпляра: персонажи сцены, иконки предметов, метки метров, свойства `is_read_only`/`max_length`. Каждый закрывался отдельно, и частота не падала.

## Состояние на входе

| Что | Сейчас |
|---|---|
| Форма значения после границы | 13 schema-specific DTO и union `FGV2ScreenFieldValue` |
| Конверсия | Пара ручных `PrepareXxx`/`BuildXxx` на каждую схему |
| Гарантия применения | Никакой: `ConsumedKeys` объявляет допустимость, применение пишется отдельно |
| Отказ ребёнка | Распространяется там, где это написали руками |
| Атомарность | Компенсирующий откат на уровне экрана; `FGV2LayeredUiReconciler` неатомарен |
| Предиктивность | `CanApplyScreenField` не опрашивает детей (`STATUS-004`) |
| Политика масштабирования | «Не задано» невыразимо (`STATUS-003`) |
| Схемы UI | Живут в C++, модами не расширяются |
| Обратная совместимость | Не поддерживается — это упрощает миграцию, а не усложняет |

## Принятые решения

- **Capability обязана быть наблюдаемой.** Объявление, применение которого не меняет захваченного состояния виджета, не является объявлением. Без этого правила ложь переезжает из `ConsumedKeys` в таблицу capability, и план не достигает цели. Средство — harness UPP-11, доступный до первой миграции виджета.
- **Виджет мигрирует вместе со своим контентом и своим адаптером.** Двойной стек существует между элементами, а не внутри одного. Обратной совместимости нет, поэтому Lua-форма правится тем же change set.
- **Миграция может быть остановлена.** UPP-15 — гейт go/no-go на трёх элементах. Если проверки не удаётся заставить краснеть на срезе Text/Image/Button, на двадцати пяти виджетах не удастся тем более.
- **Отказ Commit — нарушение инварианта с наблюдаемым следствием**, а не обычный `false`. Поведение задаётся ADR и проверяется инъекцией отказа, иначе атомарность останется незаземлённым утверждением.

## Отношение к принятым ранее решениям

[ADR-0038](../../ADR/0038-screen-field-value-flat-struct.md) отклонил переход `FGV2ScreenFieldValue` на размеченное объединение с наблюдаемым условием пересмотра «добавление 14-го payload». Этот план условие не наступает, а снимает: union удаляется целиком (UPP-30), поэтому ADR-0038 становится неприменимым и заменяется решением UPP-01. Пересматривать его отдельно не требуется — требуется зафиксировать замену, что UPP-30 и делает.

## Границы

Не входят: `STATUS-001` (lifecycle сессии и replacement flow) и `STATUS-002` (Presentation Effects) — отдельные архитектурные задачи. Аварийный путь Commit проектируется так, чтобы **не** зависеть от `STATUS-002`.

`STATUS-003` и `STATUS-004` входят: первый закрывается UPP-13, второй — UPP-27.

## Критический путь

```text
M1 ──► M2 ──► M3 ──► [ГЕЙТ UPP-15] ──► M4 ──► M5 ──► M6 ──► M7 ──► M8
                            │
                            └── отказ: миграция останавливается,
                                proposal пересматривается

M4, M5, M6 внутри себя допускают перестановку задач;
порядок между milestones строгий: композит нельзя мигрировать
раньше своих листьев.
```

## Общие правила выполнения

1. **Задача не отмечается `[x]`, пока не назван тест, который покраснеет при откате изменения.** Формулировка «тест есть и он зелёный» подтверждением не является.
2. Каждая миграция виджета в том же change set: переводит виджет, объявляет capability, пишет тест наблюдаемости, **удаляет** свой `PrepareXxx`/`BuildXxx`/DTO/ветку union и правит Lua-форму.
3. Гейт монотонного убывания (UPP-11) не может расти ни в одном коммите после M2.
4. Ассеты меняются только через `unreal-mcp`, с compile, save и прогоном automation.
5. Каждое исправленное утверждение получает **отрицательный** случай.
6. Тест, доказывающий более слабое свойство, чем его имя, переписывается, а не дополняется.
7. Строка `STATUS-NNN` удаляется тем же change set, который её закрывает.
8. Правки нормативных контрактов выполняются в той же задаче, что и код, делающий утверждение истинным.

## Итоговый Definition of Done

- [ ] UI-схема объявляется данными и компилируется переносимо, без UE. (UPP-02…05)
- [ ] Объявленная capability, не меняющая наблюдаемого состояния, невозможна: сборка краснеет. (UPP-11)
- [ ] Схема, требующая свойства, которого виджет не умеет, отклоняется до `Ready`. (UPP-08, UPP-14)
- [ ] Prepare не меняет живое состояние ни при валидном, ни при невалидном входе. (UPP-10)
- [ ] Отказ Commit не публикует экран, сохраняет предыдущую ревизию и даёт диагностику с путём до свойства. (UPP-10)
- [ ] Отказ ребёнка структурно не может дать успех родителя. (UPP-20…23)
- [ ] Гейт go/no-go пройден на срезе из трёх элементов. (UPP-15)
- [ ] «Политика масштабирования не объявлена» выразимо и отклоняется; `STATUS-003` удалён. (UPP-13)
- [ ] Предиктивный preflight предсказывает отказ глубокого ребёнка; `STATUS-004` удалён. (UPP-27)
- [ ] Замена экрана атомарна: старый не отсоединяется до полностью подготовленного нового. (UPP-28)
- [ ] Мод объявляет UI-схему из стандартных kinds без нового C++; несовместимая схема мода отклоняет мод, а не сессию. (UPP-05, UPP-08)
- [ ] `FGV2ScreenFieldAdapterRegistry`, union payload и schema-specific DTO удалены; гейт убывания доведён до нуля и превращён в постоянный запрет. (UPP-30)
- [ ] Каждое заявленное закрытие проверено правилом красного теста, а не ссылкой на задачу. (UPP-32)
