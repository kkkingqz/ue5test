# План перевода композитов на объявление

> **Материализует:** исправленную запись о трёх композитах локации в [DataDrivenUiComposition](../Archive/DataDrivenUiComposition.md) и требование собирать экран в Designer из любых доступных компонентов.
> **Задачи:** DCA-01…16.
> **Результат:** в коде не остаётся ни одного C++-класса виджета, существующего только ради композиции существующих элементов, и ни одного специального мостика под конкретный композит.

## Цель

Отчёт `DUC-08` записал, что три композита локации к объявлению не сводятся. Проверка это опровергла: набор capability всех трёх выражается объявлением полностью, а названная причина по `CommandPanel` — `OnBindingInvoked` — оказалась мёртвой поверхностью без единого `Broadcast` и без подписчиков.

Настоящее препятствие одно и лежит в ассетах: композит принимает голую панель и создаёт репитер внутри себя в `NativePreConstruct`. Этот объект — transient `UPROPERTY`, его нет в `WidgetTree`, поэтому адресация по имени до него не дотягивается. Ради обхода в `GV2UiMutationPlan.cpp` живёт хардкод трёх `Cast` по конкретным классам локации с перечислением имён контейнеров.

**Главный измеримый результат плана — исчезновение этого мостика.** Пока он существует, утверждение «модель покрывает любой композит» имеет живое исключение, и разговор о будущих компонентах опирается на модель с дырой.

Вторая половина плана — доказательство с другой стороны: три **полностью новых** композита, собранных без единой строки C++. Миграция доказывает, что старое выражается объявлением; авторинг — что новое не требует кода.

## Состояние на входе

| Что | Сейчас |
|---|---|
| Хосты коллекций в трёх композитах | Голые `UWrapBox`/`UPanelWidget`; репитер создаётся внутри и отсутствует в `WidgetTree` — **закрыто DCA-02, 2026-09-03** |
| `GV2UiMutationPlan.cpp` | Хардкод трёх `Cast` по классам локации с перечислением имён контейнеров |
| Запись объявления | Не имеет признака необязательности; композиты объявляют capability условно, `if (Target != nullptr)` — **закрыто DCA-01, 2026-09-03** |
| `Resolve*WidgetClass` | Трёхступенчатый откат свойство → CDO → `LoadClass`; ни одна из четырёх виртуальных функций не переопределена |
| `OnBindingInvoked` у `CommandPanel` | `BlueprintAssignable`, ноль `Broadcast`, ноль подписчиков в C++ и в трёх релевантных Blueprint |
| `StaminaMeter`, `Character` | Помечены `DeprecatedProperty`, только сворачиваются |
| Новые композиты из данных | Ни одного; объявляемый композит доказан только на `TopBar` и синтетических фикстурах |
| Отзывчивость раскладки | `ADR-0035` не имеет перечислителя; `WrapSize=1200` в `WBP_ListView_WrapButtons` — замер с 720p, вмороженный как константа |
| Гейты и `Content/` | Ни один гейт не читает ассеты: все семь — текстовые сканы по `Source/` и `Docs/` |

## Принятые решения

- **Мостик удаляется, а не обобщается.** Соблазн — сделать поиск внутренних репитеров общим для любого хоста. Это закрепило бы адресацию объекта вне `WidgetTree` как часть модели; вместо этого ассеты приводятся к тому, что модель уже умеет.
- **Признак необязательности принадлежит объявлению, а не виджету.** Сегодня условность выражена в C++ (`if (Target != nullptr)`), и именно она мешает выразить варианты одного композита. Перенос её в запись объявления — необходимое условие миграции, а не удобство.
- **Доказательство авторинга измеримо.** Задачи трёх новых композитов закрываются в том числе тем, что их change set **не содержит изменений в `Source/`**. Утверждение «C++ не понадобился» проверяется diff-ом, а не памятью исполнителя.
- **Разбор `WrapSize` не сворачивается в правку одного значения.** `DCA-02` перенёс константу как есть — по своему скоупу он обязан был сохранить поведение. Но её происхождение (замер, снятый на единственном строго проверяемом разрешении, и вмороженный в ассет) означает, что чинить надо инструмент и перечислитель, а не число. Отсюда `M4`.
- **Новые композиты выбраны лесенкой.** `npc_portrait` — два листа без коллекций; `location_description` — необязательное свойство в реальном случае; `inventory_tabs` — полная цепочка `экран → вкладки → блок → коллекция` из данных, то есть самое глубокое, что модель обещает.

## Границы

Не входит: реестр адаптеров для голых UMG-контролов, недостижимых сегодняшними consumers (`USlider`, `USpinBox` и прочие). Это следующий шаг к «любым будущим компонентам», и он опирается на результат этого плана, а не наоборот. Также не входят `STATUS-001`, `STATUS-002`, `STATUS-003`, `STATUS-008`.

## Критический путь

```text
DCA-01✔, DCA-02✔, DCA-03, DCA-04   — независимы друг от друга

           └──────► DCA-05, DCA-06, DCA-07 ──────► DCA-08 ──────► DCA-09…11 ──► DCA-12

DCA-05…07 переставляются между собой

DCA-13 ──► DCA-15        DCA-14, DCA-16 — независимы

M4 (DCA-13…16) не зависит от M1…M3 и переставляется с ними свободно
```

`M4` возник из разбора `WrapSize=1200`, найденного при `DCA-02`. Он не блокирует миграцию и не блокируется ею: пересечение только по `GV2RuntimeSubsystemTests.cpp` (владеет `M4`) и по ассетам `WBP_ListView_Wrap*` (их `M2` и `M3` не трогают).

## Общие правила выполнения

1. Задача не отмечается `[x]`, пока не назван гейт, который **покраснеет** при откате изменения, и это не продемонстрировано.
2. Ассеты меняются только через `unreal-mcp`, с compile, save и прогоном automation.
3. Удаляемая поверхность удаляется, а не помечается устаревшей: `DeprecatedProperty` в этом плане исходом не является.
4. Каждый новый объявляемый композит попадает в sweep наблюдаемости тем же change set, что и его объявление.
5. Правки нормативных контрактов выполняются в той же задаче, что и код или ассет.
