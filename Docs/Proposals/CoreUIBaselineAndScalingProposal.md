# Предложение по базовому набору Core UI, композиции и масштабированию

> **Предлагает:** нейтральный базовый набор виджетов с едиными конвейерами текста и графики, отзывчивую раскладку вместо равномерного масштаба и явную политику масштабирования примитива, проверяемую режимом ресурса.
> **Затрагивает:** [Screen Templates](../UI/ScreenTemplates.md), [Image Resources](../UI/ImageResources.md), [UI Index](../UI/README.md), [UI Composition and Scaling](UiCompositionAndScalingProposal.md).
> **Не является нормативным:** до реализации действует текущий contract.

## 1. Назначение

Экраны собираются из виджетов, а не из полей документа. Сегодня набор виджетов сложился исторически: часть элементов существует как `WBP_*` без контракта данных, часть контрактов не имеет виджета, а поведение при смене разрешения не описано нигде.

Предложение задаёт три вещи: **состав базового набора и границу его владения**, **единые конвейеры текста и графики для всех элементов** и **модель масштабирования**, которая работает от 4K до 720p и на непривычных пропорциях.

## 2. Состояние на входе

Измерено по репозиторию.

| Что | Сейчас |
|---|---|
| Виджеты | 15 `WBP_*`: `Text`, `RichText`, `Image`, `Button`, `ButtonList`, `Checkbox`, `InputField`, `DropdownSelect`, `ProgressBar`, `Separator`, `LoadingIndicator`, `Modal`, `Portrait`, `RichTextPopover`, `Testscreen` |
| Контракты Screen Field | Пять: `rich_text.v3`, `button_list.v2`, `checkbox.v1`, `input_field.v1`, `dropdown_select.v1` |
| Виджеты без контракта данных | `Image`, `ProgressBar`, `Portrait`, `Modal`, `Separator`, `LoadingIndicator`, `RichTextPopover` |
| Повторяемый контент | Только `ButtonList`; обобщённого списка нет |
| Режимы изображения | Три: `fixed_aspect`, `nine_slice`, `tile`; кодируются суффиксом файла ([ADR-0016](../ADR/0016-png-suffix-image-metadata.md)) |
| Проверка применимости ресурса | `UGV2ImageWidgetBase.AcceptedRenderMode` — только для изображений |
| Единый text pipeline | Заявлен ([ADR-0013](../ADR/0013-unified-text-pipeline.md)) и проверяется automation-тестом по полному инвентарю `/Game/UI` |
| Единый graphics pipeline | Заявлен ([ADR-0017](../ADR/0017-centralized-ui-presentation-paths.md)); `FGV2ImagePresentation.ResolveAndApply` — единственный путь |
| Масштабирование, DPI, разрешение | Не описаны ни в одном документе `Docs/UI/` |

Из этого следуют границы предложения: конвейеры уже приняты и требуют не введения, а **распространения на новые элементы и проверки**; масштабирование вводится с нуля.

## 3. Отношение к первой редакции

[UI Composition and Scaling](UiCompositionAndScalingProposal.md) задавал равномерный масштаб `min(H/1080, W/1440)` и требовал, чтобы раскладка отличалась только масштабом.

Решение отменено. Модель проектировалась для одного экрана с текстовым блоком и кнопками; со вкладками, списками и модалками она ломается на нижней границе — равномерный масштаб делает текст на 720p нечитаемым, а увеличить только текст внутри неё нельзя.

Остальные разделы первой редакции — идентичность повторяемых элементов, вложенный Screen Instance и вкладки, принадлежность темы слою — действуют без изменений и этим предложением не затрагиваются.

## 4. Три слоя, а не два

Владение композицией следует трёхуровневому разделению [ADR-0030](../ADR/0030-textsystem-layer-and-data-driven-package-set.md), а не бинарному «ядро и игра».

| Уровень | Что принадлежит | Пример |
|---|---|---|
| `core` | Нейтральные примитивы, конвейеры текста и графики, DPI, политики масштабирования, адаптеры Screen Field, layout-примитивы | `Button`, `RichText`, `Panel`, `ScrollArea` |
| `textsystem` | Композиты, нужные любой текстовой игре | Панель локации, строка списка персонажей, портрет собеседника |
| `rh` | Композиты и экраны конкретной игры | Строка товара, экран таверны |

Критерий тот же, что для сущностей: нужен любой игре — `core`; любой текстовой, но не любой — `textsystem`; выражает содержание конкретной игры — `rh`.

Композит не поднимается уровнем выше автоматически из-за переиспользуемости внутри своего слоя.

## 5. Базовый набор Core UI

### 5.1. Правило состава

Элемент входит в базовый набор **вместе с первым потребителем** — экраном или композитом, которому он нужен. Это то же правило, по которому проект отказался от `services.inventory` и `Quest foundation`.

Поэтому набор разделён надвое. Здесь — то, что требуется текущим экранам и работам по слоям, оверлеям и вкладкам. Остальное вынесено в [Core UI Extended Element Set](CoreUiExtendedElementSetProposal.md) и вводится по мере появления потребителя.

### 5.2. Входит в это предложение

| Элемент | Потребитель |
|---|---|
| `Panel` / контейнер | Основа любой композиции; без него вкладка не имеет содержимого |
| `ScrollArea` | Требование 720p: контент, не помещающийся в viewport, обязан прокручиваться |
| Обобщённый список (`Repeater`) | Повторяемый контент сложнее кнопки; сегодня существует только `ButtonList` |
| `Tabs` | Вкладки из первой редакции |
| `Modal` | Слой `modal_stack`; виджет есть, контракта данных нет |
| `Icon` | Элементы списков и кнопок |
| Контракты Screen Field для `Image`, `Portrait`, `Progress` | Виджеты существуют, данными не управляются |

### 5.3. Обобщённый список

Повторяемый контент строится на одном механизме с политикой раскладки (вертикальная, горизонтальная), а не на отдельном виджете под каждый случай. Элемент списка может быть композитом любого слоя.

Идентичность элементов подчиняется правилу ключей из [первой редакции](UiCompositionAndScalingProposal.md#4-идентичность-повторяемых-элементов) без исключений: обобщённый список — тот же контейнер.

## 6. Единые конвейеры

Оба конвейера уже приняты и проверяются. Предложение не вводит их заново, а фиксирует два следствия для нового набора.

**Ни один новый элемент не заводит собственного пути.** `Tabs`, `Modal`, `Tooltip`, элемент списка и любой композит используют существующие leaf-адаптеры текста и изображения. Проверка — та же automation по полному инвентарю `/Game/UI`, которая уже запрещает raw-`FText` apply.

**Одинаковый семантический стиль даёт одинаковый результат в любом виджете.** Стиль `body` не может разрешаться в разные физические размеры в зависимости от того, кто его рисует. Это проверяемое утверждение, и оно становится тестом.

## 7. Разрешение дизайна и разрешение авторинга

Это **два разных числа с разным назначением**, и первая редакция ошибочно их склеивала.

| Число | Значение | Назначение |
|---|---|---|
| Разрешение авторинга растра | **3840 × 2160**, 16:9 | Под него рисуются 2D-ресурсы: уменьшение чище увеличения, и 4K-монитор не получает мыла |
| Единицы раскладки | **1920 × 1080** | В них выражаются размеры, отступы и минимальные размеры в шаблонах |

Оба значения хранятся как константы проекта в одном месте и не повторяются в шаблонах. Ресурс, нарисованный под 4K, в раскладке занимает место, выраженное в единицах 1080 — соотношение между ними является свойством конвейера, а не заботой верстальщика.

## 8. Отзывчивая раскладка

Модель «отрисовать в опорном разрешении и равномерно масштабировать кадр» не используется.

```text
фактический viewport
    → раскладка распределяет доступное место
        → элемент получает границы
            → элемент применяет свою политику масштабирования
```

Структурная система раскладки поддерживает как минимум привязки, выравнивание, внутренние и внешние отступы, предпочтительный, минимальный и максимальный размер, заполнение и автоматический размер. При необходимости — ограничения пропорций и безопасную область.

**Политика раскладки и политика масштабирования содержимого разделены.** Раскладка отвечает, сколько места получает элемент; политика масштабирования — как содержимое использует эти границы. У составного виджета одной политики быть не может: у поля ввода фон девятислайсовый, иконка сохраняет пропорции, текст масштабируется по кривой DPI. Поэтому политика принадлежит **визуальному примитиву**, а не виджету.

## 9. Политика масштабирования примитива

Каждый визуальный примитив объявляет политику явно:

| Политика | Поведение |
|---|---|
| `FreeStretch` | Ширина и высота меняются независимо; содержимое растягивается |
| `Tile` | Содержимое повторяется с фиксированным логическим размером плитки |
| `NineSlice` | Углы неизменны, края растягиваются по одной оси, центр — по двум |
| `PreserveAspect` | Соотношение сторон сохраняется; при несовпадении границ применяется вписывание с выравниванием |

### 9.1. Режим ресурса проверяет применимость

Политика и режим ресурса отвечают на разные вопросы, поэтому не дублируют друг друга: **политика говорит, как слот использует содержимое; режим ресурса говорит, что этот битмап поддерживает.** Несовпадение — ошибка до мутации виджета.

| Политика примитива | Допустимые режимы ресурса |
|---|---|
| `FreeStretch` | `tile` |
| `Tile` | `tile` |
| `NineSlice` | `nine_slice` |
| `PreserveAspect` | `fixed_aspect` |

`tile` допустим для двух политик потому, что бесшовная заливка по построению не имеет выделенного направления: её законно и замостить, и растянуть. Иллюстрация в свободно растягивающемся слоте и рамка без разметки девятислайса законными не являются никогда.

Механизм существует: `UGV2ImageWidgetBase.AcceptedRenderMode` уже выполняет такую проверку для изображений. Предложение обобщает его на все визуальные примитивы и делает объявление политики обязательным, а не опциональным.

## 10. Масштаб текста

Текст масштабируется отдельной кривой, а не тем же множителем, что раскладка.

Линейное масштабирование недопустимо: при опорном 4K переход к 720p дал бы треть исходного размера. Кривая нелинейна и настраивается визуальной проверкой; порядок величин — около 0.8 на 1440p, 0.65 на 1080p и 0.5 на 720p относительно опорного.

**Стиль текста имеет минимальный эффективный размер.** Ниже порога текст не уменьшается. Если места не хватает, раскладка обязана предпочесть перенос, прокрутку, переформатирование или сокращение необязательных отступов — но не дальнейшее уменьшение.

Кривая и пороги принадлежат теме и общие для всех виджетов: стиль `body` не может дать разный физический размер в кнопке и в подсказке.

## 11. Минимальная поддерживаемая цель

**1280 × 720.** На ней UI обязан сохранять доступность всех обязательных элементов управления, не терять критический текст, не создавать недостижимого контента, использовать прокрутку и перенос там, где контент не помещается, соблюдать минимальный читаемый размер и сохранять работоспособность навигации мышью, клавиатурой и геймпадом.

Это не «должно выглядеть так же», а «должно оставаться пригодным к использованию».

## 12. Матрица проверок

| Разрешение | Пропорция |
|---|---|
| 3840 × 2160 | 16:9 |
| 2560 × 1440 | 16:9 |
| 1920 × 1080 | 16:9 |
| 1280 × 720 | 16:9 |
| 3440 × 1440 | 21:9 |
| 2560 × 1080 | 21:9 |

На каждом размере проверяются: раскладка, читаемость текста, навигация вводом, отсутствие обрезки обязательных элементов, поведение прокрутки, сохранение пропорций изображений, границы девятислайса, минимальные размеры, размещение модалки и подсказки.

Отдельно проверяется, что одинаковый семантический стиль даёт одинаковый физический размер во всех виджетах и что одинаковый `resource_id` разрешается одинаково везде, где применим, включая состояние загрузки, отсутствующий ресурс и запасное представление.

## 13. Не входит в предложение

- Элементы без потребителя — вынесены в [Core UI Extended Element Set](CoreUiExtendedElementSetProposal.md).
- Внешний редактор экранов: экраны собираются в UMG из примитивов и композитов.
- Универсальный фреймворк произвольных графов, деревьев, календарей и диаграмм.
- Автоматический подъём игрового композита уровнем выше.
- Значения безопасной области для ТВ и мобильных платформ.
- Портретная ориентация.
- Пользовательский множитель размера текста поверх кривой.

## 14. Критерии приёмки

1. Базовый набор `core` документирован и не содержит игровых понятий.
2. Композиты `textsystem` и `rh` собираются только из примитивов `core` и композитов своего или нижнего слоя.
3. Ни один элемент не обходит конвейеры текста и графики; проверяется по полному инвентарю `/Game/UI`.
4. Одинаковый семантический стиль даёт одинаковый физический размер во всех виджетах.
5. Одинаковый `resource_id` разрешается одинаково во всех элементах, включая загрузку, отсутствие и запасное представление.
6. Разрешение авторинга растра и единицы раскладки заданы как два разных значения в одном месте.
7. Раскладка распределяет фактический viewport, а не масштабирует кадр целиком.
8. Каждый визуальный примитив объявляет политику масштабирования; отсутствие объявления — ошибка.
9. Несовместимость политики и режима ресурса отклоняется до мутации виджета.
10. Текст масштабируется отдельной нелинейной кривой с минимальным читаемым размером.
11. На 1280 × 720 все обязательные элементы управления доступны, критический текст не потерян, недостижимого контента нет.
12. UI проходит матрицу из шести разрешений, включая две пропорции 21:9.
13. Обобщённый список подчиняется правилу ключей повторяемых элементов.
