# Предложение по контейнерному контуру исполнения

> **Предлагает:** разнести рабочую среду, сборку UE и Unreal Editor по трём контейнерам с узким RPC между ними (`uectl` / `ue-build-service` / `ue-editor-control`), и зафиксировать пять решений, без которых проверки GV2 в такой раскладке деградируют молча.
> **Затрагивает:** [Build and Tooling](../Architecture/BuildAndTooling.md), `AGENTS.md`, приёмочный контур (`Tools/Testing`), Editor API (`Tools/MCP`).
> **Не является нормативным:** до реализации действует текущий contract. Внешний контракт `ue-build-service` версии 1 нормативен в своём репозитории, а не здесь.

## Назначение и область

Внешний пакет `uectl 0.2.2` предлагает раскладку из трёх контейнеров: рабочая среда агентов без UE, сервис сборки с UE и без GPU, Unreal Editor с GPU. Между ними — предзаданные RPC-операции без endpoint произвольных команд.

Инженерная часть предложения самостоятельна и здесь не пересматривается. Предметом являются пять стыков, на которых проверки GV2 перестают доказывать то, что доказывали: два из них ломают приёмку молча, один отменяет единственный разрешённый путь правки ассетов, один меняет модель изоляции, один определяет, что вообще считается полномочием.

## Принятые решения

### A. Сохранённый лог terminal job объявляется полным и авторитетным

**Что.** Контракт API уточняется: best-effort относится только к live-стримингу. Лог завершившегося job полон, и сервер не вправе отдать его усечённым, не провалив job.

**Почему.** `run_ue_acceptance.py` строит множество **discovered** парсингом UE-лога — строки `LogAutomationCommandLine: Display:` в фазе обнаружения, со сверкой против объявленного движком числа (`Found N automation tests based on`). Затем `ue_test_report.py::validate_run` требует совпадения discovered и reported один к одному. Нынешняя формулировка «job metadata авторитетна, log delivery — best-effort» разрешает соответствующему контракту серверу отдать неполный лог, не провалив job: приёмка при этом становится зелёной, не проверив состав прогона. Это ровно тот отказ, ради которого заведены `VERIFY-AF-01`/`VERIFY-AF-02`.

**Цена.** Один абзац контракта. Клиент готов: `uectl` дочитывает offset-чанки до EOF для terminal job.

### B. Приёмка GV2 исполняется именованным серверным шаблоном

**Что.** В registry проекта заводится шаблон приёмки с фиксированным серверным argv, соответствующим раннеру GV2: `Automation RunTests <filter>` (не `RunTest`), явный `-abslog`, экспорт отчёта, семантика fresh-process. Сервер сам вычисляет `build_fingerprint` и `source_diff_hash` и кладёт их в metadata job.

**Почему.** Штатный шаблон `test` из контракта выражает другой прогон, а `build_fingerprint` и `source_diff_hash` вычисляет сам раннер — под сервисом его в контуре нет. Без них прогон перестаёт быть привязан к ревизии и к собранному бинарнику, то есть «прогнали на этом коде» и «прогнали на чём-то» становятся неразличимы.

**Почему это не нарушает запрет произвольных команд.** argv остаётся серверным и предзаданным; клиент по-прежнему не передаёт ни путей, ни команд. Меняется только то, что шаблонов становится больше одного и они именованы по проекту.

### C. Editor API выводится в сеть `ue-control`

**Что.** Порт MCP (`8000`) становится доступен в сети `ue-control`; `UNREAL_MCP_URL` указывает на хост Editor.

**Почему.** Правило `AGENTS.md` — `.uasset` создаётся и изменяется **только** через Editor API — остаётся в силе. Без этого канала оно становится невыполнимым, а невыполнимое правило не защищает, а вытесняется обходом.

**Обязательное условие.** Раздел границ безопасности внешнего дизайна обязан признать, что рабочая среда получает широкий канал управления Editor. Сейчас он утверждает обратное, и это расхождение опаснее самого канала: решение, принятое по неверному описанию границы, нельзя пересмотреть, потому что никто не знает, что его принимали.

**Цена на стороне GV2 нулевая.** `Tools/MCP/*` уже читают `UNREAL_MCP_URL`; жёстко задан только клиентский `.mcp.json`, который не является кодом проекта.

### D. Worktree не используются: все работают в одном каталоге

**Что.** Изоляция по `/worktrees/<project>/<workspace>` не применяется. Контекст всегда `workspace=main`.

**Почему.** Решение владельца проекта: стоимость и сложность параллельных рабочих копий не окупаются при фактическом режиме работы.

**Что это переносит на другие механизмы.** Блокировка workspace из внешнего дизайна перестаёт быть удобством и становится **несущей**: она остаётся единственным, что разделяет одновременные сборки, и защищает теперь общее дерево, а не изолированные. Одновременная внешняя сборка при активном Editor больше не разводится по разным каталогам — `Binaries/` и `Intermediate/` у них общие, и порядок «остановить Editor перед внешней сборкой» становится частью процедуры, а не рекомендацией.

**Риск записывается, а не обходится.** Прецедент в этом проекте есть: параллельные сессии в одном рабочем дереве требовали ручной дисциплины со staging — коммитить только свои файлы, не собирать поверх чужой незавершённой работы. С отказом от worktree риск не исчезает, а смещается в git index и в общие каталоги сборки. Смягчение — один пишущий в момент времени и блокировка workspace; механической защиты от нарушения этого порядка предложение не вводит.

**Выигрыш.** Около 1,9 ГБ на несозданный workspace (`Intermediate` 1,4 ГБ + `Binaries` 448 МБ по текущему замеру) и отсутствие второго дерева, которое надо синхронизировать.

### E. Состав сети `ue-control` объявляется инвариантом

**Что.** Аутентификации между контейнерами нет намеренно. Следствие фиксируется прямо: **членство в сети `ue-control` и есть полномочие** собирать и управлять Editor.

**Кто следит.** Соблюдение состава сети контролирует внешняя система. Проверки внутри GV2 это предложение не вводит: инвариант принадлежит инфраструктуре, а не репозиторию, и дублирующий тест здесь давал бы ложное чувство, что репозиторий за него отвечает.

## Что меняется в GV2

| Что | Где | Состояние |
|---|---|---|
| Путь к движку | `UE_ROOT`, `DEFAULT_UE_ROOT` в двух файлах | Готово: значение по умолчанию собрано в одну константу на файл |
| Endpoint Editor API | `UNREAL_MCP_URL` | Готово: инструменты читают переменную; правило в `AGENTS.md` больше не предполагает локальный Editor |
| Контур исполнения проверок | [Build and Tooling § Где какая проверка исполняется](../Architecture/BuildAndTooling.md) | Готово: три группы по требованиям к окружению зафиксированы нормативно |
| Источник приёмочного evidence | `Tools/Testing/run_ue_acceptance.py`, `ue_test_report.py` | Открыто: решить, исполняется ли раннер внутри сервиса или заменяется шаблоном registry (решение B) |
| Клиентский MCP-конфиг | `.mcp.json` | Открыто: хост Editor вместо `127.0.0.1` |

Нумерованные требования к контуру, включая `ue-build-service`, вынесены в `Tools/UECtl/GV2-REQUIREMENTS.md` — рядом с вендоренным пакетом, который они ограничивают.

Портативная группа проверок (134 CTest, включая Python-гейты по `Source/GV2/**`) Unreal не требует и остаётся в среде, где правится код. Это уже нормативно и от контейнерной раскладки не зависит.

## Польза, риски и трудоёмкость

**Польза.** Рабочая среда перестаёт нуждаться в установленном движке; сборка и Editor получают разные обязанности и разные права; отсутствует endpoint произвольных команд.

**Риски.** Отказ от worktree концентрирует конкурентный доступ на одном дереве (решение D). Вывод Editor API в сеть расширяет доступную из рабочей среды поверхность (решение C). Оба приняты осознанно и записаны здесь вместе с ценой.

**Трудоёмкость.** **M** — несколько компонентов и обязательная сверка приёмочного контура; нового shared subsystem в GV2 не появляется.

## Не входит в предложение

Реализация `ue-build-service`; выбор образов и compose; политика хранения на Unraid; Live Coding RPC; изменение исходников Epic Engine; перенос портативной группы проверок в сервис сборки.

## Критерии приёмки

- Контракт API называет сохранённый лог terminal job полным и авторитетным; best-effort ограничен live-стримингом.
- Приёмка GV2 воспроизводится через именованный серверный шаблон: множество automation test id, `build_fingerprint` и `source_diff_hash` совпадают с локальным fresh-process прогоном на той же ревизии.
- `validate_run` проходит на evidence, полученном из `artifact_paths`, без ослабления сверки discovered и reported.
- `.uasset` правится из рабочей среды через Editor API по `UNREAL_MCP_URL`; правило `AGENTS.md` не получает исключений.
- Границы безопасности внешнего дизайна описывают фактический канал управления Editor.
- Портативные 134 CTest исполняются в среде правки кода и проходят.
