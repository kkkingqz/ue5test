# Предложение по расширенному набору элементов Core UI

> **Предлагает:** отложенный набор базовых элементов интерфейса, каждый из которых вводится вместе со своим первым потребителем.
> **Затрагивает:** [Screen Templates](../UI/ScreenTemplates.md), [Core UI Baseline](CoreUIBaselineAndScalingProposal.md).
> **Не является нормативным:** до реализации действует текущий contract.

## 1. Назначение

Разбор базового набора Core UI перечислил около пятнадцати элементов. Часть из них нужна текущим экранам и работам по слоям и вкладкам — она вошла в [Core UI Baseline](CoreUIBaselineAndScalingProposal.md). У остальных **потребителя сегодня нет ни на одном экране**.

Этот документ хранит их, чтобы решение не пришлось принимать заново, и задаёт условие включения каждого.

## 2. Почему они отложены

[ADR-0026](../ADR/0026-core-and-gameplay-ownership.md) отвергает создание подсистем «заранее»: применимость доказывается вторым потребителем, а не ожиданием. По этому же правилу проект отказался от Quest foundation и от сервисов инвентаря и боя.

Виджет отличается от подсистемы только тем, что кажется дешёвым. На деле каждый элемент базового набора несёт контракт Screen Field, адаптер, тему, поведение при масштабировании, проверку в матрице из шести разрешений и обязательство совместимости — и всё это придётся сопровождать до появления первого экрана, который его использует.

Отложенный элемент не является отвергнутым. Он ждёт потребителя.

## 3. Состав и условия включения

| Элемент | Вводится вместе с |
|---|---|
| `Slider` | Первым экраном настроек либо непрерывной величиной, которую игрок задаёт |
| `Stepper` / числовой ввод | Первой операцией с количеством: покупка нескольких предметов, разделение стопки |
| `Toggle` / переключатель | Первой настройкой с двумя состояниями, если её не покрывает существующий `Checkbox` |
| `ContextMenu` | Первым экраном, где у элемента больше двух действий и они не помещаются кнопками |
| `Toast` / уведомление | Первым уведомлением, которое не должно прерывать игрока модалкой |
| `GridList` | Первым экраном с двумерным размещением: инвентарь, карта, набор ячеек |
| `Tooltip` за пределами текстовых фрагментов | Первым нетекстовым элементом, которому нужна всплывающая подсказка |

## 4. Правила включения

1. Элемент вводится тем же change set, что и его первый потребитель, а не заранее и не отдельным заходом.
2. Элемент подчиняется всем правилам [Core UI Baseline](CoreUIBaselineAndScalingProposal.md): единые конвейеры текста и графики, явная политика масштабирования примитива, проверка режимом ресурса, участие в матрице из шести разрешений.
3. Элемент, оказавшийся нужным только одной игре, принадлежит её пакету, а не `core`. Критерий трёх вопросов применяется до, а не после реализации.
4. Появление потребителя переносит строку из этого документа в план — сам документ при этом не становится источником задач.

## 5. Не входит

- Реализация без потребителя — это и есть предмет отказа.
- Универсальные фреймворки графов, деревьев, календарей и диаграмм.
- Элементы, дублирующие уже существующие: второй вид кнопки, второй вид списка.

## 6. Критерии приёмки

Документ считается отработавшим, когда каждая строка таблицы либо реализована вместе со своим потребителем, либо признана ненужной и удалена с указанием причины.

Отдельного признака завершённости у него нет: это очередь, а не задача.
