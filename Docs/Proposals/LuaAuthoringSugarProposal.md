# Предложение по Lua-сахару для авторов геймплея

> **Предлагает:** тонкий Lua-слой над фасадом `game`, сокращающий запись типовых геймплейных операций.
> **Затрагивает:** [Lua Runtime Contract](../Architecture/LuaRuntimeContract.md), [Commands and Events](../Architecture/CommandsAndEvents.md).
> **Не является нормативным:** до реализации действует текущий contract.

Документ выделен из `Human-Friendly Gameplay Authoring Layer v2` — той его части, которая не требует изменения нормативных правил. Часть про формат статических definitions отклонена (см. «Отклонённые предложения»), часть про визуальный редактор — в [Content Editor Plugin](ContentEditorPluginProposal.md).

## Назначение и область

Типовая операция автора концептуально проста, а её запись через фасад — нет:

```lua
game.runtime.dispatch_command({
    command_id = "core:command.location.travel",
    args = { target_location_id = "rh:location.city.tavern" },
})
```

Предлагается модуль-сахар, дающий короткую форму той же операции. Сахар **вызывает фасад** и не вводит ни нового пути мутации, ни нового формата данных, ни новых сущностей в состоянии.

Область — только Lua. Формат definitions, схемы и Stable ID не меняются.

## Состояние на входе

Фасад устроен так (важно, потому что исходное предложение описывало несуществующий API):

| Что | Как называется на самом деле |
|---|---|
| Отправить команду | `game.runtime.dispatch_command({ command_id = …, args = {…} })` |
| Отложить команду | `game.commands.enqueue{…}` |
| Зарегистрировать обработчик | `game.commands.handlers.register(command_id, fn, opts)` |
| Зарегистрировать валидатор | `game.commands.validators.register(id, impl, opts)` |
| Получить актора | `game.instances.actors.get(instance_id)`, `.player()`, `.list(filter)` |
| Прочитать definition | `game.repository.get(id)` / `.require(id)` / `.list(kind)` |

`game.commands.execute` не существует; аргументы команды лежат в `args`, а не разложены плоско в конверте.

Доменные методы на обёртке уже работают: пакет регистрирует декоратор через `game.instances.actors.register_type(discriminator, decorator)` ([ADR-0026](../ADR/0026-core-and-gameplay-ownership.md)), поэтому `player():add_gold(10)` доступно и сахара не требует.

## Принятые решения

- **Механизм в ядре, привязка к namespace — в пакете.** Резолвер коротких ссылок универсален и живёт в `core`; пакет создаёт его экземпляр со своим namespace. Модуль ядра, знающий про `rh`, нарушал бы [ADR-0026](../ADR/0026-core-and-gameplay-ownership.md).
- **Короткая форма экономит namespace и kind, но не path.** В реальном контенте предмет — `rh:item.weapon.iron_sword`, поэтому `item("weapon.iron_sword")`, а не `item("iron_sword")`. Исходное предложение показывало второе; это работает только пока путь состоит из одного сегмента, и ломается на первом же `weapon.`.
- **Definition и instance различаются именем функции, а не контекстом.** `def.actor("aria")` возвращает canonical ID (строку). `instances.of(...)` возвращает список обёрток. Формы, возвращающей «того самого актора» по имени definition, не будет: она молча ломается на втором стражнике и ломается в рантайме, а не при проверке.
- **Сахар не пишет в состояние.** Любое изменение проходит через `dispatch_command`. Удобная запись не должна становиться обходным путём мимо валидаторов и окна мутации.
- **Диагностика человекочитаема, но детерминирована.** Подсказки вида «возможно, имелось в виду …» допустимы, если их порядок и выбор не зависят от обхода хеш-таблиц: диагностики входят в [INV-011](../Architecture/Invariants.md).

## Предлагаемая поверхность

```lua
local a = require("rh:module.authoring")

-- Ссылки: namespace и kind подставляются, path пишется целиком
a.def.actor("aria")                  --> "rh:actor.aria"
a.def.item("weapon.iron_sword")      --> "rh:item.weapon.iron_sword"
a.def.location("city.tavern")        --> "rh:location.city.tavern"

-- Чужой пакет остаётся явным
a.def.screen("core:screen.recovery") --> "core:screen.recovery"

-- Экземпляры
a.player()                           --> обёртка актора игрока или nil
a.instances.of("actor", "aria")      --> список обёрток по definition

-- Команды
a.run("location.travel", { target_location_id = a.def.location("city.tavern") })
a.later("shop.buy", { item_id = a.def.item("weapon.iron_sword") })
```

`a.run` собирает конверт и вызывает `game.runtime.dispatch_command`; `a.later` — `game.commands.enqueue`. Имя команды разрешается тем же резолвером: `"location.travel"` → `rh:command.location.travel`, а команда ядра указывается полностью.

Ошибка разрешения (`path` не является валидным сегментом, kind не совпал, ссылка на несуществующий definition) даёт типизированный отказ с указанием исходной короткой формы и того, во что она развернулась.

## Что сахар не делает

- Не читает и не пишет `game.state` напрямую.
- Не регистрирует команды, валидаторы и подписки — для этого есть реестры.
- Не кэширует обёртки: они одноразовые по контракту.
- Не подменяет `game.repository` — сахар отдаёт ID, читает по ним фасад.
- Не работает вне пакета, объявившего его зависимостью: сахар — обычный модуль, видимый в манифесте.

## Отклонённые предложения

Из исходного документа отклонено всё, что касается формата статических definitions. Причина общая: перечисленное требует правки нормативных правил ради экономии нескольких символов в файле, который автор пишет один раз, а читает инструмент.

| Предложение | Почему отклонено |
|---|---|
| Вывод `namespace`/`kind`/`path` из пути файла (`actors/aria.json5` → `rh:actor.aria`) | Прямо противоречит «Kind не выводится из directory» ([Stable ID Specification](../Architecture/StableIDSpecification.md)) и «`definition_type` не выводится из filename/path» ([Definition Envelope](../Architecture/DefinitionEnvelopeAndSchemaRules.md)). Правило существует, чтобы identity не зависела от того, как распаковали дерево — по той же причине в PKG-01 убрали вывод `package_id` из имени каталога |
| Упрощённый конверт `{ runtime_type: "npc", hp: 100 }` | Конверт закрыт: root допускает только `schema_version`, `type`, `definitions`, `extensions` |
| Сокращённые ссылки вида `"location:tavern"` | Это не сокращение Stable ID, а другая нотация: грамматика требует `namespace:kind.path`, точки в форме нет вовсе |

**Формат ссылок остаётся единым: `rh:location.city.tavern` везде** — в definitions, в Lua, в диагностике, в инструментах. Сокращения существуют только внутри Lua-сахара как аргументы функций и никогда не попадают в файлы контента.

## Проверки

Всё выразимо в Lua, поэтому проверяется спеками `Tests/Lua/` ([ADR-0024](../ADR/0024-lua-spec-runner.md)); C++ не затрагивается вовсе.

Обязательные случаи: разрешение короткой формы для каждого kind; сохранение полной формы чужого пакета без изменений; отказ на невалидный сегмент; отказ на несовпадение kind; отсутствие мутации состояния при отказе команды; детерминированность порядка подсказок в диагностике.

## Этапы

1. **Резолвер и ссылки** — модуль ядра, создающий резолвер по namespace, и его экземпляр в `rh`. Чистые функции, состояния не касаются.
2. **Экземпляры и команды** — `player()`, `instances.of`, `run`, `later`.
3. **Доменные помощники пакета** — короткие обёртки над сервисами `rh` поверх уже готовых декораторов.

Этапы независимы по риску: первый не может ничего сломать, второй трогает путь команд, третий целиком внутри пакета.

## Польза, риски и трудоёмкость

**Польза.** Снимает основную часть боли, названной в исходном предложении, не трогая ни одного нормативного правила и ни одной строки C++.

**Трудоёмкость: S.** Два Lua-модуля и набор спеков.

**Риск: сахар начнёт обрастать логикой.** Мера — правило «сахар только сокращает запись»: любая функция, принимающая решение о том, что произойдёт в игре, принадлежит сервису пакета, а не сахару.

**Риск: две формы записи в кодовой базе.** Часть модулей будет писать через фасад, часть через сахар. Мера — сахар предназначен геймплейным модулям пакета; модули ядра и спеки, проверяющие сам фасад, продолжают использовать фасад напрямую.

**Риск: короткая форма попадёт в контент.** Мера — резолвер существует только в Lua и не участвует в разборе definitions; проверка `gv2-content validate` отвергнет короткую форму в файле как невалидный Stable ID.

## Критерии приёмки

- Геймплейный модуль пакета выражает переход, покупку и награду без единого полного Stable ID в теле функции.
- Короткая форма чужого пакета невозможна: полная форма проходит как есть, короткая с чужим namespace отвергается.
- Попытка изменить состояние из сахара мимо команды невозможна структурно: такой функции нет.
- Ни одна короткая форма не встречается в `GameData/`.
- Спеки покрывают каждый класс отказа резолвера.
