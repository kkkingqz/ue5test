# Внешнее ревью 2026-08-23: итог раунда

> **Показывает:** исторический итог раунда внешнего ревью; документ не является источником правил или задач.

## Охват и метод

Внешнее ревью состояния `main` на commit `93bc1e1a11890189188c4b554174f3d39f3795a7`, полученное после закрытия раунда [PlanAudit2026-08](PlanAudit2026-08.md). Ревью проверяло корректность утверждений, закрытых предыдущим раундом, и искало новые дефекты.

Каждое утверждение ревью проверялось по текущему коду, а не принималось на веру: находка признавалась подтверждённой только после нахождения конкретного места в источнике. Раунд прошёл в два прохода — основной документ и последующая проверка результатов исправления.

## Второй проход

Проверка результатов исправления. Все пять утверждений подтверждены по коду и устранены одним change set.

| Находка | Исход |
|---|---|
| `percent` у `meters` не проверяется по типу и диапазону на границе | Устранена. Подтверждена сильнее заявленного: `math.min(1, stamina / 100)` в Lua возвращает целое при полном значении, поэтому шкала выносливости показывала ноль ровно при 100% |
| `BAI-08` не применил общую грамматику ключа к `meters` и `characters` | Устранена. Утверждение итога плана «грамматика едина» было ложным; в сводке плана проставлена поправка |
| Позиционная идентичность `item_N` противоречит запрету отката к индексу массива | Устранена. Коллекции переведены на `{key, resource_id}` с `instance_id` в качестве ключа; отменённое решение помечено в сводке плана |
| Презентер выводит идентичность персонажа из `resource_id`, и весь контент RH идёт по этой ветке | Устранена. Персонаж получил семантический ключ, legacy-путь удалён из презентера и схемы расширения |
| Типографская проверка измеряет фактических потребителей только на 1080p | Устранена. Прогон на 720/1080/1440/2160 |

## Что раунд говорит о методе

Три из четырёх находок первого прохода уровня P1 — одна и та же форма: зелёный тест, доказывающий более слабое свойство, чем заявлено. Два ложных утверждения обнаружились не в коде, а в собственных сводках закрытых планов, причём одно из них было написано по итогам предыдущего раунда проверки. Из этого в `AGENTS.md` выведено правило подтверждения Definition of Done, а в [Add Screen Field](../../Guides/AddScreenField.md) — обязательная сверка ключей границы в обе стороны.
