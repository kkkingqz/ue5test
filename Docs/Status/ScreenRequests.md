# Заявки на экраны и UI-поля

> **Показывает:** экраны и поля Screen Template, которых не хватает геймплею пакетов; документ описывает потребность и не вводит новых правил.

Геймплей по умолчанию использует существующий `textsystem:screen.location` и модальное окно `core:screen.modal_confirm`. Если игре нужен другой экран или новое поле, геймплей не ссылается на несуществующий template, а заявка записывается сюда: назначение, поля и их значения, stable keys, команды. Реализация — Widget Blueprint, schema и запись в Screen Registry — выполняется отдельно.

Формат записи: назначение, затронутый template/schema, поля, поведение, источник данных, связанные пробелы, статус.

Порядок реализации — этап Э3 плана [Engine Gap Closure](../Plans/EngineGapClosure/Screens.md), который начинается после полного закрытия этапа по движку.

## SR-001. Неактивный пункт меню с подсказкой о причине

- **Назначение:** действие, которое сейчас недоступно (не хватает выносливости, нет нужного предмета, NPC занят), остаётся видимым в меню локации, но неактивно; при наведении показывается причина.
- **Template и schema:** `textsystem:screen.location`, поле `commands`, schema `textsystem:schema.ui_field.location_commands.v1` → новая версия схемы (`v2`), так как меняется состав элемента.
- **Поля элемента `items[]`:**

| Поле | Kind | Обязательно | Значение |
|---|---|---|---|
| `key` | key | да | как сейчас: stable identity пункта |
| `text` | text | да | как сейчас: подпись действия |
| `binding` | binding | нет | как сейчас; у неактивного пункта отсутствует |
| `enabled` | boolean | нет, по умолчанию `true` | `false` — пункт виден, но не нажимается и визуально отличается (style state `disabled`) |
| `disabled_reason` | text | нет | `TextSpec` причины; показывается подсказкой при наведении только у неактивного пункта |

- **Поведение:**
  - Неактивный пункт не отправляет Semantic Input. Это только presentation: команда всё равно перепроверяет условия ([Semantic Input](../UI/SemanticInput.md)), отказ даёт typed refusal.
  - Подсказка — UE-local hover surface без вызова Lua, по той же модели, что hover у RichText ([UI Document](../UI/UIDocumentAndReconciliation.md)).
  - Смена `enabled` у пункта с тем же `key` обновляет существующий виджет, а не пересоздаёт его.
- **Источник данных:** источники действий меню из `rh` возвращают для каждого пункта доступность и причину ([GAP-006](EngineGaps.md#gap-006-сборка-меню-локации-из-источников-действий)).
- **Связано:** строка «Tooltip за пределами текстовых фрагментов» в [Core UI Extended Element Set](../Proposals/CoreUiExtendedElementSetProposal.md) — эта заявка является её первым потребителем.
- **Статус:** open.

## SR-002. Отчёт о конце хода

- **Назначение:** показать игроку, что произошло в конце хода. Каждая фаза конца хода (модели NPC, процессы, эффекты и т. д.) возвращает результат — картинку и описание — либо пустой результат. Экран показывает непустые результаты; если все результаты пустые, экран не открывается.
- **Template:** новый Screen Template, условно `textsystem:screen.turn_report`, в слое `location_content`: отдельный экран вместо экрана локации, а не модальное окно. Template общий (`textsystem`): формат «картинка + описание» не зависит от правил `rh`.
- **Зависимость:** показ в основном слое требует маршрутизации экрана активного режима ([GAP-001](EngineGaps.md#gap-001-presentation-router-с-регистрацией-view-provider-из-пакета), [Temporary Game Modes](../Proposals/TemporaryGameModesProposal.md)): без неё `location_presenter` перестраивает route после каждой команды и заменяет отчёт. Отчёт — временный режим `rh` (условно `rh:mode.turn_report`), чей `view` строит этот экран.
- **Поля:**

| Поле | Schema / kind | Обязательно | Значение |
|---|---|---|---|
| `title` | text | да | заголовок отчёта, например «Прошла ночь» |
| `entries` | новая schema, условно `textsystem:schema.ui_field.report_entries.v1`, keyed array | да, не пустой | результаты фаз в порядке исполнения |
| `entries[].key` | key | да | stable identity записи: ID фазы и её результата, не индекс и не текст |
| `entries[].resource_id` | ref на resource | нет | картинка результата; отсутствует — запись без картинки (не заглушка) |
| `entries[].text` | text | да | `TextSpec` описания с параметрами (`{amount}`, `{actor_name}`) |
| `buttons` | `core:schema.ui_field.button_list.v2` | да | кнопки последней записи, минимум «Продолжить» |

- **Поведение:**
  - Записи показываются по одной: картинка и описание текущей записи, кнопка «Далее» переходит к следующей. Номер текущей записи — UE-local state, как scroll или выбранная вкладка: «Далее» не вызывает Lua и не создаёт новую revision документа.
  - На последней записи вместо «Далее» показывается кнопка из поля `buttons` («Продолжить»). Она привязана к команде `rh`, которая завершает режим отчёта и возвращает экран локации. `rh:command.turn.end` запускает режим отчёта только при непустом списке.
  - Подпись «Далее» — текст template (`textsystem`), а не значение из Lua.
  - Отчёт — только presentation: результаты уже применены к canonical state командой конца хода. Сохранять отчёт после закрытия не требуется.
- **Источник данных:** фазы конца хода в `rh` возвращают `{ resource_id?, text }` или `nil`.
- **Ресурсы:** картинки и тексты конкретных результатов заводятся по правилам заявок на ресурсы.
- **Статус:** open.

## SR-003. Экран магазина

- **Назначение:** кнопка на локации открывает магазин; игрок видит ассортимент с описаниями и ценами и покупает предметы. Ассортимент, цены и описания — данные `rh`; запас бесконечный, цены фиксированные.
- **Template:** новый Screen Template, условно `textsystem:screen.shop`, в слое `location_content` как экран временного режима магазина ([GAP-001](EngineGaps.md#gap-001-presentation-router-с-регистрацией-view-provider-из-пакета)). Template общий: структура «список товаров с ценой и покупкой» не зависит от правил `rh`.
- **Поля:**

| Поле | Schema / kind | Обязательно | Значение |
|---|---|---|---|
| `title` | text | да | название магазина |
| `description` | text | нет | описание магазина или реплика торговца |
| `merchant_portrait_resource_id` | ref на resource | нет | портрет торговца |
| `balance` | text | да | деньги игрока, например «Золото: {gold}» |
| `items` | новая schema, keyed array | да | товары в порядке из данных |
| `items[].key` | key | да | Stable ID Definition предмета |
| `items[].icon_resource_id` | ref на resource | нет | иконка предмета |
| `items[].name` | text | да | название предмета |
| `items[].description` | text | нет | описание предмета |
| `items[].price` | text | да | цена, например «{price} зол.» |
| `items[].binding` | binding | нет | покупка этого предмета; отсутствует у неактивного товара |
| `items[].enabled` | boolean | нет, по умолчанию `true` | `false` — товар виден, кнопка покупки неактивна |
| `items[].disabled_reason` | text | нет | причина неактивности при наведении, например «Не хватает золота» |
| `buttons` | `core:schema.ui_field.button_list.v2` | да | минимум «Уйти» — завершает режим магазина |

- **Поведение:**
  - Описание выбранного товара показывается в области описания; выбор и прокрутка списка — UE-local state.
  - После покупки Lua публикует новую revision того же экрана: меняются `balance` и доступность товаров; `key` товаров не меняются, поэтому выбор и прокрутка сохраняются.
  - Покупка без отдельного подтверждения; неактивность — только presentation, команда покупки перепроверяет деньги.
- **Источник данных:** Definition магазина `rh` (ассортимент) и Definitions предметов (цена, название, описание, иконка).
- **Связано:** [SR-001](#sr-001-неактивный-пункт-меню-с-подсказкой-о-причине) (та же модель неактивного элемента), [GAP-011](EngineGaps.md#gap-011-локализуемые-аргументы-textspec).
- **Статус:** open.

## SR-004. Экран диалога

- **Назначение:** диалог — последовательность экранов «текст + картинка» с кнопкой «Далее» или выбором варианта ответа. Тот же экран выводит результат оценки при продаже и взаимодействия, запущенные реакциями на события.
- **Template:** новый Screen Template, условно `textsystem:screen.dialogue`, в слое `location_content` как экран временного режима диалога ([GAP-001](EngineGaps.md#gap-001-presentation-router-с-регистрацией-view-provider-из-пакета)).
- **Поля:**

| Поле | Schema / kind | Обязательно | Значение |
|---|---|---|---|
| `speaker_name` | text | нет | имя говорящего; отсутствует у реплики рассказчика |
| `speaker_portrait_resource_id` | ref на resource | нет | портрет говорящего |
| `image_resource_id` | ref на resource | нет | картинка шага |
| `text` | text | да | текст шага с параметрами |
| `choices` | новая schema, keyed array | да, не пустой | кнопки шага: один пункт «Далее» или варианты ответа |
| `choices[].key` | key | да | stable ID варианта из данных диалога, не индекс и не текст |
| `choices[].text` | text | да | подпись варианта |
| `choices[].binding` | binding | нет | команда выбора; отсутствует у неактивного варианта |
| `choices[].enabled` | boolean | нет, по умолчанию `true` | неактивный вариант виден, но не нажимается |
| `choices[].disabled_reason` | text | нет | причина при наведении |

- **Поведение:**
  - Каждый шаг диалога — новая revision того же Screen Instance (stable instance key режима), поэтому экран не пересоздаётся между шагами.
  - «Далее» — обычный вариант из `choices` с binding на команду перехода к следующему шагу; отдельной кнопки template не добавляет.
  - Длинный текст прокручивается; прокрутка — UE-local state и сбрасывается при смене шага.
- **Источник данных:** граф диалога в данных `rh`, флаги игрока и NPC ([GAP-008](EngineGaps.md#gap-008-поля-коллекции-и-целостность-ссылок-на-экземпляры)); имя NPC в тексте — [GAP-011](EngineGaps.md#gap-011-локализуемые-аргументы-textspec).
- **Статус:** open.

## SR-005. Экран танца

- **Назначение:** сцена танца с двумя и более участниками-NPC: временные характеристики участников, описание текущего момента и кнопки действий модуля. По завершении результат возвращается участникам, экран закрывается.
- **Template:** новый Screen Template, условно `textsystem:screen.participant_scene`, в слое `location_content` как экран временного режима ([GAP-001](EngineGaps.md#gap-001-presentation-router-с-регистрацией-view-provider-из-пакета)). Структура «участники с показателями + описание + действия» не зависит от танца и подходит для других сценических модулей.
- **Поля:**

| Поле | Schema / kind | Обязательно | Значение |
|---|---|---|---|
| `title` | text | да | название сцены |
| `image_resource_id` | ref на resource | нет | картинка сцены |
| `description` | text | да | описание текущего момента или результата последнего действия |
| `participants` | новая schema, keyed array | да, не меньше двух | участники в порядке передачи в модуль |
| `participants[].key` | key | да | instance ID участника |
| `participants[].name` | text | да | имя участника |
| `participants[].portrait_resource_id` | ref на resource | нет | портрет |
| `participants[].meters` | keyed array полос | да | временные характеристики сцены |
| `participants[].meters[].key` | key | да | ID характеристики сцены |
| `participants[].meters[].label` | text | да | подпись со значением, например «Грация: {value}» |
| `participants[].meters[].percent` | number `[0..1]` | да | заполнение полосы |
| `actions` | keyed array, элемент как у SR-001 (`key`, `text`, `binding`, `enabled`, `disabled_reason`) | да | действия модуля; на последнем шаге — «Завершить» |

- **Поведение:**
  - Каждое действие — новая revision того же Screen Instance; участники и полосы сохраняют widgets по `key`.
  - Временные характеристики существуют только в режиме и не сохраняются; итог записывается участникам одной командой при завершении.
- **Источник данных:** модуль танца `rh`: временные характеристики рассчитываются из базовых характеристик участников ([GAP-012](EngineGaps.md#gap-012-поля-definition-из-блока-расширения-пакета)).
- **Статус:** open.
