# Заявки на экраны и UI-поля

> **Показывает:** экраны и поля Screen Template, которых не хватает геймплею пакетов; документ описывает потребность и не вводит новых правил.

Геймплей по умолчанию использует существующий `textsystem:screen.location` и модальное окно `core:screen.modal_confirm`. Если игре нужен другой экран или новое поле, геймплей не ссылается на несуществующий template, а заявка записывается сюда: назначение, поля и их значения, stable keys, команды. Реализация — Widget Blueprint, schema и запись в Screen Registry — выполняется отдельно.

Формат записи: назначение, затронутый template/schema, поля, поведение, источник данных, связанные пробелы, статус.

## SR-001. Неактивный пункт меню с подсказкой о причине

- **Назначение:** действие, которое сейчас недоступно (не хватает выносливости, нет нужного предмета, NPC занят), остаётся видимым в меню локации, но неактивно; при наведении показывается причина.
- **Template и schema:** `textsystem:screen.location`, поле `commands`, schema `textsystem:schema.ui_field.location_commands.v1` → новая версия схемы (`v2`), так как меняется состав элемента.
- **Поля элемента `items[]`:**

| Поле | Kind | Обязательно | Значение |
|---|---|---|---|
| `key` | key | да | как сейчас: stable identity пункта |
| `text` | text | да | как сейчас: подпись действия |
| `binding` | binding | нет | как сейчас; у неактивного пункта отсутствует |
| `enabled` | boolean | нет, по умолчанию `true` | `false` — пункт виден, но не нажимается и визуально отличается (style state `disabled`) |
| `disabled_reason` | text | нет | `TextSpec` причины; показывается подсказкой при наведении только у неактивного пункта |

- **Поведение:**
  - Неактивный пункт не отправляет Semantic Input. Это только presentation: команда всё равно перепроверяет условия ([Semantic Input](../UI/SemanticInput.md)), отказ даёт typed refusal.
  - Подсказка — UE-local hover surface без вызова Lua, по той же модели, что hover у RichText ([UI Document](../UI/UIDocumentAndReconciliation.md)).
  - Смена `enabled` у пункта с тем же `key` обновляет существующий виджет, а не пересоздаёт его.
- **Источник данных:** источники действий меню из `rh` возвращают для каждого пункта доступность и причину ([GAP-006](EngineGaps.md#gap-006-сборка-меню-локации-из-источников-действий)).
- **Связано:** строка «Tooltip за пределами текстовых фрагментов» в [Core UI Extended Element Set](../Proposals/CoreUiExtendedElementSetProposal.md) — эта заявка является её первым потребителем.
- **Статус:** open.

## SR-002. Отчёт о конце хода

- **Назначение:** показать игроку, что произошло в конце хода. Каждая фаза конца хода (модели NPC, процессы, эффекты и т. д.) возвращает результат — картинку и описание — либо пустой результат. Экран показывает непустые результаты; если все результаты пустые, экран не открывается.
- **Template:** новый Screen Template, условно `textsystem:screen.turn_report`, в слое `modal_stack`: блокирует меню локации, пока игрок не закроет отчёт. Template общий (`textsystem`): формат «картинка + описание» не зависит от правил `rh`.
- **Поля:**

| Поле | Schema / kind | Обязательно | Значение |
|---|---|---|---|
| `title` | text | да | заголовок отчёта, например «Прошла ночь» |
| `entries` | новая schema, условно `textsystem:schema.ui_field.report_entries.v1`, keyed array | да, не пустой | результаты фаз в порядке исполнения |
| `entries[].key` | key | да | stable identity записи: ID фазы и её результата, не индекс и не текст |
| `entries[].resource_id` | ref на resource | нет | картинка результата; отсутствует — запись без картинки (не заглушка) |
| `entries[].text` | text | да | `TextSpec` описания с параметрами (`{amount}`, `{actor_name}`) |
| `buttons` | `core:schema.ui_field.button_list.v2` | да | минимум «Продолжить» |

- **Поведение:**
  - Записей может быть больше, чем помещается на экран: нужна прокрутка списка. Альтернатива — показ по одной записи с «Далее»; выбор формы — открытый вопрос.
  - «Продолжить» привязан к команде пакета, которая закрывает модальное окно (`close_modal`); новая команда для показа не нужна: `rh:command.turn.end` вызывает `show_modal` с этим template только при непустом списке.
  - Отчёт — только presentation: результаты уже применены к canonical state командой конца хода. Сохранять отчёт после закрытия не требуется.
- **Источник данных:** фазы конца хода в `rh` возвращают `{ resource_id?, text }` или `nil`.
- **Ресурсы:** картинки и тексты конкретных результатов заводятся по правилам заявок на ресурсы.
- **Статус:** open.
