# Добавить доменные методы сущности

> **Задача:** дать категории сущностей доменные методы вместо ручной правки таблиц состояния.
> **Нужно:** понимание разницы definition / экземпляр / обёртка — [RuntimeInstances](../Concepts/RuntimeInstances.md).
> **Нормативно:** [Lua Runtime Contract](../Architecture/LuaRuntimeContract.md), [Canonical State and Save](../Architecture/CanonicalStateAndSave.md), [Commands and Events](../Architecture/CommandsAndEvents.md).

## Шаги

**1. Решить, нужна ли новая категория.** Если сущность уже является актором, достаточно добавить метод существующей обёртке. Новая категория заводится вместе со своей секцией состояния и своим реестром.

**2. Разместить реестр под `game.instances`.** Список полей фасада закрыт: `game.instances.items`, а не `game.items`.

**3. Держать обёртку одноразовой.** Она хранит ссылку на таблицу состояния, не копирует её и не кэшируется:

```lua
function M.wrap(state_entry)
    local wrapper = {}
    setmetatable(wrapper, {
        __index = function(_, key) return state_entry[key] end,
        __newindex = function(_, key, value) state_entry[key] = value end,
    })
    return wrapper
end
```

Metatable здесь не украшение: именно из-за неё сохранить обёртку в состояние невозможно — валидатор отвергнет.

**4. Брать дискриминатор из definition.** Подтип («игрок» или «NPC») читается из definition по `definition_id`, а не дублируется полем в состоянии: два источника истины разойдутся.

**5. Разделить ответственность.** Реестр — identity, поиск, создание, удаление, детерминированное перечисление. Обёртка — локальные операции над одной сущностью. Сервис — сценарии над несколькими.

**6. Определить удаление.** Удаление обязано оставлять дерево валидным: либо отказ при наличии зависимых ссылок, либо явный каскад. Висячий `instance_id` после удаления недопустим.

**7. Добавить спеку.** Полезные кейсы: повторный `get` возвращает другую таблицу; запись через обёртку видна в состоянии; сохранение обёртки в состояние отвергается; удаление с зависимыми ссылками отклоняется.

## Типичные ошибки

**Мутирующие методы в реестре.** `registry.add_gold(id, 20)` превращает реестр в менеджер сущностей. Правильно — `registry.get(id):add_gold(20)`.

**Кеширование обёрток.** До измеренной проблемы производительности не нужно и создаёт вопросы времени жизни при загрузке и перезапуске сессии.

**Копия состояния внутри обёртки.** Тогда появляется вторая версия истины и запись «теряется».

**Новое поле верхнего уровня в фасаде.** Каждая следующая категория расширяла бы фасад — поэтому реестры живут под `game.instances`.
