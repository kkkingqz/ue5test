# ADR-0022: External Translation Catalog

## Context

Текст сейчас является definition kind `text` с обязательным полем `data.message`. Это делает репозиторий владельцем и идентичности текста, и его содержимого.

Для содержимого это плохой формат. Переводчики не работают с JSON5 и schema validation; объём переводов на порядок больше объёма определений; правка перевода меняет `content_hash` репозитория, то есть ломает golden-прогоны и трогает identity контента, хотя на gameplay не влияет вовсе.

При этом идентичность текста трогать нельзя: `text_id` разрешается как typed reference kind `text` против winner set, и опечатка в нём — фатальная диагностика сборки. Это основная страховка автора контента, и её потеря была бы регрессом.

Unreal использует PO как формат обмена с переводчиками (export/import) и `.locres` как скомпилированный рантайм-артефакт. То есть PO не является «своим» форматом в противовес движковому — это ровно тот формат, который движок ожидает для round-trip.

## Decision

- Репозиторий владеет **идентичностью** текста; внешний каталог владеет **содержимым**.
- Definition kind `text` остаётся в репозитории как реестр идентификаторов. Его `data` содержит `source_message` — строку на языке авторинга. Она служит контекстом для переводчика и fallback при отсутствии перевода.
- Переводы хранятся в PO-каталогах внутри package root (`<package-root>/localization/<locale>.po`) и ключуются тем же `text_id`. Discovery пакета их не сканирует: package root по-прежнему определяется каталогами `definitions/` и `schemas/`.
- Переводы не входят в `content_hash`, не пересекают Lua boundary и не участвуют в run digest.
- Резолвинг принадлежит host-у: Lua публикует `TextSpec`, Presentation разрешает его в отображаемый текст. `gv2-headless` переводы не загружает и `TextSpec` не разрешает.
- Физический рантайм-артефакт host-specific и собирается из PO build-шагом. Формат артефакта не является gameplay contract.
- Отсутствующий перевод не является ошибкой сборки: применяется fallback на `source_message`. Полнота перевода — предмет отчёта инструмента, а не gate.

## Consequences

- Правка перевода не меняет identity контента и не ломает golden-прогоны.
- Проверка `text_id` сохраняется без изменений: ссылка по-прежнему резолвится против winner set.
- Схема `text` меняется (`message` → `source_message`), что однократно меняет pinned content hash фикстур и `GameData/core`.
- Мод поставляет свои переводы тем же способом: PO лежит внутри его package root.
- Появляется build-шаг PO → host-артефакт. Он принадлежит tooling и не становится runtime dependency.
- Инструмент проверки полноты перевода не может быть частью `gv2-content validate`, поскольку отсутствие перевода не является невалидным контентом.

## Rejected alternatives

- Оставить содержимое в definitions: сохраняет привязку переводов к identity контента и заставляет переводчика работать с JSON5 и schema validation.
- Убрать kind `text` из репозитория целиком: ломает проверку `text_id` и лишает автора единственной автоматической защиты от опечатки в ссылке на текст.
- Хранить переводы в UE String Table как источнике истины: делает переводы editor-only, недоступными вне UE, и нарушает портируемость исходников.
- CSV вместо PO: ломается на многострочных текстах, не имеет контекста и множественных форм, не поддерживается инструментами переводчиков.
