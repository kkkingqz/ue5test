# ADR-0020: C++ Scope Criterion

## Context

Изначальный замысел проекта — тонкий C++ и вся логика в Lua — никогда не был записан
как проверяемое правило. Документация фиксировала только смежное требование
«C++ не владеет gameplay-state и не содержит доменной модели» (ADR-0001), и оно
соблюдается буквально: в проекте нет ни одного класса `Item`, `Quest` или `Location`.

Но требования «делать в C++ только необходимое» не существовало, поэтому ни одно
решение против него не проверялось. Каждое отдельное «реализуем это в C++»
выглядело обоснованным, а суммарный объём никто не измерял. Замер на 2026-08-14:

```text
GV2ContentCore        10 000
GV2 (UE presentation)  6 885
GV2RuntimeCore         3 946
gv2-headless           1 100
gv2-content              704
GV2ContentHostSupport    205
Lua                      425
```

Соотношение production-кода ≈ 54:1. Часть этого объёма неизбежна (UMG, VM host,
repository build до создания первой VM), часть накопилась по одному локально
разумному решению за раз.

Лозунг «минимум C++» непроверяем и потому бесполезен как правило: он не отвечает
на вопрос о конкретном изменении. Нужен критерий, применимый к одному решению.

## Decision

Код принадлежит C++ только если выполнено хотя бы одно условие:

1. он требует возможности, которых у Lua нет по trust model — файловая система,
   процесс, потоки, native libraries, UObject/UMG/Slate, платформенные API;
2. он обязан работать до создания Lua VM либо без неё вовсе.

Всё остальное принадлежит Lua.

Данные пересекают C++/Lua boundary минимальным возможным представлением:
скаляр вместо структуры, идентификатор вместо объекта, непрозрачные байты вместо
разобранного дерева. Расширение boundary требует обоснования, что более узкое
представление не решает задачу.

Критерий применяется к новым решениям. Он не является требованием переписать
существующий код: соответствие проверяется при изменении области, а не ретроспективно.

## Consequences

- Появляется один вопрос, который обязан быть задан в review любого нового C++
  модуля или функции: какое из двух условий выполнено. Отсутствие ответа —
  дефект проектирования, а не стилистическое замечание.
- Умолчание меняется: при равных прочих реализация выбирается в Lua.
- `GV2ContentCore` проходит по условию 2 — repository строится до первой VM,
  а `gv2-content` работает вообще без Lua. Модуль остаётся как есть.
- `GV2` (UMG) и VM host в `GV2RuntimeCore` проходят по условию 1.
- Части `GV2RuntimeCore`, занятые сериализацией и хэшированием run manifest/digest,
  критерию не удовлетворяют: это работа, которую Lua выполняет естественно.
  Переписывание не является обязательным, но при следующем изменении этой области
  выбор в пользу Lua является умолчанием.
- Save/load пересматривается отдельным решением: передача разобранного state tree
  в C++ противоречит правилу о минимальном представлении (ADR-0021).

## Rejected alternatives

- Записать «минимум C++» как принцип без критерия: непроверяемо, не даёт ответа
  о конкретном изменении и повторяет исходную проблему.
- Ретроспективная ревизия существующих модулей: `GV2ContentCore` покрыт тестами
  и проходит критерий по условию 2; стоимость переписывания не оправдана.
- Оставить только ADR-0001: он ограничивает authority, но не объём, и текущее
  распределение кода ему не противоречит.
