# ADR-0023: Stable ID Publication Freeze and Authoring Lifecycle

## Context

Контракты архитектуры ([ADR-0002](0002-stable-id-format.md), [Stable ID Specification](../Architecture/StableIDSpecification.md), `AGENTS.md`) фиксируют инвариант: «Опубликованный Stable ID не переиспользуется для другого смысла; rename использует owner-declared redirect; удаление использует tombstone».

Однако в процессе локальной разработки и создания контента (authoring phase) идентификаторы ещё не зафиксированы в релизах, внешних сохранениях игроков или сторонних модах. Требование создавать постоянные `redirects` и `tombstones` на каждую черновую правку автора до выпуска пакета загрязняет дескриптор пакета мусорными редиректами и блокирует естественный рефакторинг контента.

## Decision

Разграничить жизненный цикл Stable ID на две явно выраженные фазы:

1. **Pre-publication (Draft / Authoring phase)** — до публичного релиза / заморозки пакета:
   - Идентификаторы являются подвижными рабочими драфтами.
   - Автор может свободно переименовывать определения на месте с помощью инструмента `gv2-content rename`, который атомарно обновляет определение и все ссылки на него в пределах пакета.
   - Мусорные редиректы и томбстоуны не создаются.

2. **Момент заморозки (Publication Freeze)**:
   - Наступает в момент публикации пакета контента в релиз (поставка игрокам, публикация версии мода, фиксация эталонного манифеста). С этого момента идентификатор считается **опубликованным (Published)**.

3. **Post-publication (Frozen / Production phase)** — после публикации:
   - Безусловный инвариант: опубликованный Stable ID **никогда не переиспользуется для сущности с другим смыслом**.
   - Переименование опубликованного ID в новой версии пакета обязано оформляться через явный `redirect: { "old_id": "new_id" }` в дескрипторе пакета (`package.json5`), обеспечивая миграцию сохранений и обратную совместимость модов.
   - Удаление опубликованного ID обязано оформляться через `tombstone: [ "deleted_id" ]`.
   - Повторное использование retired/tombstoned ID под новым активным определением запрещено и отвергается валидатором репозитория (`core:diagnostic.repository.tombstone.active_definition_conflict`).

## Consequences

- Инструменты автора (`gv2-content rename`, `gv2-content refs`) дают удобный и безопасный рефакторинг до релиза без ручного поиска по файлам.
- Репозиторий контента остаётся чистым и избавлен от черновых редиректов.
- Сохраняется абсолютная детерминированность, версионируемость и целостность опубликованных идентификаторов в релизах.
- `BuildAndTooling.md` и `StableIDSpecification.md` синхронизированы с данным разграничением.
