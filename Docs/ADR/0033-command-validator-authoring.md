# ADR-0033: Command Validator Authoring and Read-Only Policy Enforcement

> **Решение:** авторский синтаксис `validate(command_ref, name, fn)` для независимых read-only политик поверх команд, декодирование аргументов по форме значения без знания игровых имён в ядре, единый execution scope для `fail()`, разрешение target при заморозке и явная заменяемость обработчиков команд.

## Context

Пакеты, модули и моды нуждаются в возможности накладывать независимые ограничения на команды, реализацией которых они не владеют (например, запрет перемещения при проклятии, блокировка торговли в закрытом городе или карантин).

Низкоуровневый реестр валидаторов (`game.commands.validators`) уже существует в runtime, выполняет валидаторы до открытия окна мутации и останавливает dispatch на первом типизированном отказе. Однако:
1. В авторском окружении (`_ENV`) отсутствовал высокоуровневый API объявления валидатора.
2. Функция типизированного отказа `fail()` была доступна только внутри обработчика команды (`active_command_context`) и выбрасывала ошибку при вызове из валидатора.
3. Разрешение целевой команды при объявлении делало бы порядок загрузки файлов частью контракта.
4. Вспомогательное декодирование аргументов в `Scripts/authoring/context.lua` содержало захардкоженный список имён игровых параметров (`target_location_id`, `item_id`, `destination` и др.), что нарушало изоляцию ядра ([INV-016](../Architecture/Invariants.md)).
5. Отсутствовали явные охранники от побочных эффектов в точках презентации, событий и отложенных команд.
6. Замена обработчика команды происходила молча без защиты от случайной перезаписи.

## Decision

1. **Авторский API валидаторов (`validate`)**:
   - В авторское окружение `_ENV` предоставляется функция:
     ```lua
     validate(command_ref, validator_name, validator_fn)
     ```
   - `command_ref` принимает `CommandDescriptor` (например, `commands.travel`) или канонический Stable ID вида `<pkg>:command.<path>`.
   - `validator_name` — непустая строка идентификатора внутри пакета.
   - Валидаторы накапливаются в авторском контексте пакета на этапе загрузки (`register`).

2. **Непрозрачный Stable ID валидатора**:
   - Канонический Stable ID валидатора формируется по формуле:
     `<declaring_package>:validator.<target_namespace>.<target_command_path>.<name>`
   - Идентификатор считается **непрозрачным**: связь с target command не извлекается строковым парсингом, а хранится явным полем записи валидатора.

3. **Декодирование аргументов по форме значения (`decode_authoring_args`)**:
   - Ядро не содержит списков имён игровых параметров.
   - Декодирование `raw_args` выполняется единственной функцией `decode_authoring_args(raw_args)` одинаково для обработчиков и валидаторов:
     - **Массив (`#raw_args > 0`)**: позиционные аргументы. Каждый аргумент, являющийся валидным Stable ID и разрешимым в pinned repository, автоматически оборачивается в definition wrapper (`properties.wrap_definition`).
     - **Пустая таблица (`next(raw_args) == nil`)**: вызов без аргументов.
     - **Иная таблица или скаляр**: передаётся как единственный аргумент (таблица целиком или скаляр).
   - Вызовы действий, передававшие именованные таблицы под старый список ядра (например, `{ target_location_id = conn_id }`), переводятся на позиционную форму `action("...", conn_id)`.

4. **Единый Execution Scope и расширение `fail()`**:
   - Вводится общий стек execution scope: `none | command | validator | event`.
   - Scope хранит `kind`, `package_id`, `command_id` и `initial_write_revision`.
   - `fail(key, params)` доступен как в scope `command`, так и в scope `validator`.
   - В scope `validator` отказ `fail()` формирует типизированную ошибку в пространстве имён **объявившего валидатор пакета** (`<declaring_pkg>:error.<key>`) и совершает non-local exit через внутренний sentinel `FAIL_SENTINEL`.
   - Произвольные ошибки Lua в валидаторе не перехватываются как отказ и остаются runtime fault (`LuaDispatchError`).
   - Проверка `AuthoringFailAfterMutation` действует только для scope `command`, так как окно мутации в момент валидации закрыто.

5. **Разрешение Target Command при заморозке**:
   - Существование целевой команды проверяется однократно при общей заморозке реестров (`freeze`), когда загружены модули всех пакетов.
   - Отсутствие target команды вызывает ошибку сборки `AuthoringValidatorTargetMissing`.
   - Объявление валидатора после заморозки отклоняется `AuthoringValidatorDeclarationAfterFreeze`.

6. **Охранники от побочных эффектов (Read-Only Enforcement)**:
   - Валидатор обязан быть чистой функцией проверки состояния.
   - В scope `validator` вызовы `emit(...)`, `show_screen(...)`, `commands.*:later(...)` и мутирующие операции Gameplay Services отклоняются ошибкой программиста `AuthoringValidatorSideEffectDisallowed`.
   - Мутация состояния и вызов `run(...)` блокируются существующими инвариантами закрытого окна мутации и флага `is_dispatching`.

7. **Явная заменяемость команд**:
   - Обработчики команд по умолчанию запечатаны от переопределения.
   - Повторная регистрация команды без явного флага заменяемости отклоняется ошибкой `CommandNotReplaceable`.
   - Законная замена обработчика сохраняет валидаторы, объявленные другими пакетами.

## Consequences

- Пакеты и моды могут модульно накладывать правила валидации на любые команды системы.
- Ядро полностью очищено от игровых понятий и терминов пакетов `textsystem`/`rh`.
- Порядок объявления файлов внутри пакетов не влияет на разрешение зависимостей между валидаторами и командами.
- Ошибки контракта валидатора (попытка вызова побочных эффектов, неверные типы) дают чёткие ошибки программиста до начала изменения состояния игры.

## Rejected alternatives

- **`priority` в авторском API**: отклонён для дизайнерского слоя; порядок внутри модуля сохраняется детерминированно по порядку объявления, численный приоритет остаётся только в низкоуровневом programmer API.
- **Отдельный реестр валидаторов на команду (`command_id -> validators`)**: отклонено до измерений; плоский реестр с фильтрацией $O(N)$ полностью удовлетворяет требованиям производительности v1.
- **Извлечение списка игровых имён параметров в общий helper**: отклонено как закрепление нарушения [INV-016](../Architecture/Invariants.md).
