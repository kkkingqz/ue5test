# ADR-0028: Simplified Authoring Surface

> **Решение:** ввести класс authoring-скриптов (`scripts/authoring/*.lua`) с собственным лексическим окружением `_ENV`, создаваемым загрузчиком дескриптором модуля, запретом записи глобальных переменных, неявным успехом команд и источником презентации с автоматической инвалидацией.
> **Нормативный текст:** [Authoring Surface](../Architecture/AuthoringSurfaceContract.md), [Lua Runtime](../Architecture/LuaRuntimeContract.md), [Screen Templates](../UI/ScreenTemplates.md).

## 1. Контекст и проблема

В [ADR-0007](0007-lua-module-environment.md) было зафиксировано правило «одна VM, единый `_G`, per-module environments отсутствуют». В [ADR-0027](0027-designer-lua-authoring-layer.md) был введён авторский слой, использующий фабрику `authoring.gameplay(package_id)` и пролог из локальных переменных.

Практическое применение слоя в пакете `rh` показало, что пролог и обязательный префикс `M.` на каждом символе (`M.commands`, `M.player`, `M.world`, `M.def`, `M.fail`, `M.emit`, `M.text`, `M.show_screen`) создают значительный визуальный и синтаксический шум в коде правил игры. Кроме того, требование явного `return M` и оборачивания результатов команд в конверты `{ ok = true, value = ... }` отвлекает геймдизайнера от описания чистых правил игры.

## 2. Решение

### 2.1. Класс authoring-скриптов и лексическое окружение `_ENV`
- Файлы подкаталога `scripts/authoring/` игрового пакета (или модули с флагом `authoring: true`) выделяются в класс **authoring-скриптов**.
- Загрузчик перед исполнением чанка создаёт дескриптор модуля `mod = authoring.gameplay(package_id)` и лексическое окружение `_ENV`, предварительно наполненное именами:
  - `commands` — прокси для объявления обработчиков команд;
  - `player` — динамический аксессор к игроку;
  - `world` — динамический аксессор к миру;
  - `def` — фабрика определений репозитория;
  - `location` — типизированный аксессор определений локаций;
  - `actor` / `actors` — аксессоры экземпляров акторов;
  - `fail` — функция типизированного отказа;
  - `emit` — функция публикации событий;
  - `on` — функция подписки на события;
  - `text` — конструктор `TextSpec`;
  - `button` — конструктор кнопок меню;
  - `action` — конструктор семантических привязок действий;
  - `show_screen` — функция публикации экранного запроса.
- Окружение связано через метатаблицу с `_G` для чтения стандартных библиотечных функций (`pairs`, `ipairs`, `type`, `assert`, `math`, `string`, `table`, `error`, `pcall` и др.).
- Попытка записи в глобальное окружение из authoring-скрипта перехватывается метаметодом `__newindex` и завершается типизированной ошибкой `AuthoringGlobalWriteDisallowed`.
- Окружение не является security sandbox: оно служит исключительно синтаксической эргономике. Модули программиста (`scripts/runtime/`, `scripts/services/`) продолжают использовать стандартное окружение и `require`.

### 2.2. Создание дескриптора загрузчиком (отсутствие `return M`)
- Дескриптор создаётся до запуска скрипта. Возвращаемое значение чанка игнорируется, директива `return M` в конце authoring-скрипта не требуется.
- Экспортной таблицей модуля становится созданный дескриптор `mod`, который замораживается и регистрирует объявленные команды и подписчиков на фазе `register`.

### 2.3. Неявный успех команд и нормализация результата
- Обработчик команды в авторском слое нормализует возвращаемое значение:
  - `return nil` (или отсутствие return) расценивается как успех команды без значения (`{ ok = true }`);
  - `return fail(...)` расценивается как типизированный отказ (`{ ok = false, error = ... }`);
  - Любое другое возвращённое значение (число, строка, таблица) расценивается как полезная нагрузка успешного результата (`{ ok = true, value = ... }`);
  - Таблица с полем `ok = false`, возвращённая напрямую без вызова `fail()`, **не считается отказом** и оборачивается в `{ ok = true, value = { ok = false, ... } }`;
  - Непойманное исключение в теле обработчика расценивается как `fault` команды.

### 2.4. Источник презентации и автоматическая инвалидация
- Презентация отделяется от геймплейного кода: команды не вызывают перестроение экранов.
- Рантайм регистрирует источник презентации и автоматически обновляет желаемое состояние экрана после каждой успешно закоммиченной команды.

## 3. Пересмотр предыдущих решений

- **ADR-0007**: Правило «модули не создают глобальных переменных» остаётся в силе. Формулировка «per-module environments отсутствуют» уточняется: authoring-скрипты получают специализированный `_ENV`, предотвращающий создание globals и инжектирующий контекстно-зависимые имена авторского слоя.
- **ADR-0027**: Заменяется способ связывания с авторским контекстом: вместо ручного `local authoring = require(...)` и префикса `M.` используется инжектируемый `_ENV`.

## 4. Последствия

- Designer-facing Lua освобождается от технического бойлерплейта (`M.`, `return M`, конвертов `ok = true`).
- Сохраняются все гарантии детерминизма, неизменяемости снимка репозитория, изоляции состояния и фаз жизненного цикла.
- Модули программиста сохраняют прежний API.
