# ADR-0039: Presentation Source Stays a Singleton

> **Решение:** `Scripts/runtime/presentation_source.lua` продолжает допускать ровно один зарегистрированный источник; композиция нескольких источников не вводится.
> **Условие пересмотра:** появление второго реального потребителя `game.presentation.register_source`, которому нужен собственный auto-refresh route после команд.

## Context

`presentation_source.lua` хранит единственную `registered_source` функцию: `register_source(fn)` отклоняет повторную регистрацию (`PresentationSourceDuplicateRegistration`). После каждого успешно закоммиченного командой изменения рантайм вызывает `game.presentation.resolve()`, который вызывает эту единственную функцию и публикует построенный ею route.

Предыдущее ревью оставляло это как есть с оговоркой «до ADR по UI document reconciliation». Реконсиляция со слоями с тех пор реализована: `FGV2LayeredUiReconciler`, `UGV2GameShellWidgetBase`, шесть слоёв (`background`, `location_content`, `character_presentation`, `core_interface`, `overlay_stack`, `modal_stack`), маршрут с независимыми оверлеями и модалками в одном документе. Условие пересмотра из старого решения формально наступило ([EXT-AF-05](../Status/Archive/PlanAudit2026-08.md)).

## Decision

Оставить singleton-источник без изменений.

Причины остаться:

1. **Реального второго потребителя нет.** Единственный вызов `register_source` вне тестов — `textsystem:module.presentation.location_presenter`, который перестраивает route (главный экран локации) после каждой команды. Ни один из пакетов (`core`, `textsystem`, `rh`, `sample`) не пытается зарегистрировать второй источник и не имеет для этого причины.
2. **Композиция уже существует там, где она нужна на практике.** `show_modal`/`show_overlay`/`close_modal`/`close_overlay` вызываются напрямую из командных обработчиков **любого** пакета (пример: `rh:command.request_buy` вызывает `show_modal` для подтверждения покупки) и пишут в независимые слоты документа (`overlays[key]`, `modals[key]`), не проходя через `presentation_source` вообще. Практическое ограничение singleton-источника — это ограничение именно на «кто автоматически перестраивает **route** после каждой команды», а не на способность нескольких пакетов участвовать в одном документе.
3. **Композиция route из нескольких источников — нерешённая проблема мержа, а не техническая деталь.** Если бы второй пакет зарегистрировал свой источник, encoder должен был бы определить: чей route побеждает при конфликте, в каком порядке вызываются источники, что происходит, если оба хотят разные `template` для одного `instance_key`. Ни одного правила для этого сегодня нет, и придумывать его для гипотетического потребителя означало бы вносить неиспользуемую сложность.

## Consequences

`register_source` продолжает принимать ровно одну функцию за сессию; попытка второй регистрации остаётся ошибкой. Пакет, которому нужен собственный независимый route (а не оверлей/модалка), не может добавить его без замены существующего источника целиком — это ограничение сохраняется явно, а не молчаливо.

Новое **наблюдаемое** условие пересмотра: появление второго пакета, который реально пытается зарегистрировать `game.presentation.register_source` для своего route (не оверлея и не модалки). К этому моменту необходимо решить правило мержа/порядка из Decision п.3 прежде чем разрешать композицию.

## Rejected alternatives

- **Список источников вместо одного, выполняемых по порядку регистрации.** Отклонён: не определяет, что происходит при конфликте route от двух источников; откладывает нерешённую проблему на runtime вместо архитектурного решения.
- **Namespace-scoped источники (по одному на пакет, объединяемые в разные UI-инстансы).** Отклонён как избыточный для текущего использования: `ui_instance_id` уже поддерживает несколько независимых документов на уровне протокола, но ни один потребитель не нуждается в отдельном UI-инстансе для собственного route — все делают это через оверлеи/модалки существующего документа.
- **Снять ограничение вообще (позволить молчаливую перезапись источника).** Отклонён: превращает диагностируемую ошибку конфигурации (`PresentationSourceDuplicateRegistration`) в тихий баг «чей источник выиграл, тот и решает».
