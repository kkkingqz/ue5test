# ADR-0032: Field Contracts and Generic Instance Creation

> **Решение:** декларативные дескрипторы полей (`field.*`) на прототипах сущностей, автоматическая валидация структурных инвариантов при записи, и обобщённый фасад создания динамических экземпляров (`instances.create`).
> **Нормативный текст:** [Authoring Surface](../Architecture/AuthoringSurfaceContract.md), [Canonical State and Save](../Architecture/CanonicalStateAndSave.md).

## Context

После внедрения авторских расширений сущностей ([ADR-0031](0031-entity-authoring-extensions.md)) методы сущностей (`Actor`, `Location`) объявляются декларативно через прототипы авторского окружения.

Однако код авторских скриптов пакетов (в частности, `GameData/rh/scripts/gameplay/actors.lua`) всё ещё содержал значительный объём инфраструктурного кода:
1. Повторяющаяся ручная валидация аргументов (`validate_amount`) в каждом методе (`require_gold`, `spend_gold`, `add_gold`, `require_stamina`, `spend_stamina`, `add_stamina`).
2. Описание полей сущностей через вспомогательную структуру дескрипторов ресурсов (`RESOURCES`).
3. Неявный fallback `self -> player`, маскирующий отсутствие передачи получателя в методах.
4. Прямой импорт инфраструктурного модуля ядра `core:module.runtime.instance_allocator` и прямая запись в физическую коллекцию `game.state.item_instances` внутри доменного метода `Actor:add_item()`.

Требуется предоставить авторам контента высокоуровневые инструменты описания инвариантов состояния и создания динамических экземпляров, изолировав геймплей от низкоуровневого устройства состояния.

## Decision

1. **Декларативные дескрипторы полей (`field.*`)**:
   - В авторское окружение `_ENV` инжектируется семейство фабрик дескрипторов полей (`core:module.authoring.field`):
     - `field.non_negative_integer(opts)` — целое неотрицательное число ($\ge 0$);
     - `field.positive_integer(opts)` — целое строго положительное число ($> 0$);
     - `field.integer(opts)` — произвольное целое число;
     - `field.number(opts)` — число с плавающей точкой (finite double);
     - `field.string(opts)` — строковое значение;
     - `field.boolean(opts)` — логическое значение;
     - `field.enum(values, opts)` — значение из перечисленного набора;
     - `field.ref_definition(kind, opts)` / `field.ref_instance(kind, opts)` — канонические ссылки на сущности.
   - Объявление поля на прототипе сущности (`Actor.gold = field.non_negative_integer()`) через метаметод `__newindex` прокси прототипа автоматически регистрирует поле в схеме свойств (`core:module.authoring.properties`).

2. **Валидация структурных инвариантов при записи**:
   - Запись значения проверяется до мутации состояния. Нарушение инварианта выбрасывает structural error, предотвращая попадание повреждённых данных в каноническое состояние независимо от вызывающего кода.
   - **Схема сущности является композицией, а не цепочкой перекрытия.** Эффективная схема собирается из трёх источников в порядке возрастания конкретности: generic entity kind (`"Actor"`, `"Location"`) → `definition_id` → `discriminator`. Слияние выполняется **по имени поля**: более конкретный источник переопределяет одноимённое поле, но не скрывает остальные поля менее конкретного источника.
   - Переопределение поля может сузить ограничения (`min`, `max`, `min_length`, `max_length`); смена `kind` поля является ошибкой сборки схемы.
   - Композиция вычисляется однократно при заморозке реестров ([INV-006](../Architecture/Invariants.md)), поэтому путь записи получает плоскую таблицу полей и не выполняет поиск по цепочке источников.

   Отвергнутая альтернатива «первый найденный источник побеждает целиком» делала объявление `Actor.gold` молча недействующим для любого актора, у которого есть собственная схема по `discriminator`, — то есть отключала защиту инварианта именно там, где она нужна больше всего.

3. **Повторное объявление поля запрещено по умолчанию**:
   - Объявление поля с именем, уже объявленным для той же сущности, отклоняется ошибкой `FieldAlreadyDeclared`.
   - Осознанное переопределение выражается явно: `field.<kind>({ override = true })`.
   - Это та же форма, что выбрана для замещения Lua-модулей ([ADR-0025](0025-lua-module-replacement-and-export-freezing.md)): запечатано по умолчанию, замещаемо по явному флагу. Молчаливое «побеждает последний загруженный» отвергнуто.

4. **Объявление поля не является регистрацией вида актора**:
   - Наличие схемы generic entity kind не делает произвольный `discriminator` известным. Проверка `ActorTypeNotRegistered` остаётся привязанной к `discriminator` и продолжает ловить опечатки.
   - Пакет, вводящий новый вид актора, объявляет его явно.

5. **Разделение структурных инвариантов и геймплейных предусловий**:
   - **Структурный инвариант** (`field.non_negative_integer()`) защищает форму состояния от ошибок программиста (отрицательные балансы, неверные типы).
   - **Геймплейное предусловие** (`Actor:require_gold(amount)`) проверяет бизнес-правило возможности действия и возвращает структурированный отказ `fail("economy.insufficient_gold", ...)` до начала мутации.
   - Методы списания (`Actor:spend_gold(amount)`) не дублируют проверки underflow.

6. **Обобщённое создание динамических экземпляров (`instances.create`)**:
   - В авторский `_ENV` предоставляется фасад `instances.create(kind, payload)`:
     - `kind` указывает вид создаваемого экземпляра;
     - Фасад валидирует входные параметры (ссылку на определение по репозиторию, владельца `owner`);
     - Аллоцирует `instance_id` через `instance_allocator`;
     - Сохраняет чистую каноническую структуру в секцию `game.state`, соответствующую виду;
     - Возвращает аллоцированный `instance_id`.
   - **Ядро не перечисляет виды экземпляров.** Вид объявляется пакетом на фазе `register`; неизвестный вид — типизированный отказ. Имя секции состояния **выводится** из имени вида по общему правилу (`item` → `item_instances`), а не задаётся автором: ядро знает правило именования, но не знает ни одного имени вида.
   - Перечисление `"item"` в ядре отвергнуто как прямое нарушение [INV-016](../Architecture/Invariants.md): `Item` и `Inventory` являются семантикой пакета `rh` и не поднимаются ни в `textsystem`, ни тем более в `core`.
   - `actor` остаётся осознанным исключением: он существует до загрузки любого пакета, имеет собственный реестр и обёртку, и его создание делегируется существующему `game.instances.actors.create`.
   - Геймплейный код пакетов больше не импортирует `instance_allocator` и не обращается напрямую к `game.state`.

7. **Нарушение контракта поля является runtime fault, а не геймплейным отказом**:
   - Штатный путь отказа — предусловие `require_*` с `fail()` до мутации.
   - Срабатывание контракта поля означает ошибку кода, а не ситуацию игры: команда прерывается, событийный контекст отбрасывается, ошибка поднимается наверх.
   - **Каноническое состояние при этом не откатывается**: записи, сделанные до ошибки, остаются. Прогон после такого отказа не является доверенным.
   - Транзакционность окна мутации является отдельным решением и в этот ADR не входит.

8. **Контракт поля не проверяет аргументы методов**:
   - Контракт защищает результирующее состояние, а не знак и смысл аргумента: `spend_gold(-10)` увеличивает баланс, не нарушая инварианта.
   - Проверка аргументов принадлежит границе, через которую приходят недоверенные данные, — валидаторам команд.
   - До появления валидаторов пакет защищает собственные методы локальной проверкой; общий механизм типизированных аргументов методов в этот ADR не входит.

9. **Изоляция слоёв**:
   - Текстовый движок `textsystem` не получает понятий `Resource`, `Item` или `Inventory`.
   - Общие слои (`core`, `textsystem`) предоставляют только инфраструктуру валидации полей и создания инстансов; семантика предметов и экономических механик остаётся в пакете `rh`.

## Consequences

### Положительные
- Код `GameData/rh/scripts/gameplay/actors.lua` очищается от инфраструктурных зависимостей, ручной валидации типов и прямых обращений к `game.state`.
- Инварианты состояния гарантируются централизованно в точке записи для всех путей мутации.
- Исключён риск попадания некорректных типов в `game.state`.

### Отрицательные / Компромиссы
- Добавляется модуль дескрипторов `core:module.authoring.field`, фасад `instances.create` и реестр видов экземпляров.
- Валидация выполняется при **каждой** записи в каноническое состояние. Композиция схем вычисляется один раз при заморозке, поэтому путь записи не выполняет поиск по цепочке источников, но сама проверка значения остаётся на горячем пути.
- `spend_*` и `add_*` теряют проверку аргумента: она не заменяется контрактом поля, а переносится на границу команд. До появления валидаторов команд ответственность несёт пакет.
- Нарушение контракта поля прерывает команду без отката уже сделанных записей. Это делает контракт поля средством обнаружения ошибки, а не средством сохранения целостности состояния.
- Схема сущности перестаёт быть одной таблицей: её эффективное содержимое собирается из трёх источников, и диагностика обязана показывать, какой источник дал конкретное поле.

## Rejected Alternatives

- **Абстракция `Resource` в TextSystem**: отклонена, так как экономические ресурсы не являются универсальной механикой текстовых игр и нарушают изоляцию слоёв ([ADR-0030](0030-textsystem-layer-and-data-driven-package-set.md)).
- **Автоматическая генерация методов `get/set/require/spend/add` из описания полей**: отклонена, чтобы избежать неявной магии и сохранить явный контроль над геймплейной семантикой методов.
- **Перечисление видов экземпляров в ядре** (`"item"` → `game.state.item_instances`): отклонено как нарушение [INV-016](../Architecture/Invariants.md). Вид объявляет пакет, имя секции выводится из имени вида.
- **Цепочка перекрытия схем «первый источник побеждает целиком»**: отклонена — делает объявление поля на generic entity kind молча недействующим при наличии схемы по `discriminator`.
- **Молчаливое переопределение поля последним загруженным пакетом**: отклонено в пользу `FieldAlreadyDeclared` с явным флагом `override`, по образцу [ADR-0025](0025-lua-module-replacement-and-export-freezing.md).
- **Объявление поля как регистрация вида актора**: отклонено — снимает проверку `ActorTypeNotRegistered` со всех дискриминаторов и превращает опечатку в молчаливое создание актора.
- **Транзакционное окно мутации в рамках этого решения**: отклонено как отдельное архитектурное изменение; вынесено в самостоятельное предложение.
