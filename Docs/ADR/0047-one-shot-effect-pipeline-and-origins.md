# ADR-0047: Единый pipeline одноразовых эффектов и равноправие источников

> **Решение:** источник эффекта не входит в его identity. Lua-published и host-local эффекты проходят одну очередь, получают `sequence` из одного счётчика и один apply path с одинаковыми правилами отбрасывания. Host-local источник допустим только для эффекта, отсутствие которого не меняет ни одного значения canonical state и который восстановим из snapshot и состояния устройства ввода.

## Контекст и проблема

Раздел `Effect` контракта [Presentation Snapshot and Effects](../UI/PresentationSnapshotAndEffects.md) нормативен с версии 0.7 и не реализован ни одной строкой: в `Scripts/`, `Source/` и `Tests/` нет ни публикующего биндинга, ни очереди, ни apply path, ни отбрасывания по stale target. Расхождение открыто как `STATUS-002`.

Реализация начинается с первого потребителя — всплывающего окна по наведению курсора на размеченный `<interactive>`-span. И этот потребитель немедленно обнажает противоречие в самой формулировке контракта.

### Чем была неправа формулировка «Lua → UE сообщения»

Контракт открывает раздел фразой: «Lua → UE сообщения разделены на durable desired snapshot и one-shot effects». Она определяет эффект через его источник — Lua. Между тем два других нормативных документа столь же прямо запрещают первому потребителю иметь этот источник:

- [SemanticInput](../UI/SemanticInput.md): «RichText popover является UE-local transient surface: открытие, positioning, hover delay и закрытие не вызывают Lua»; «Hover/unhover не создаёт Semantic Input».
- [WidgetRegistry](../UI/WidgetRegistry.md): «Hover/unhover не пересекают Lua boundary».

Появление и затухание окна по наведению — одноразовый эффект по любому признаку из раздела `Effect`: он не является носителем важного состояния, может быть отброшен по stale target и не реплеится при save/load. Но опубликовать его из Lua нельзя, не сломав два других правила.

Формулировка была неправа тем, что подняла **происхождение** сообщения до определяющего признака **вида** сообщения. Признаки, ради которых эффект отделён от snapshot — одноразовость, отбрасываемость, отсутствие в сохранении, — ни одного слова об источнике не содержат. Источник попал в определение не как свойство эффекта, а как описание единственного канала, существовавшего на момент записи.

### Почему нельзя просто разрешить второй канал

Host-local источник — это путь, по которому в презентацию попадает сообщение, не пришедшее из Lua. Если такому сообщению разрешить нести gameplay-значимое состояние, презентация станет порождать истину, и [INV-014](../Architecture/Invariants.md) будет нарушен наблюдаемо: появится значение, пережившее reload, которого нет в сохранении.

Поэтому решение не может состоять в одном лишь разрешении второго источника. Оно обязано нести критерий, отделяющий допустимый host-local эффект от скрытого канала авторитета, и критерий этот обязан быть проверяемым, а не оценочным.

## Принятое решение

### 1. Источник не входит в identity эффекта

Эффект остаётся тем, что описывает контракт: `effect_id`, монотонный `sequence`, optional `target`, `args`. Поля «источник» в DTO **нет**. Два источника различаются только точкой входа:

- **Lua-published.** Публикуется фиксированным биндингом рядом с `publish_snapshot`. Биндинг schema-валидирует DTO и глубоко копирует его в исходящую очередь; reconciler внутри Lua-вызова не запускается.
- **Host-local.** Порождается презентационным событием, не имеющим gameplay-смысла: наведение курсора, уход курсора, завершение показа по таймеру.

Оба кладут эффект в одну очередь, получают `sequence` из одного счётчика и проходят один apply path.

Причина отсутствия поля источника прямая: поле вернуло бы источник в identity, и первая же ветка `if (Origin == ...)` в apply path означала бы два механизма под одним именем.

### 2. Критерий допустимости host-local эффекта

Host-local эффект допустим тогда и только тогда, когда выполнены оба условия:

1. **Нулевое влияние на canonical state.** Canonical state до порождения эффекта и после его полного исполнения побайтово равны.
2. **Восстановимость без него.** После rebuild презентации (load, UI reconstruction, map/presenter reset, recoverable failure) эффект не воспроизводится сам и не требуется для корректного состояния: presentation полностью строится из latest complete snapshot.

Оба условия наблюдаемы и проверяются прогоном, а не рассуждением. Эффект, не удовлетворяющий любому из них, обязан идти через Lua и command path, а не через host-local источник.

### 3. Один счётчик `sequence`

`sequence` монотонно возрастает по всей очереди независимо от источников. Двух счётчиков не существует: при двух счётчиках порядок между эффектами разных источников не определён, и правило контракта «Same/older revision ignored» перестаёт быть проверяемым для смешанного потока.

### 4. Отбрасывание с типизированной причиной

Эффект отбрасывается по трём причинам, и каждая различима: stale target, чужое поколение сессии, устаревшая ревизия. Общий булев отказ запрещён — он делает неотличимой доставку в чужую сессию от нормального отбрасывания по исчезнувшей цели.

Отказ эффекта не инвалидирует snapshot и gameplay state.

### 5. Non-persistence

Незавершённый эффект не сохраняется и после загрузки не возобновляется. Проверяется поведением после реальной загрузки, а не отсутствием поля в файле сохранения.

## Последствия

- Раздел `Effect` контракта перестаёт определять эффект через источник и получает оба источника с критерием допустимости host-local.
- Наведение курсора остаётся UE-local: правила `SemanticInput` и `WidgetRegistry` не меняются и не получают исключений.
- Всплывающее окно становится первым потребителем pipeline, а не первым исключением из него.
- Появляется обязанность, которой раньше не было: всякий новый host-local эффект проверяется по критерию из п. 2 своим прогоном. Критерий дешёвый, но не бесплатный.
- `STATUS-002` закрывается механизмом, а не первым эффектом: DTO, очередь, apply path, отбрасывание и тесты non-persistence — предмет отдельных задач `PEP-03` и `PEP-04` плана [PresentationEffectPipeline](../Plans/PresentationEffectPipeline/README.md).

## Отклонённые альтернативы

**Оставить единственный Lua-источник, а hover пропустить через Lua.** Прямо нарушает `SemanticInput` («открытие, positioning, hover delay и закрытие не вызывают Lua») и превращает движение курсора в gameplay-событие. Цена — трафик на границе на каждое движение мыши и hover, попадающий в command path, который существует для gameplay-решений.

**Оставить единственный Lua-источник, а затухание сделать локальным таймером виджета.** Даёт результат для одного окна и создаёт второй механизм презентации мимо очереди и `sequence`. `STATUS-002` при этом не закрывается, а к нему добавляется новое расхождение. Это тот же класс ошибки, который уже разбирался в `PAH-R3` и в уроке про две расходящиеся реализации одного правила (`GBH-06`/`GBH-08`).

**Ввести поле источника в DTO.** Возвращает источник в identity эффекта. Первое же ветвление по этому полю в apply path означает два механизма под одним именем — ровно то, что решение запрещает.

**Разрешить host-local эффекты общей формулировкой без критерия.** Оставляет `INV-014` без проверяемой границы: «эффект не несёт gameplay-состояния» без наблюдаемого условия — оценочное суждение автора change set, а не правило.

**Два счётчика `sequence`, по одному на источник.** Делает порядок между эффектами разных источников неопределённым и лишает правило отбрасывания устаревших смысла для смешанного потока.
