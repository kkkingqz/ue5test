# ADR-0035: UI Foundation and Composition

> **Решение:** каноничность экранного документа при UI-local природе переходного состояния (прокрутка, активная вкладка, наведение), обязательное правило идентичности повторяемых элементов с уникальностью в контейнере и запретом вывода из текста, вкладки как одноуровневые вложенные Screen Instances, отзывчивая модель раскладки вместо равномерного масштабирования, разделение растра (4K) и единиц раскладки (1080p), объявление политик масштабирования примитивом с проверкой режимом ресурса, нелинейная кривая текста с читаемым порогом для 720p, трёхуровневое владение UI-ассетами (`core → textsystem → rh`) и отнесение темы и шаблонов к `textsystem`.

## Context

Исторически пользовательский интерфейс проекта развивался от одного активного экрана с ограниченным набором из 15 виджетов `WBP_*`, из которых только пять управлялись контрактами данных Screen Field:
1. **Идентичность элементов**: требование «deterministic `key`» не имело спецификации области уникальности, приоритетов вывода и валидационных гейтов, что приводило к риску скрытого пересоздания виджетов при смене порядка или локали.
2. **Модель масштабирования**: первоначальная идея равномерного масштабирования кадра `min(H/1080, W/1440)` делала текст нечитаемым на экранах 1280×720 и не позволяла изолированно увеличивать типографику.
3. **Слои и вкладки**: многослойный UI-документ (маршрут, оверлеи, модальные окна) и вкладки не имели строгой модели жизненного цикла и реконсиляции.
4. **Владение UI-ассетами**: ассет темы `UGV2UiTheme` и базовые шаблоны не были распределены по трём слоям архитектуры (`core`, `textsystem`, `rh`).

## Decision

1. **Каноничность экрана и UI-local состояние**:
   - Каноническим состоянием является экранный документ (маршрут и значения полей Screen Fields), публикуемый Lua.
   - Прокрутка, активная выбранная вкладка, раскрытое состояние выпадающего списка, фокус и наведение являются **UI-local** состоянием Unreal Engine и не сериализуются в сохранение. После загрузки интерфейс детерминированно воссоздаётся из канонического состояния.

2. **Идентичность повторяемых элементов**:
   - Каждый элемент повторяемого поля обязан содержать непустой `key`, уникальный в пределах непосредственного контейнера (`field_id`).
   - Полный путь идентичности элемента в реестре биндингов: `layer → instance_key → field_id → key`.
   - **Источники ключа в порядке приоритета**:
     1. явный `key`, указанный автором;
     2. Stable ID или instance ID доменной сущности (`rh:item.weapon.iron_sword`, `actor@42`);
     3. канонический `command_id` с детерминированно нормализованными аргументами.
   - **Запреты**:
     - Запрещено выводить ключ из отображаемого или локализуемого текста (`text_id`, `TextSpec`).
     - Запрещено кодировать в ключ изменяемое состояние (`item#count`, `gold_10`).
   - Документ с отсутствующим, дублирующимся или недопустимым ключом отклоняется целиком до фазы применения (`ApplyBindings`).

3. **Вкладки как вложенные Screen Instances**:
   - Вкладка представляет собой Screen Instance, вложенный в поле-контейнер экранов верхнего уровня (маршрут, оверлей, модальное окно).
   - Ограничение вложенности: строго один уровень (вкладка внутри вкладки запрещена).
   - Содержимое всех вкладок присутствует в документе одновременно, обеспечивая мгновенное UI-local переключение без сетевых/игровых команд.

4. **Отзывчивая раскладка и единицы измерения**:
   - Отказ от масштабирования отрисованного кадра. Раскладка адаптивно распределяет доступное пространство viewport.
   - **Два базовых числа**:
     - Растровые исходники рисуются под целевое разрешение авторинга **3840×2160 (4K)**.
     - Размеры и отступы в шаблонах раскладки выражаются в единицах **1920×1080**.
   - Визуальные примитивы явно объявляют политику масштабирования (`FreeStretch`, `Tile`, `NineSlice`, `PreserveAspect`), которая валидируется на совместимость с режимом ресурса.
   - Текст масштабируется по нелинейной кривой и не опускается ниже минимального порога читаемости (целевой минимум 1280×720).

5. **Трёхуровневое владение UI-ассетами**:
   - `core`: нейтральные примитивы, конвейеры текста/графики, адаптеры Screen Field, layout-контейнеры.
   - `textsystem`: базовые экранные шаблоны, композиты текстовых игр и ассет темы `UGV2UiTheme`.
   - `rh`: экраны и специфичные для игры композиты.

6. **Правило ввода элементов базового набора**:
   - Элемент вводится в базовый набор только при наличии реального потребителя в том же change set (ADR-0026). Расширенный набор без потребителей вынесен в отдельное предложение.

7. **Неизменность дайджеста презентации**:
   - Дайджест сессии (`FRunResult::FinalScreenId`, `FinalScreenFields`) описывает только канонический экран и не расширяется оверлеями и модальными окнами.

## Consequences

- Реконсиляция виджетов становится предсказуемой и безопасной: порядок элементов в списках может меняться без пересоздания виджетов.
- Поддерживается корректное отображение на экранах от 720p до 4K и ультрашироких мониторах (21:9).
- Чёткое разделение ответственности предотвращает утечку специфики проекта в ядро.

## Rejected Alternatives

- **Равномерное масштабирование кадра (`min(H/1080, W/1440)`)**: делает текст нечитаемым на 720p и препятствует изолированной адаптации элементов.
- **Единое число для растра и раскладки**: приводит либо к размытию графики на 4K, либо к неудобным дробным значениям в шаблонах.
- **Вывод политики масштабирования исключительно из режима ресурса**: примитив теряет контроль над способом размещения (например, иконка фиксированного размера vs фоновый тайл).
- **Введение элементов без потребителя**: нарушает инвариант ADR-0026.
- **Включение модалок и оверлеев в Presentation Digest**: размывает каноническую границу экрана и усложняет детерминированную верификацию.
